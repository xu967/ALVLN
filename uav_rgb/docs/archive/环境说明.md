### 为什么不是 CUDA 13.1（写死结论）

1. **驱动门槛**：`nvidia-smi` 报 "CUDA Version: 13.0"，即该驱动最高只支持到 CUDA 13.0 运行时。CUDA 13.1 的 runtime 需要更高版本驱动，装了也起不来。
2. **架构门槛**：RTX 2080 Ti = Turing = sm_75。CUDA 13.x 已把 Turing 放入"维护/弃用"轨道，编译 sm_75 收益为零，风险大于收益。
3. **现状可用**：CUDA 12.8 完整支持 sm_75（`nvcc --list-gpu-arch` 含 compute_75），且与本机驱动完全兼容，冒烟测试已 PASS。

## 3. sm_75 编译注意事项

1. **CMake**：architecture 必须显式指定，且要放在 `project()` 之前强制写入缓存：
   ```cmake
   set(CMAKE_CUDA_ARCHITECTURES 75 CACHE STRING "CUDA architectures" FORCE)
   project(xxx LANGUAGES CXX CUDA)
   ```
   否则 CMake 3.28 会采用 nvcc 默认架构（实测打印为 **52**）。
2. **裸 nvcc**：`-gencode arch=compute_75,code=sm_75`（可加 `code=compute_75` 以附带 PTX 供前向兼容）。不要用 `-arch=native`。
3. **不要使用 sm_80+ 才有的特性**：Turing 无 `wgmma`、无张量内存加速器 (TMA)、无 `cp.async.bulk`、无 FP8 指令；Tensor Core 为第二代（FP16/BF16/INT8/INT4）。
4. **PTX 前向兼容有限**：嵌入 PTX 时驱动可 JIT，但仍是 12.8 的 PTX ISA 版本；将来升级到 CUDA 13 工具链需重新评估。
5. **PyTorch（如后续安装）**：设置 `TORCH_CUDA_ARCH_LIST="7.5"`（`env.sh` 已预置），并使用带 CUDA 12.x 的 wheel；CUDA 13 的 wheel 对 sm_75 支持情况需先验证。
6. **验证方法**：`cuobjdump -lelf <binary>` 应只出现 `*.sm_75.cubin`。
