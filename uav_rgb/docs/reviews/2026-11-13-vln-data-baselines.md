# 无人机 VLN：数据、长航线和公开基线核验

- 日期：2026-11-13；审查基线：主线 `f7323c4`，另只读核对 BL2–BL5 工作树和数据盘产物。
- 本文是审查与后续实施规格；表内旧实验数字来自已有产物，不是本次新跑的结果，也不是语言导航成绩。
- 结论：先完成现有场景里的语言闭环，再扩连续长航线。已有街景扫描并不只有十几米；当前手工任务切得短。换数据库无法替代语言落地、自主停止和观测边界修复。

## 1. 需求必须落到任务合同

当前硬件合同是定高、四个高层动作，不能升降、抓取或投送。可交付的第一阶段任务例子是：“沿走廊飞到沙发旁，停下来。”验收要同时看到原始指令、真实机载画面、动作、终止理由和目标误差。

SAGE 指令含 `Add_Object` 和 `Scenario_Driven`，部分要求拿物体、送饮料。直接在终点附近停下，只能证明完成导航子任务，不能宣称整句任务完成。[官方指令类型](https://huggingface.co/datasets/spatialverse/SAGE-3D_VLN_Data)

实施要求：保留原句；数据清单显式标记任务能力范围。先纳入纯导航、目标指认和区域到达；需要操纵的指令单列为“仅评导航子目标”，或从正式导航主表排除并报告数量。禁止模型拿到 `end` 物体 ID 后把查表说成语言理解。

`tools/scene_import_sage3d.py` 的文件头已说明原轨迹高度约 0.5 m，导入器改到 `FLY_H_M=1.2`。这是一份由 SAGE 数据构造的 UAV 定高任务，不能直接称为官方 SAGE-Bench 成绩；高度、动力学、碰撞体、停止规则、距离计算已经改变。

- [Wanderland 数据卡](https://huggingface.co/datasets/ai4ce/wanderland) 标 Apache-2.0；当前公开335场景，其中113个 evaluation-ready。v2 showcase 暂无 `episodes.json` 和 `scene.usdz`，导入现有脚本时优先选 v1、逐文件检查 manifest。

- [CityNav 官方仓库](https://github.com/water-cookie/citynav) 的代码为 MIT，但底层 [SensatUrban](https://github.com/QingyongHu/SensatUrban) 通过单独表单下载，资产使用条款需分别确认。
- [OpenFly 官方平台](https://github.com/SHAILAB-IPEC/OpenFly-Platform) 与 [HF 数据](https://huggingface.co/datasets/IPEC-COMMUNITY/OpenFly/tree/main)：数据卡标 Apache-2.0；UE、GTA等第三方场景不能因平台代码开源而一概认为可再分发。
- [Mip-NeRF 360 官方项目](https://jonbarron.info/mipnerf360/) 面向围绕一点旋转的360度视角重建；是否支持我们的平移航线，仍须按实际采集相机和渲染质量验证。

## 3. 3DGS 的问题要分开定位

本地已有证据见 `docs/experiments/3dgs-site-wanderland.md`：563个相机位姿，沿约52m街道往返；当前6条人工路线仅9.4–15.2m，`tools/scene_import_wanderland.py:57` 明确列出端点。相机离地约1.29m，飞行在2.0m；采集路径北侧超过约4m、部分西端停车区没有覆盖。一个穿树候选因A*绕出采集带而被弃用。

所以至少有四种不同问题：

1. **坐标、尺度、内参错误**：连训练相机原位都渲不好，先修导入/渲染；不要加数据掩盖。
2. **未观测区域**：原位好、离开采集带或转身看背面就糊；需要多方向覆盖、换场景或限制任务可用域。
3. **细结构闪烁/高斯尺度异常**：要对比完整球谐、抗锯齿/超采样、尺度过滤，指标和原图一起看；提高分辨率不能补出未采集内容。
4. **运动/录像不连贯**：导航步频、控制瞬态、追踪镜头、离线帧率分别分析。美化跟随镜头不代表飞行更稳。

现有场地记录写每米探测，实际 `tools/scene_probe_quality.py` 的采样间距是0.5m。`lapvar` 是纹理锐度，不是几何或重建真值：白墙会低，噪声/漂浮物可能很高。补充验收应覆盖导航会遇到的视角：中心及左右偏移、转弯时的±45°/90°、实际高度与俯仰范围；把支持视角距离、空洞/透明覆盖、深度异常和人工关键帧核对一起记录。有对应留出照片才计算 PSNR/SSIM/LPIPS，没有真值不能拿锐度当 PSNR。

Wanderland 的官方碰撞网格在本地这例最高约1.64m，不覆盖2m飞行层；现有 `collision.source=points` 使用 LiDAR 是必要的。换飞行高度时重新生成飞行层占据、校验机体包络，不能只把RGB相机往下挪。

## 4. 现有52m场景如何做30–40m航线

以下是实施任务卡；本轮已完成步骤1–3的候选清单/几何/前视探针及步骤4的少量偏航探针，结果见§10，尚未验收真实动态飞行。先复用代码，不建新的场景框架。

1. **冻结数据和对照**：记录 `scene.json`、PLY、LiDAR、相机文件哈希；保留原6条路线及其编号。新任务写独立版本的 scene/task manifest，引用原大文件，禁止重跑导入覆盖历史数据。
2. **找同一连通域**：复用 `sim/3dgs/planner.py` 的 `OccPlanner`，在LiDAR飞行层求路径；候选端点先试 `(4,-1.5)` 到 `(38,-8.5)` 及反向，约35m直线范围。它只是从现有端点挑的候选，16–24m中段尚未连通验收。若绕到未拍摄区就拒绝，不拼贴不连续场景，不用瞬移连接路线。
3. **直接用现有候选探针**：源码支持 `--candidate name:x,y,yaw,wx,wy[,z]`；`--route` 不给数值表示不复测旧路线。示例命令如下，输出目录每次用新名字。

```bash
source env.sh
nvidia-smi -L
"$DATA_ROOT/uav_rgb/3dgs-venv/bin/python" tools/scene_probe_quality.py \
  --scene "$DATA_ROOT/uav_rgb/3dgs-scenes/wanderland_1MlUucug/scene.json" \
  --route \
  --candidate 'long_east:4,-1.5,-15,38,-8.5,2' \
  --candidate 'long_west:38,-8.5,165,4,-1.5,2' \
  --out "$DATA_ROOT/uav_rgb/tmp/vln-long-route-probe-01"
```

4. **再验路线周边视角**：在 `tools/scene_probe_quality.py` 扩展一组固定偏移样本即可，配 `tools/test_scene_probe_quality.py`；不要把采集外区域当训练负样本。现有 `low_frac<=0.1` 只能作为旧质量筛查，最终要核对联系表；多视角有连续雾墙/空洞的候选不接收。
5. **接入任务而非只加终点**：为新路线人工核对地标并写导航指令、目标区域、参考路径、转弯顺序。长指令例子应来自实际画面，不能照代码里过时的“公园栅栏”描述直接生成——场地记录已更正为商业街卷帘门。指令不得把精确世界坐标当作语言。
6. **先教师、后语言策略**：固定版本的教师同路线、同起点扰动各20集，记录失败与碰撞；随后跑纯视觉、真实语言、打乱语言三臂。步骤预算由路线长度和动作耗时生成，并固定在manifest，不能每个策略临时增加步数。
7. **验收**：在同一真实场景中连续飞行，轨迹无跳变；A*路径和实际轨迹均落在已核对的视角支持域；报告SR/SPL、碰撞率、超时率、路线级质量、每米动作切换/急停。长距离本身不是泛化证据，同一街道6段仍只算1个场景。

第一轮路线未通过时，先定位是几何阻断还是视角缺失：前者选同场景其他端点；后者再选2–3个Wanderland v1场景。跨场景泛化需要独立街区留出，不能随机拆同街道的帧。

## 5. 磁盘预算：已有资源足够先做闭环

本次 `df -h` 实测：根盘30G、约1.6G可用；数据盘295G、约47G可用。六个SAGE场景合计约1.1G；当前Wanderland场景目录约1.4G，原下载目录另约312M。数值是本次 `du -sh` 读数，后续运行前重新检查。

| 阶段 | 建议新增空间预算 | 说明 |
| --- | --- | --- |
| 现有场景语言闭环 + 30–40m候选验证 | 5–10GB | 本项目估算，主要用于轨迹、少量抽样视频、缓存；复用现有PLY，不复制整场景 |
| 再引入2–3个Wanderland场景并验收 | 10–20GB | 本项目估算，以本地场景文件量作参考；只取高斯、LiDAR、位姿和必要标注，再按需取RGB |
| 扩展室内场景/多种子正式训练 | 新增200–500GB数据盘较合适 | 是工程预算，不是某数据集最低要求；需要留解压、渲染集、checkpoint和临时缓存空间 |
| 单独复现 AerialVLN | 约100GB可用空间作为起始预算 | 官方模拟器下载约35GB、标注小于100MB；解压与运行缓存另算，100GB是估算，先量单场景 |
| OpenFly全量训练数据 | 当前不下载 | 官方HF根目录显示约2.97TB；500GB加盘也不够全量，先按场景/样本选择小子集 |

官方大小来源：[AerialVLN README](https://github.com/AirVLN/AirVLN#model--simulator--datasets)、[OpenFly 文件目录](https://huggingface.co/datasets/IPEC-COMMUNITY/OpenFly/tree/main)。InteriorGS原始压缩集数据卡约43.8GB，SAGE指令轨迹约9.82GB，均无需在语言闭环验证前全量下载。

需要用户提供的是 InteriorGS 账户授权后的数据访问能力（token通过环境变量配置，不写文档/仓库），以及后续扩容数据盘。当前47GB足够先做第一阶段，不能把“还没加500GB”当成不实现语言链路的理由。

## 7. 公开指标如何用于我们

| 指标 | 要回答的问题 | 本项目必须补充的定义 |
| --- | --- | --- |
| SR | 是否自主停在目标附近 | STOP判定、成功半径、碰撞规则；悬停避障不能自动算任务完成 |
| OSR | 途中是否曾到达成功区域 | 它诊断停止失败，不能替代SR；说明碰撞前后取样范围 |
| NE | 末位置离目标多远 | 公开实现常用可通行最短距离；本项目当前用xy欧氏距离，要标明，不能跨墙误读 |
| SPL | 成功与路径效率是否兼得 | `S*l/max(l,p)`；当前最短路是到目标圆盘的距离，需要明确标为本项目变体，不与到目标点的官方列混排 |
| nDTW / SDTW | 是否按指令顺序沿参考路线执行 | 有合法参考路径才算；固定空间采样间隔、距离函数与归一化尺度；SDTW = 成功标志 × nDTW |
| 碰撞率/超时率/失败请求比例 | 是否可靠 | SR、OSR和error_rate使用请求分母；碰撞率CR等低值优指标按完成/有效集统计，必须同时报n_failed。启动失败没有碰撞观测，不能记为无碰撞压低CR；见 `EVAL_STANDARD.md §5.6` |
| 动作切换/米、停止次数/米、jerk、偏航速率 | 是否平稳 | 固定物理时间采样与滤波；镜头平滑不计作控制改善 |

指标来源：[Anderson等，导航评估与SPL](https://arxiv.org/abs/1807.06757)、[Ilharco等，nDTW与SDTW](https://arxiv.org/abs/1907.05446)。任务要求绕过某地标时，SPL只奖最短到点并不足够，必须增加参考轨迹顺序指标；纯“找到目标”任务不应强迫复现唯一示范路径。

正式表每行固定：策略可见输入、是否oracle、数据版本、场景/路线/指令数、split、碰撞版本、成功半径、动作空间、高度、控制周期、步骤预算、训练种子、checkpoint hash。不同引擎、不同动作合同的论文数字只作旁表引用，主表坚持同环境配对；置信区间按场景/路线聚类，不能把同一路线十句改写当十个独立场景。

## 8. 自有方案：把语言真正用于动作，再谈创新

推荐先验证“语言目标置信度 + 短期视觉记忆 + 机载安全动作”三部分，暂不扩大网络规模。它是待验证假设，不能提前写成方法有效或首创。

1. **可观测输入**：原始语言、当前/历史RGB、实际可获得的机体估计量。目标GT、A*路线、物体ID和全图只允许教师/评测器访问。完整语义地图的语言查表实验可保留为known-map基线，必须独立标明。
2. **任务层输出**：相对目标/子目标方位、置信度、独立到达判断。低置信度进入观察/搜索或安全悬停；禁止用真值方位补洞。传给现有C++/CUDA学生的cond必须带来源和时间戳。
3. **时序记忆**：先利用现有GRU原型比较短历史是否减少同一目标丢失后的反复转向；有收益才迁入主线。用到图像/点目标模型时，目标必须由语言grounder产生，不能直接取标注终点渲染图当VLN成绩。
4. **停止分离**：模型判“到目标”，控制器负责减速/安全悬停，评测器独立查是否真的到。避障SAFE与任务STOP不能共享一个含糊标签。
5. **四组必要对照**：纯视觉；正确语言；同起点交换目标指令；打乱/清空语言。若正确与打乱语言的行为/成功率无显著差别，说明语言没有被利用，不继续加数据包装成果。
6. **消融**：同一grounder下比较现有CNN、CNN+记忆；同一学生下比较oracle方位、真实grounder；单独关掉置信度门控、记忆和停止头。记录grounding误差/延迟与导航失败的关联，才能知道改进来自哪里。

最低交付验收：同一初始画面、两条不同可执行目标指令产生可解释的不同轨迹；在未见场景上也有效；主动STOP和碰撞记录真实；支持域外渲染/GT泄漏不能贡献成绩。之后再决定是否将“基于置信度的异步语言更新与动作稳定性”作为论文方案，先对照公开方法查新和跑消融。
