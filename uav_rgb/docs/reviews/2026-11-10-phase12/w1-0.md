## 5. 离线归因（11-11，只读 `$D/exp-action-latency-20261110/`，不起 gz；对应恢复指令的 9 项）

### 5.1 迟到步慢在哪（第 2 项；`profile_late_steps.py` → `profile-late-steps.md`）

- 平局推演不是第一轮的慢源。第一轮所有臂的 manifest 都是 `teacher_tiebreak=legacy`；legacy 下 `plan_action_global_tiebreak` 只调一次 `plan_action_global`（一次 A\* + 纯追踪），`tie_margin` 恒为 None（2317 个位姿核对）；
  `lr_tie_margin_steps` 只在 `visible` 下才跑。visible 口径补算的 `lr_tie_margin_steps` 是 legacy 单步 CPU 耗时的 1.7 倍，第一轮没有跑它。
- 慢源是那一步的 A\*。按 A\* 行为事后分类（类别在看过迟到清单之后才定，不是预注册）：F = A\* 无路退回局部规划，H = A\* 有路且出堆数 ≥ 1500（长路径、近起点），N = 其余。
  K=3 L=0.16：F 16/59（27.1%）、H 19/56（33.9%）、N 1/708（0.1%）；L=0.20：F 0/34、H 3/56（5.4%）、N 0/731。K=1 两个 L：迟到只有 N 类的 1/318。
- 离线 CPU 耗时（5 次中位，场景重生成与 manifest 的 world_sha256 全部对上）：迟到步 41.1 ms，同批随机不迟到步 15.6 ms，比值 2.63（Mann–Whitney p=2.74e-8）；
  F 类迟到步 37.6 ms 对 N 类不迟到步 8.3 ms，比值 4.55；步号 ≤ 3 的迟到步 44.5 ms 对步号 ≤ 3 的不迟到步 42.4 ms，比值 1.05（p=0.934）：起飞段的 A\* 本身就长（出堆数中位约 2500），迟到只是更靠近阈值。
  CPU 耗时与出堆数的 Spearman 相关 0.49。迟到步集中在每集头 4 步：K=3 L=0.16 为 16/40，L=0.20 为 3/40（`analysis-round1.md` 第 1 节）。
- 离线 CPU 与实测对不上的部分：K=1 的两个迟到步离线 CPU 只有 12.3 ms，而按实测 lag 推出的策略段墙钟为 87–93 ms（seed 172 与 seed 8 的第 0 步），这两步的慢来自系统噪声，不是 A\*。测量时容器被别的任务占满（cgroup `nr_throttled` 增 16），所以读 CPU 比值，不读墙钟绝对值。
- 对 L 阶梯的含义：K=3 起飞段的 A\* 是迟到的主因，L=0.20 的阈值 0.22 s 只留下 3 步（都在步 0 到步 2），L=0.24（阈值 0.26 s）余量最大；
  `--rtf 0.5` 把世界目标实时因子压到 0.5（森林三档实测 action_rtf 均值 0.73–0.76），同样的 A\* 墙钟折成的仿真秒约减为三分之二（估计，未核实），是 B 组的依据。

### 5.2 位移差来自哪（第 3 项；`analyze_round1.py` → `analysis-round1.md` 第 3 节）

K=3 对 K=1 稳态前飞位移低 3.3%（L=0.16）与 2.6%（L=0.20），而逐步生效时长只差 -0.26% 与 -0.00%，时长差按弹性 2.38 只能解释 -0.61% 与 -0.00%。

  （步 3–30 里 r=2 / r=3 / r≥4：L=0.20 的 K=1 为 15% / 12% / 72%，K=3 为 10% / 9% / 82%）。
