# 工程规范（执行细则）

- 建立：2026-10-29
- 适用：在本仓库做任何代码、配置、脚本、数据管线改动的人或 agent
- 和已有文档的关系：`CLAUDE.md` 管**环境与不可违反的边界**，`docs/HANDOFF.md` 第八节
  是**代码规则（doc 11）**，`docs/EVAL_STANDARD.md` 管**报数字的口径**。
  本文是它们之间的**执行顺序**：先做什么、改的时候守什么、改完怎么验、怎么留痕。
  有冲突时，`CLAUDE.md` 与 `EVAL_STANDARD.md` 优先。

## 一、动手前

1. **先声明范围**：这次改哪些文件、**不碰**哪些文件。仓库有并发会话，`ui/` 不是你的。
2. **先复现再改**。写成「输入 X → 错误输出 Y」才算 bug。没有复现的想法不进代码。
3. **改之前 grep 所有调用方**。签名、返回值、错误语义变了，调用方会静默坏掉。
4. **不确定的默认值先不改，先测**。测出来的数才有资格改默认值。

## 二、写的时候

5. **最小改动**。不加没人要的抽象、配置、开关、依赖。删代码优于加代码。
6. 硬约束（违反任何一条就不要提交）：
   - C++ 单文件 **≤280 行**、CUDA 单文件 **≤360 行**。超了拆文件，**不许压注释**。
   - 只编 **sm_75**，绝不 sm_120、绝不 `-arch=native`。
   - 禁 PyTorch / TensorRT / cuDNN / cuBLAS / ROS 2。
   - 模型只输出 4 个离散动作；仿真真值（位置、障碍几何、深度）**不进学生输入**，
     只能用来生成教师标签。
   - 数据 split 按场景/几何组，不按帧随机拆。
   - `ui/` 归另一会话，不改。
7. **注释只写代码看不出来的"为什么"**。不写"这里做了什么"，不写显而易见的。
   已知局限用 `shortcut: <限制>，<什么时候必须修>` 标出来，让它成为显式决策而不是隐患。

## 三、验证

8. **编译 + 全量 CTest（真实 GPU）**。只跑子集、或者只跑 Python，不许说"通过"。
   `bash tools/check.sh` 是入口。
9. **每条修复都要有"改前失败 / 改后通过"的实测对照**。贴真实输出，不写"应该可以"。
10. **行为变更必须给出触发场景和真实输出**：默认值、校验、错误码、退出码，
    都要说清楚谁在哪里会感觉到不同。
11. **没跑的一律写"未跑"**，并写清为什么没跑。

## 四、留痕

12. 每个任务写 `docs/worklog/YYYY-MM-DD-HHMM-<slug>.md`，必须含：
    **做了什么 / 没做什么（每条带原因）/ 待确认 / 验证到哪一步 / 风险与遗留**。
13. 实验数字进 `docs/experiments/<实验名>.md`：命令、环境（有卡/无卡）、时间、原始输出。
    失败也记。worklog 记"做了什么"，实验文档记"跑出什么数"，两者不混。
14. 同一任务继续迭代时**追加 `## 更新 YYYY-MM-DD HH:MM` 小节，不新建文件**。
    结论变了要改开头那行"结论"，不能让文档自相矛盾。

## 五、Git

15. **只有用户明确说"提交"或"推送"时才动 git**。"审查""继续""修一下"都不算授权。
16. **不用 `git add -A`**。逐文件确认归属（本仓库有并发会话在写）。
17. 提交前跑 `git status --short`、`git diff --check`、`git diff --stat`。
18. 提交信息用可读前缀 `fix:` / `feat:` / `docs:` / `test:` / `chore:`，一次提交一个主题。
19. **每次提交后构建都必须是绿的**。所以互相依赖的源文件要放进同一次提交
    （典型坑：CMakeLists 引用了还没 `git add` 的新测试文件 → 干净 clone 直接 configure 失败）。
20. 远端是 `git@github.com:xu967/ALVLN.git` 的 `uav_rgb/` 子目录，推送在 `../ALVLN`
    里做，流程见 `docs/worklog/2026-10-29-1900-attribution-and-git-baseline.md` 的
    「维护方式」。**不要用 partial clone**（会卡死），不要强推。

## 六、清理

21. 一次性调试脚本、`/tmp` 下的临时目录、后台进程，**任务结束当轮删掉**。
    正式单测放 `src/tests/` 或模块目录下，不要散落在 `/tmp`。

## 七、汇报

22. **先给结论，再给证据**。数字必须来自实测，并标明命令。
23. **必须显式列出"没做什么"和"没验证到什么"**。"无明显问题""其他都测过了"这类
    没有信息量的话等于没写。
24. 结构、指标、口径按 `docs/EVAL_STANDARD.md`：离线报 `acc` + `macro_f1` +
    `balanced_accuracy` + 每类召回；只报准确率的结论无效。

## 八、当前已知的、还没修的（不要重复发现，直接接着做）
