# uav_rgb / TinyAerialVLN 长期规划（2026-11-06 立）

- 用途：个人学习项目。目标是一架琛光 E1 MINI（约 100 g 含载荷）+ LicheeRV Nano（SG2002）+ ESP32（CF-Drone 固件）的微型四轴，只靠单目 RGB 和一句短指令，在室内 / 校园里自主避障到达目标；模型自研 C++/CUDA 训练，仿真里训练，真机上跑。
- 本文回答「接下来半年做什么、按什么顺序、每一步怎么算过」。任务状态仍以 `docs/TASKS.md` 为准，口径以 `docs/EVAL_STANDARD.md` 为准，本文只管方向与门禁。
- 原则只有一条：**载具 → 传感器 → 场景 → 语言**，前一层不过门禁，后一层的数字不算数。这是从两次教训里来的：只把执行方式从 X3 换成 cf_stab，学生 SR 0.59 → 0.06；校园任务最近一次闭环 0/80。

## 1. 阶段与门禁

### 阶段 0（本周，11-06 → 11-10）：E1 固件在环 + 给老师的 demo

- 交付：`sim/cf_sitl/`（固件原样编入、电机/电池/刚体/IMU/ToF/光流、定高定速执行器、`cf_sitl_proc`）；Gazebo `CfSitlSystem` 插件 + E1 模型；3DGS 接同一 SITL；可视化 REVIEW #5–#14/#17/#18 修完；Gazebo 柱阵上重采重训 E1 学生；Callinstrasse 教师闭环三视角视频；四组对照数字（教师 / 旧 X3 学生 / 新 E1 学生 / 盲前进，同 20 seed）。
- 门禁：`tools/check.sh` 全过；SITL 自检 0 失败（悬停、阶跃、松杆、确定性）；数字进 `docs/experiments/`，标明 E1 与 X3 不可比；代码推到 GitHub。
- 不做：改固件、接真机、重建自己场地。

### 阶段 1（第 2–4 周）：真机参数标定与 SITL 验收，固件改造并行

- 你们测（清单在 `docs/RESEARCH_2026-11-06_e1_sitl_survey.md` §4.3，按优先级）：整机质量；占空比→推力曲线三档电压（Bitcraze system_id 方法）；悬停占空比与打杆阶跃的 `log dump`；惯量；电机时间常数；陀螺静置漂移；CLI `p` 全量导出；相机标定与延迟。
- 我们做：标定脚本从 `$DATA_ROOT/uav_rgb/real-drone/` 读数据拟合 `e1_mini.json`，逐项把 `status` 改成 `measured`；相机模型（内参、畸变、噪声、运动模糊、曝光、延迟队列）在 `sim/tools/student.py` 入口统一加，Gazebo 与 3DGS 共用。
- 固件（你们团队，`sim/cf_sitl/exec/` 是参考实现）：把定高定速执行器移进 1 kHz 环；四动作 UART 解析器（帧头、CRC、ACK、超时回悬停、再超时降落）；每 tick 刷新 controlTime；日志加电机占空比、原始 IMU、电池电压三列；无桨台架测试。
- 门禁 G1–G4（REVIEW §2.4）：G1 同一串打杆输入，SITL 的 rates/attitude 与真机 `log dump` 对齐（阈值你定，建议倾角误差 <2°、角速度 RMS <10%）；G2 悬停占空比 ±5%；G3 松杆滑行距离、前进位移与顶视视频对齐；G4 过了才拿 SITL 采正式数据。**过 G4 后删 cf_stab / cf_sil / cf_blackbox 及其测试（约 −1900 行）。**
- 决策点：悬停余量。按现在假设 50% 电量 0.82、低电 0.92 超过固件上限 0.90。测完推力曲线后三选一：换 75 mm 桨 / 减载荷 / 接受只用前 30% 电量。

### 阶段 2（第 2–3 个月）：Sim-to-Real 首飞（纯视觉避障，不带语言）

- 场地：先用手机拍你们真正要飞的场地（1.5–2.5 m 高绕飞 2–3 分钟，重叠多，锁曝光，地上放卷尺或 ArUco 定尺度），COLMAP（装到数据盘）+ gsplat 重建成自己场地的 3DGS；尺度和重力对齐一次性作用到 means/quats/scales；用留出的照片做渲染对比验收。
- 训练：在自己场地的 3DGS + E1 SITL 里采集训练；3DGS 侧做光照/曝光/噪声随机化；Gazebo 只保留做接触碰撞的回归。
- 部署：自研权重导出成板端格式（SG2002 的 TPU 工具链需要 ONNX 一类中间格式，自己写一个导出器，不引入训练框架）；量化后离线 parity（同一帧 logits 误差）；端到端延迟（曝光→动作发出）目标 p95 <150 ms，决策 ≥5 Hz。
- 飞行规程：无桨台架 → 系绳 → 网内 → 自由飞；每次飞行记 RGB、动作、ToF、光流、固件日志，回灌到仿真对比图像统计和动作分布。
- 门禁：真机室内 ≥20 次试飞，SR ≥ 50%，碰撞率 < 盲前进；sim 与 real 的动作分布 KL 和图像统计（亮度/对比度/模糊）差异有数字。
- 决策点：相机型号与安装（现在按 Sipeed GC4653 假设）；是否用官方闭源固件的定点模块（能更快飞起来，但 SITL 只能黑盒辨识）。

### 阶段 3（第 3–6 个月）：语言导航（VLN）

- 指令：从 22 词模板升到结构化指令集（地标 + 关系 + 动作，如「穿过红柱子左边的门，在蓝桶前停」），词表 ≤200；先在 3DGS 校园里做，地标用真实物体。
- 模型：加记忆（GRU 或短时序堆帧）解决「停得准」和多步指令；STOP 独立门控；仍是四动作 + 可能新增 STOP/上下（上下需要固件支持，先不加）。
- 评测：按无人机尺度重定成功半径（1.5 m，不用 VLN 基准的 20 m）；SR / OSR / NE / SPL / nDTW；必做三组对照：正确指令 / 打乱指令 / 盲前进，McNemar 检验；≥20 张独立留出地图。
- 门禁：正确指令相对打乱指令的 SR 增益显著（p <0.01）且 SR ≥ 50%；没有这个增益就不叫语言导航。
- 真机：阶段 2 的场地 + 真实地标，先 3–5 条固定指令。

### 阶段 4（6 个月后）：鲁棒与扩展

- 多场景泛化（≥3 个重建场地）、动态障碍（行人）、室外弱风、续航模型下的长任务、电量感知返航。
- 安全：动作超时 / 失联 / 低压 / 倾覆的失控保护全覆盖并有台架测试记录；ToF + 光流做软地理围栏；飞行日志自动归档。
- 整理：把阶段 0–3 的数字、视频、脚本整理成可复现的实验包。

### 第二条主线：教师端算法（与阶段 1–3 并行）

学生模型小、要上 NPU，不好做大；提升空间在教它的人。五条算法按收益排：DAgger 在学生自己的轨迹上重贴标签、把四动作代价差做成价值软标签、不教相机看不见的东西（可见性权重）、PPO 特权教师再蒸馏、学生侧双帧 + 辅助深度头。详见 [`TEACHER_LINE_PLAN.md`](TEACHER_LINE_PLAN.md)（含现有教师代码盘点、每条的最小实现与验证、代码放哪）。

## 2. 横切的四条线（每个阶段都要守）

1. **口径与数据治理**：离线必报 acc + macro_f1 + balanced_accuracy + 每类召回；闭环按 AvoidBench 的 SR/PO/EO；同一张表只放同一载具同一语义；每个数据集过 11 项 audit；split 按几何组；改几何必 bump 版本号。
2. **工程基础**：所有实验守护进程跑（`setsid nohup`、`run.pid`、`DONE`）；`tools/check.sh` 是提交前红线；构建产物与数据只放数据盘；容器 Gazebo 的 EGL 问题是采集瓶颈，优先级高（修好可快 10 倍），修不好就把采集放到 3DGS；sm_75 产物靠 PTX JIT 跑，等稳定后加 sm_89 fatbin。
3. **安全**：模型永远只出四个离散动作，飞控保留最终否决权；任何新动作先在 SITL 验证失控保护；真机规程无桨 → 系绳 → 网内 → 自由。
4. **留痕**：每个任务一份 worklog（做了什么 / 没做什么 / 验证到哪），每个实验一份 experiments 文档，progress.md 让新会话能接上。

## 3. 不做的事（避免返工）

- 不再调第四套占位动力学；不在 SITL 里偷偷加真值（偏航真值、真值高度）。
- 没有真相机参数前不做相机畸变/噪声模型；没有过 G4 前不拿 SITL 数字宣称真机能飞。
- 不引入 PyTorch / TensorRT / ROS 2 到训练推理主线；3DGS 渲染用的 gsplat venv 只是数据工具。
- 不用 VLN 基准的 20 m 成功半径和米级瞬移动作。
- 不在同一张表混报 X3 和 E1、observation 和 dispatch。

## 5. 风险

- 推力余量不足（最大）：会直接决定能不能挂相机飞。先测。
- 采集吞吐：软件渲染 3 s/步，600 集要 7 小时以上；EGL 修不好就把主采集搬到 3DGS。
- 语言 grounding：22 词模板能过的东西，不代表结构化指令能过；阶段 3 可能要改模型结构。
- 板端算力与延迟：SG2002 的 NPU 跑 160×120 CNN 没问题，但 ISP + 推理 + 串口整条链的延迟没测过。
- 单人项目的时间：阶段 1 依赖你们的实测数据，拿不到数据阶段 2 就只能在假设参数上做。
