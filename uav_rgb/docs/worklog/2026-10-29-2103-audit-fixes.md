## 做了什么

### 一、会静默产出坏结果的两条

- `env.sh:18-20`：`__uav_rgb_prepend` 用 `${!var_name}`，`set -u` 下变量未定义直接退出。
  `tools/check.sh:3` 就是 `set -euo pipefail` 后 source 它，干净容器/CI 上第一行就死。
  改成 `${!var_name-}`。
- `src/nn_cuda.cu:16-34`：`CUDA_CHECK` / `check_after_kernel` 原来 `std::exit`，
  而 `conv/linear/softmax` 三个 `.cu` 早已改成抛 `runtime_error`。训练每个 batch 都走
  这两个函数，显存/驱动出错时进程直接退，`train_main` 的 catch 收不到、
  `trainer.cpp:253` 的 `save_checkpoint` 被跳过。改成抛 `runtime_error`。

### 二、输入校验（都是"跑完还报成功"的类型）

- `src/train_main.cpp:39-40`：`--lr` 只做了 `std::stof`。加 `isfinite && > 0` 校验。
- `src/class_weights.cpp:38`：`std::stof("")` 抛异常后 `used=0`，而 `used != tok.size()`
  是 `0 != 0`，空 token 被静默当成 0 权重。加 `tok.empty()` 判断。
- `src/class_weights.cpp:96`：全 0 权重会让加权求和恒为 0，加入口拒绝。
- `tools/preprocess.py:252`：`--size` 允许非 8 倍数，预处理几十分钟后才在 `make_cnn` 报错。
  改为在 `parse_size` 就拒绝。

### 三、训练产物被污染

- `src/train_main.cpp:76`：`RunOwner`（flock + 拒绝非空目录）早已实现、有测试、编进了
  `uavrgb_core`，但没有任何调用点。接进 CLI：`--resume` 为空时拒绝复用非空 `--out`。
  （接在 CLI 而不是 `Trainer::run`，是因为 `trainer.cpp` 已 277 行、上限 280 行。）

### 四、标签可信度

- `tools/preprocess.py:101`：`bool(row.get("collision", False))` 把字符串 `"false"` 判成
  True。改成必须是真正的 bool，否则 die。
- `tools/preprocess.py:69-73`：manifest 的 `error` 非空（采集中断）时直接拒绝打包。
- `tools/preprocess.py:88-91`：`actions.jsonl` 行数与 `num_steps` 不符时报错。
- `src/dataset.cpp:140-190`：没开 `--drop-collision` 时，把碰撞步占比打到 stderr。
  实测旧数据集 6.8%，新 carrot planner 最差场景 37%。
- `sim/tools/collect_parallel.py:296-302`：成功判定原来只看 `episode_executed`，
  现在要求 `camera_verified`/`physics_verified` 同时为真。

### 五、数据集可追溯

  `expert_action` / `forward`）、`hold_s`、`scene_meta_sha256`。原来两种教师策略

## 没做什么

- **没有加 best-checkpoint**（`src/trainer.cpp:253` 每 epoch 覆盖）。
  原因：`trainer.cpp` 已 277 行，上限 280，加不下；需要先按职责拆分文件。
  这是"交付的永远是最后一轮（最过拟合）模型"的直接原因，优先级高。
- **没有实现仿真时间动作窗口**（§19.3）。原因：属于独立改造，`--hold` 仍是墙钟秒，
  采集依然不可复现（同 seed 两次 1.40 vs 2.36）。
- **没有加深度/接触话题的停更检测**。原因：会给采集加新的失败路径，需要在真实
  仿真是做多轮验证，本轮没时间窗口容量。已知后果：深度停更后会继续用旧帧打标签。
- **没有改车道间距**。原因：场景设计决策，且会改变已跑过的全部实验基线。
- **没有做 resume 的数据签名校验**（`src/class_weights.cpp` 只比权重向量）。
  原因：需要给 checkpoint 加字段并升版本，属设计变更。
- **没有给 `nn_cuda.cu` 补 int64 边界校验**。原因：22 GiB 卡上不可达（numel 需要 >2^31），
  属防御性加固，不是当前缺陷。
- **没有给 maxpool 的 float argmax 换 int32**。原因：当前池化后最大 19200，
  离 2^24 还差三个数量级。
- **没有动 `ui/`**（另一会话负责）。审计里发现的 `monitor.py` 增量读前缀冲突、
  SIGINT 不转发两条没有修，已写进给用户的报告。
- **没有改 `collect_parallel.py` 的 TOCTOU**（判空不是原子的，同 out 并发会互相踩）。
  原因：需要加锁文件，属独立改造。
- **没有提交**。仓库有并发会话，只按文件归属逐个改，没有 `git add -A`。

## 一次按实测回退的改动

审计提出 `plan_action` 的 `clearance=0.36` 对机体真实外接半径 **0.3555 m**
（SDF `rotor_0` 在 (0.13, -0.22)、桨盘半径 0.1）只剩 4.5 mm，小于 `ray_clear`
的采样误差。我先改成 0.40 + 加密采样到 65，然后**真机跑了 8 场景 × 80 步**：

| 配置 | 穿过 x=4.0 | 穿过 x=5.0 | max\|y\| |
| --- | --- | --- | --- |
| 0.36 / 33（原配置） | 6/8 | 5/8 | 0.69 |
| 0.40 / 65（改后） | 3/8 | **2/8** | **1.86** |

0.902 m 的缝减去 2×0.40 只剩 0.102 m 瞄准带，比 5° 网格在 1.6 m 处的横向跨度
（约 0.14 m）还窄，planner 大面积退回 `base`，回中线约束丢失。**已回退到 0.36/33**，
把这次证伪和"真正的解法是放宽车道间距"写进了代码注释与实验文档。
实验记录见 `docs/experiments/2026-10-29-teacher-traverse-ablations.md` §5。
