# 2026-11-02 08:30 Teacher 闭环闸门失败诊断

## 做了什么

### 1. 闸门结论：未通过

`--policy teacher-nn`，test split 20 集，`goal_reach`：

| 指标 | 值 |
|---|---|
| SR | **0.0**（0/20） |
| 碰撞率 | 0.05（1/20） |
| 动作分布 | SAFE 57 / FORWARD 259 / **YAW_L 0 / YAW_R 0** |
| 每集步数 | 14–17（上限 60） |

### 2. 定位到「停止」而非「转向」是直接死因

- `collect.py:1057`：**连续 3 步 SAFE 即结束回合**。20 集各 15 步左右、SAFE 总数 57 ≈ 20×3，完全吻合。
- 每集最终距航点 1.50–2.07 m，成功阈值 1.5 m，**19/20 差一点点就到**。
- 专家数据核对：`stop_radius=0.5`，**SAFE 只在距航点 ≤0.50 m 时出现**（984 个 SAFE 步，p95=0.49，最大 0.50）；非 SAFE 步最近 0.63 m。标签边界是锐利的距离阈值，不是在 1.7 m 处停。

### 3. 排除输入管线 bug

给 `eval_closed_loop.py` 加 `--save-depth`，把 seed=1 的闭环帧全留下，再用 `TeacherPolicy` 按同样顺序离线重放：

- **重放预测与闭环实际动作 17/17 完全一致** → 输入管线确定、无 bug，模型真的每一步都选了 FORWARD。
- yaw 单位两边一致（`collect._yaw_deg` 存度；`dataset.py` 和 `teacher_policy.py` 都 `radians()` 转换）。
- 场景几何核对：`relation=right` → 目标柱是左侧那根 `(2.5, 1.614)`，waypoint 在其外侧 `(2.5, 2.414)`，指令与几何自洽。

真实轨迹：drone 从 `(-0.5, 0.84)` 沿 x 轴直线飞到 `(3.0, 0.65)`，**侧向从未移动**，距航点最近 1.74 m。正确行为应在开头就向 +y 侧转。

### 4. 根因：模型系统性低估转向

val split（33 集 / 351 滑窗）离线指标，未加权 ckpt `teacher-run-400/ckpt_best.pth`：

| 类别 | recall |
|---|---|
| SAFE | 0.889 |
| FORWARD | 0.965 |
| YAW_LEFT | **0.400** |
| YAW_RIGHT | **0.387** |

按距航点距离分桶，`预测 YAW 率` 在每个桶都只有 `gt YAW 率` 的 1/2 到 1/3：

| 距航点 | n | GT YAW 率 | 预测 YAW 率 |
|---|---|---|---|
| [0.5,1.0) | 83 | 0.27 | 0.14 |
| [1.0,1.5) | 78 | 0.18 | 0.04 |
| [1.5,2.0) | 46 | 0.15 | 0.07 |
| [2.0,3.0) | 43 | 0.19 | 0.07 |

混淆矩阵主要是 `2→1`（20 个 YAW_LEFT 里 11 个判成 FORWARD）、`3→1`（31 个 YAW_RIGHT 里 15 个判成 FORWARD）。

**因果链**：回合开头几步漏判转向 → 直飞 → 进入训练分布里不存在的状态（专家从不直飞这段）→ 越走越偏 → 靠近柱阵末端时判 SAFE 三连 → 回合在 1.7 m 处结束。

### 6. 根因锁定：闭环 warm-up 窗口在训练里不存在

train split 闭环跑完：**SR 0.1（2/20），仍然 0 次转向**。连训练过的场景都飞不起来
→ 不是场景泛化问题。

用专家 GT 轨迹 + `TeacherPolicy` 的真实 padding 协议逐帧重放（val 33 集 582 步）：

| step | 专家转向率 | 模型预测转向率 | 准确率 |
|---|---|---|---|
| 0 | **0.697** | **0.000** | 0.303 |
| 1 | 0.576 | 0.000 | 0.424 |
| 2 | 0.121 | 0.000 | 0.879 |
| 3–5 | ≤0.121 | 0.000 | 0.88–1.00 |
| 6 | 0.121 | 0.152 | 0.909 |

机制：`_FrameBuffer.build` 在缓冲未满时用**首帧重复**补齐，闭环第 i 步的窗口是
`[f0]×(seq_len-i-1) + [f0..fi]`。训练集只产 `seq_len` 帧真历史的窗口，**从没见过这种拼接**。
而专家恰恰在前两步转向（70%/58%），于是模型在这两步一律输出 FORWARD（转向率 0.000）。
一开局直飞后，轨迹进入专家从不经过的状态，之后再也回不到需要转向的位置。

**修法**：`teacher/dataset.py` 为每集额外产出 `seq_len-1` 个 warm-up 样本，拼接方式与
`_FrameBuffer.build` 逐帧一致（`test_dataset_windows.py` 断言窗口内容）。
样本量 3610 → 5906，YAW 占比 12.6% → 约 18%，顺带缓解类别不平衡。

### 8. 教师补特权目标向量（进行中）

warm-up 版闭环 SR 0.65，剩下 7 个失败里 5 个是**在距航点 0.5–0.9 m 处撞柱**——教师不知道
终点的确切位置，只能从图像反推。教师本来就是特权模型，于是给位姿补两维**机身系目标向量**
（前向/左向），`POSE_DIM` 6 → 8：

- `teacher/dataset.py`：`_pose_sequence(rows, waypoint)` 计算 `goal_fwd/goal_left`
- `teacher/model.py`：`POSE_DIM = 8`（时序 GRU 输入 582 → 584）
- `sim/tools/teacher_policy.py`：`act()` 增加 `waypoint_xy` 参数，同口径计算
- `sim/tools/collect.py`：把 `waypoint` 传进去；非 l1 任务显式报错
- `test_dataset_windows.py` 增加目标向量断言（yaw=0、waypoint=(3,1) 时 `goal_fwd=3-0.5i`）

旧 ckpt 的 `pose_dim=6` 与新口径不符，加载时会明确报错，不会静默错位。

## 蒸馏的 C++ 落地（W4 前置）

计划文档写的是「C++ 侧用 cnpy 读 .npz」。改成**不引入任何新依赖**：

1. `teacher/export_soft_targets.py`：按 `(episode_id, step)` 导出软标签
   （修掉了滑窗改造后「同一集第二个窗口就 sys.exit」的致命 bug，并加导出条数断言）。
2. `tools/join_soft_targets.py`（新）：按 `.uavr` 的**全局样本序**拼成扁平
   `float32[n*C]`，只给 C++ 读一个裸数组。
3. `src/ops_soft.cpp`（新）：`softmax_ce_loss_soft` / `softmax_ce_grad_soft`，
   `L = α·软标签CE + (1-α)·硬标签CE`，梯度 `α(p-q) + (1-α)(p-onehot)`。
4. `uavrgb_train --soft-targets <bin> [--distill-alpha A]`；与 `--class-weights` 互斥
   （两种 loss 归一化口径不同，混用会悄悄改变梯度尺度）。
5. 软标签文件大小必须严格等于 `n*C*4`，否则直接报错——错位会把样本 A 的教师分布
   喂给样本 B，而且训练曲线看起来完全正常。

测试：
- `test_soft_loss`：α=0 与无权 CE **逐位一致**、α=1+one-hot 等价硬标签、手算对照、
  FP64 有限差分 gradcheck、非法输入（尺寸/未归一化/α 越界/label 越界）抛异常。
- `test_soft_targets_train`：合成 4 类数据上，对齐软标签 val_acc **0.733**，
  故意旋转一类的软标签 val_acc **0.050** —— 证明软标签确实按全局下标生效。
- 全量 CTest：**23/23 PASS**。

## 没做什么

- **没有加数据**。按预定纪律，闸门失败先查预处理/管线；现在管线已排除、根因已定位为「转向召回低」，在验证过 seq_len 对照实验之前不堆数据。
- **没有改老师模型结构**。`--save-depth` 是唯一代码改动（2 处，纯诊断开关，默认关闭，不改变任何既有评测结果）。
- **没有把 trainer 的 `float(loss)` warning 修掉**（不影响结果，纯噪声）。

## 待验证的两个对照实验

1. **train split 闭环**（进行中）：同一权重在训练过的场景上跑 20 集。
   - SR 高 → 问题是**场景泛化**，要加几何多样性。
   - SR 仍 0 → 问题是**策略组合**（时间窗 padding / 漂移），与场景数量无关。
2. **`--seq-len 1` vs `--seq-len 8`**：验证 8 帧 Bi-GRU 是否反而有害。若有害，学生端的 GRU 设计必须重新论证——这直接决定要不要花 6 天写 GRU 的 CUDA kernel。
3. **warm-up 重训**（进行中，`teacher-run-400-warmup`，20 epoch / 5906 样本）：
   用同一套 `warmup_probe` 复测，step 0 准确率必须从 0.303 明显抬升，再跑闭环闸门。

## 对学生端 GRU 设计的影响

warm-up 缺陷是**时序模型 + 定长窗口**特有的：学生当前是逐帧 CNN，没有缓冲，天然没有此问题。
如果按计划给学生加 GRU，会原样继承这个坑——训练时必须同样补 warm-up 拼接，否则闭环前几步
同样会退化。这一条要写进 GRU 的 CUDA kernel 测试清单。
