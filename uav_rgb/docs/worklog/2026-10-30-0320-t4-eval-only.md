# T4：训练器加 `--eval-only`，复评 ckpt_best

- 时间：2026-10-30 03:20
- 范围：`src/train_main.cpp`、`src/trainer_eval.cpp`、`src/include/uavrgb/trainer.hpp`、
  `src/metrics_json.cpp`、`src/tests/test_eval_only.cpp`、`src/tests/synthetic_dataset.hpp`、
  `src/CMakeLists.txt`
- 结论：**完成**。`uavrgb_train --eval-only <ckpt>` 可用；CTest 20/20；
  对 airsim10k 的 `ckpt_best.bin` 复评出 test `macro_f1=0.5173`（末轮只有 0.3855），
  且训练期 val 行逐字节复现。

## 做了什么

- `trainer.hpp` / `trainer_eval.cpp`：新增 `Trainer::eval_only(ckpt, eval_val, eval_test)`。
  只加载 checkpoint、建模型、跑 `evaluate`，不建优化器、不更新权重；向
  `<out>/metrics.jsonl` 追加 `split=val|test` 的 validation 事件，字段与训练期一致。
- `train_main.cpp`：解析 `--eval-only <ckpt>` 与 `--split val|test|all`；eval-only
  走独立分支，跳过 lr/epochs 校验；用 `RunOwner(out, resume=true)` 允许非空 run-dir，
  防止与正在写同一目录的训练并发。
- `trainer_eval.cpp`：显式请求的 split 为空时写 `EVAL_SPLIT_EMPTY` FATAL 事件并抛错，
  不再 exit 0 假装评过；stdout 先打印与 metrics.jsonl 相同的 JSON 行，再打印人读行。
- `metrics_json.cpp`：validation 事件**无条件**输出 `macro_f1` / `balanced_accuracy` /
  `confusion`（空 confusion 写 `[]`），避免新评估路径漏填字段时静默丢掉四件套。
- `src/tests/test_eval_only.cpp`：合成 16/4/4 的 train/val/test 集，训练 1 epoch，
  再用 `ckpt.bin` 跑 eval-only；断言 val/test 两条 validation 与训练期逐字节一致、
  `results.csv` 行数不变、四件套字段存在。
- `synthetic_dataset.hpp`：`write_synthetic_uavr` 增加可选 `test_n`（默认 0），
  其余调用方不变。
- 真实验收：`airsim10k-run/ckpt_best.bin` 与 `ckpt.bin` 各评一次，输出到
  `airsim10k-eval-*`；数字见 `docs/experiments/2026-10-30-t4-eval-only.md`。

## 没做什么

- **没有做闭环评测**：T7 才把 `ckpt_best` 接进 Gazebo；本轮只做离线 val/test。
- **没有验证 `--drop-collision=true` 的对账**：airsim10k 的 `config.json` 是
  `drop_collision=false`，本次两边一致；带碰撞过滤的数据集需要另外对账。
  - 原因：没有带碰撞标记的新数据；合成夹具没有 collision 字段。
- **没有自动读取 `<out>/config.json` 校验 batch/drop-collision**：C++ 侧没有 JSON
  解析器，强行加会引入依赖；本轮用「同 batch/同 drop」的命令约定并在实验文档写明。
- **没有给 eval-only 加 `--resume` 语义**：`RunOwner` 的 resume=true 只用于放行
  非空目录，不会加载优化器。
- **没有把 `--eval-only` 接进 UI**：UI 属于另一会话的文件域，且 T4 不依赖它。

## 待确认

- 逐字节对账依赖同 batch；是否要在 eval-only 里强制读取 config.json 的 batch？

## 风险与遗留

- eval-only 用 `RunOwner(resume=true)` 会在输出目录留下 `.run.lock`；后续训练
  `--resume` 可接受，但普通训练仍要求空目录。
- 对账只对同 batch 成立；不同 batch 的浮点求和顺序会让末位变化，不能再用逐字节断言。
- `ckpt_best.bin` 的历史 run 没有 epoch 元数据；本次靠 metrics.jsonl 的 epoch 1
  val 行对账，后续应在 checkpoint 头里加 `best_epoch` 以简化追溯。
