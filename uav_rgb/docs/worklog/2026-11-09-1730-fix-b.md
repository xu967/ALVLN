## 没做什么

- `--save-every-epoch`：归 STUDENT-SELECT；本批没碰 epoch 末写 `ckpt_best.bin`/`ckpt.bin` 的那段。
- `check_elems` 合并进 `cuda_check.hpp`：三个文件报错前缀不同（`conv2d_cuda:`/`linear_cuda:`/`softmax_cuda:`），测试断言依赖；合并要加 `where` 参数改 ~15 处调用，收益 15 行，不做。
- `--cosine-lr` 的「resume 时显式关掉」：CLI 没这个语法，加 `--no-cosine-lr` 是新 flag（BRIEF 禁改 CLI 面），留 `shortcut:`。
- SHA256 实现本身的速度（标量 ≈92 MB/s，`sha256sum` 的 SHA-NI 快 2×）：不在清单，且一遍 681 MB 的 CPU 只 7 s，重负载下墙钟才到 30 s，问题在机器被占满不在算法。
- eval-only 的 `--out` 归属检查没覆盖「目录里只有 metrics.jsonl 没 config.json」的老 eval 目录：那种目录本来就是 eval 专用，继续放行。

## 风险与遗留

- #3 的归属检查会拒绝「把别的 run 的 ckpt 评进一个有 config.json 的目录」。若有脚本一直这么用（比如把多个模型的 eval 都堆进某个训练目录），现在会 rc 2；改成 `--out` 新目录即可。
- B2 之后，凡 `config.json` 里记了 `augment/warmup_steps/cosine_lr/weight_decay/label_smoothing` 的 run，resume 都会把它们带上——这是修正而不是漂移；但此前做过的「带这些开关的 run 再 resume」实验，续训段实际跑的是默认算法（AdamW 退回 Adam 等），解读那些曲线时要记得。
- `tools/preprocess.py` 是 DAGGER-GZ 的域，B1 只改了 `aux_payload` 内 6 行 + 新增 `episode_focal_px`；合并时若 GZ 也动了该函数需人工对一下。
