## 风险与遗留

- GPU 默认针对本机 NVIDIA Linux GLVND 路径；其他机器必须安装对应 EGL，或显式使用 software。
- software 表示旧显示路径；其他显示服务可能使用 GPU，实际 renderer 必须单独确认。
- Ogre 写共享 `~/.gz/rendering/ogre2.log`；本轮串行复制证据，未引入 HOME 重定向。
- RTF 从约 0.24 提到 1 后异步采样轨迹可能不同，两组世界一致但并非位姿逐帧相同。
  审计通过不意味着训练/评测分布逐像素等价。
- 所有修改保留在工作区；此前已有其他未提交修改，未撤销或删除。

## 更新 2026-11-03 14:06：GPU 改动审计

审计结论：本机 GPU 启动和两个 campus 场景约 4.2× 每步加速证据成立；
在扩展并发与正式跨后端评测前，应修复以下 4 项。范围是此次 GPU 改动及其直接调用链，
不是对全部历史未提交修改的重新认证。

### 做了什么

- 两个 agent 分别复查启动/清理和统计/实验，主审独立复现并核对 HEAD，区分新增与既有问题。
- 读取所有共享启动调用、控制时序、episode/eval 汇总和清理；重跑相关 Python 测试。
- 对照实际世界字节、Ogre 日志、manifest、oracle 和审计结果，确认报告没有将软件审计失败隐去。

### 发现与最小修复

1. **P1 / 既有：全局扫杀会误杀其他任务。**
   `sim/tools/collect_parallel.py:166` 的 `_sweep_orphan_topics` 只凭 ppid=1、
   进程名和 `/uav/`、`/model/x3` 话题判定归属，未检查本次 partition/登记 PID。
   `cleanup_all()` 在采集和评测收尾都会调用它；独立后台订阅者也可能符合条件。
   最小修复：删除全局扫杀，清理只针对本次登记进程组。否则一个任务结束可能中断另一个任务。

2. **P2 / 既有：组长退出后，同组残留子进程可能继续占用算力。**
   `sim/tools/collect_parallel.py:128` 只在 `proc.wait()` 超时后发 SIGKILL。
   当组长已退出、子进程忽略 SIGTERM 时，代码检查五秒后仅告警并取消登记，后续清理无法重试。
   最小修复：根据进程组是否还存在升级信号，只有清空后才取消登记；不要只看组长状态。

3. **P2 / 新增：observation 模式的 action_rtf 时间区间不一致。**
   `sim/tools/collect.py:859` 用 `sim_dt/window`，但 `:674` 和 `:759`
   在 observation 模式让分子包含派发前推理时间，`:730` 的分母只包含派发后的动作。
   base/l1 默认采用该模式。实际 1×、推理 0.8 秒、动作剩 0.2 秒，结果报 5×。
   最小修复：独立记录派发起点的性能 sim_dt，或在 observation 下将 RTF 标为不可用；
   不要改变旧标签/动作合同。补 collect_one 到 performance_summary 的回归测试。
   否则会把推理越慢误读为仿真越快。上轮 campus 是 dispatch，不受该大偏差影响。

4. **P2 / 新增字段漏接：默认评测丢失后端与性能元数据。**
   `sim/tools/eval_closed_loop.py:345` 未将 episode manifest 的 `performance` 和
   `render_backend_requested` 复制到最终报告；`:585` 默认删除 `.work`，唯一记录随之丢失。
   最小修复：删除工作目录前读取并汇总这两个字段，继续明确 requested 不是实际 renderer。
   否则保存的 eval.json 无法区分请求的 GPU/软件路径，也不能取得新增 RTF。

## 更新 2026-11-03 14:57：四项审计缺陷修复

### 做了什么

- `collect_parallel.py` 删除全局 orphan 话题进程扫描/终止及启动、收尾两处调用。
  `cleanup_all` 只遍历本次登记的进程组，不再按话题名认领其他任务。
- `stop_group` 按进程组是否还有运行成员决定 TERM→KILL，即使组长已退出也继续回收。
  只读 `ps` 快照用于识别指定组的 zombie；探测失败保守保留登记，清空后再取消登记。
  取消登记前再 `poll` 回收可能刚退出的直接子进程。
- `collect.py` 为性能单独统计 `dispatch_sim_dt`，`performance.rtf_basis` 明确为
  `dispatch_pose_to_after_pose`。旧 `sim_dt`、action_start、标签和动作窗口语义保留。
  无可测仿真时间推进时 `action_rtf=null`。
- `eval_closed_loop.py` 在删除工作目录前复制 `performance` 和 `render_backend_requested`
  到持久报告，采集失败明细也保留可用字段；旧 manifest 缺失时明确 null。
- 新增 `test_process_cleanup.py`、`test_eval_provenance.py`，扩展 `test_rendering.py`。
  两个 agent 分别负责清理/评测，主 agent 负责计时、集成和真实验证。
- `sim/README.md` 说明新的统计口径与默认评测元数据留存。

### 待确认与风险

- 无本轮阻塞待确认项。
