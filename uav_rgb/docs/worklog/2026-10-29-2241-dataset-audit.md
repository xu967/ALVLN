# D0：数据集验收闸门

- 时间：2026-10-29 22:41
- 范围：`sim/tools/audit_dataset.py`（新）、`sim/tools/test_audit_dataset.py`（新）
- 结论：**部分完成**。8 条检查里 6 条可用、2 条因旧数据缺字段只能 SKIP；
  拿现有 200 集数据跑已经在 4 条上判 FAIL，证明「以前的数据集有问题」不是猜测。

## 做了什么

- `sim/tools/audit_dataset.py`：递归读采集产物（manifest + actions.jsonl +
  oracle.jsonl + scene.json），把「数据是否正确」拆成可机械判定的不变量，
  任一条 FAIL 就非零退出。检查项：
  - `manifest_validity` 每集 validity 三项必须全 true
  - `time_pairing` 每步 depth/pose 与 RGB 的 gap ≤ 50 ms
  - `action_window` 动作窗口 sim_dt 的变异系数 ≤ 5%
  - `forward_motion` 稳态前进步位移 ≥ 0.4×SPEED_FWD×dt，失败率 ≤ 1%
  - `transition_lag` 偏航接前进的过渡步位移中位数 ≥ 标称 50%
  - `yaw_direction` YAW_LEFT ⇒ dyaw>0、YAW_RIGHT ⇒ dyaw<0
  - `class_share` 每类占比 ≥ 5%
  - `split_geometry` 跨 split 的 geometry_gid 交集必须为 0
  - `label_recompute` 用 pillars + 动作前位姿复算标签（**未实现**，见下）
- `sim/tools/test_audit_dataset.py`：4 组用例（干净数据全过、窗口漂移、
  缺类、几何跨 split 泄漏）。`tools/check.sh` 自动 glob `sim/tools/test_*.py`，
  无需改脚本。

## 没做什么

- **没有实现 `label_recompute`**。原因：`actions.jsonl` 没记动作前位姿，
  无法用 `plan_action` 复算。需要 `collect.py` 多写 `pose_before` / `yaw_before`。
- **没有校验「图像和标签是否对齐」**。原因：采集只存 RGB PNG，depth 用完即弃；
  要投影柱子真值到图像平面做 IoU，得先把 depth 存盘。
- **没有处理 `forward_motion` 的位姿差近似误差**。旧数据没有 `displacement_m`，
  用相邻动作后位姿差代替，误差是一个位姿周期（实测窗口错位 20–60 ms）。
  这会让该检查在新旧数据上口径不一致；新数据有真字段，不受影响。
- **没有接进量产流程**。原因：闸门先要验证自己；等新采集格式补齐字段后再设为
  `preprocess.py` 的前置门禁。
- **没有跑新格式数据**。原因：唯一的新格式数据是学生闭环评测产物
  （`--stop-on-collision` 会提前结束，validity 全 false），不是训练集。

## 待确认

- `action_window` 阈值定 5% 是否合理：Gazebo RTF 抖动是物理事实，改 sim-time
  hold 后应该接近 0；若仍超 5% 说明还有别的漂移源。
- `transition_lag` 失败要不要算「不能用于训练」？它记录的是真实物理
  （偏航减速→前进加速），不是 bug；但标签「前进 1 秒」对应的位移只有标称的 19%。
- `class_share` 5% 门槛：四类均匀是理想值，实际避障场景里 SAFE_NEUTRAL 天然偏少，
  是否要改成「每类至少 N 条」而不是比例。

## 风险与遗留

- **最大的风险**：`label_recompute` 和图像对齐这两条没实现，「标签是否等于
  teacher 在那一帧该做的动作」目前仍无证据。其余检查证明的是「数据自洽」，
  不是「标签正确」。补齐 5 个字段后必须先跑这两条再量产。
- 阈值（50 ms / 5% / 1% / 50% / 5%）是首版经验值，没有用多批数据标定过；
  改阈值等于改验收口径，要同步改文件头说明。
- `split_geometry` 只能查「同一批数据内部」泄漏；跨批次（旧数据 + 新数据）
  的泄漏查不出来，除非每次把历史 gid 并进来。
