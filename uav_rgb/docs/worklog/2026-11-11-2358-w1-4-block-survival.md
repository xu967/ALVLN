## 做了什么

- `eval_closed_loop.py` 新增 5 个函数、2 个常量：
  - `block_outcomes(actions, oracle, goals, half_width, aborted)`：逐块判据，从 `summarize.py` 移入。与原函数相比只有 3 处不同：缺省半宽的常量名、docstring 多 2 行、`outside` 一行加了 `half_width is not None`（评测没开走廊时不查横向）。
  - `blocks_passed(oracle, actions, block_goal_x, corridor_half_width)`：卡里的签名，返回通过的块数，是 `block_outcomes` 的块数封装。第 k 块通过 = 首次到达 `x >= block_goal_x[k]` 之前（含那一步）无接触碰撞且 `|y|` 不超过走廊半宽。
  - `flight_path_m(oracle, actions, goal_x, ...)`：一集的 oracle xy 折线，量到首次接触碰撞（含那一步）、越界（`|y|` 超半宽）或进入目标区（过线按插值点）为止。折线与目标区的写法复用 `trajectory_xy` / `goal_path_length_m`，与 `summarize_episode` 的 `path_length_m` 同一套。
  - `collisions_per_100m(episodes)`、`block_survival(episodes, requested, blocks)`。
  - 常量 `BLOCK_CORRIDOR_HALF_WIDTH_M = 3.0`、`FLIGHT_PATH_KEY = "_flight_path_m"`。
- `run_episode`：course_base 的每集 summary 加 `blocks_passed`、`blocks_total`；所有任务加私有键 `_flight_path_m`。走廊半宽用评测自己的 `--corridor-half-width`。
- `write_report`：顶层加 `collisions_per_100m`（所有任务）和 `block_survival`（只在 `--task course_base`，长度 K，分母 = 请求集数，与 `requested_success_rate` 同口径）；`per_episode` 去掉私有键（和 `infer_ms` 一样只供汇总、不落盘）。
- `aggregate()` 与 `summarize_episode()` 没改：3DGS 评测（`sim/3dgs/eval_3dgs.py`）与 `tools/compare_datasets.py` 共用它们，新键只在 `run_episode` / `write_report` 加。
- `summarize.py`：删掉自己那份 `block_outcomes`，改为从 `eval_closed_loop` 导入。在仓库里跑用仓库的 `sim/tools`；被拷进实验目录时先找目录里冻结的 `code/sim/tools`。
- `test_eval_blocks.py`（33 项）：`blocks_passed` 三种轨迹与边界；`flight_path_m` 的截断规则；完整 `ec.main()`（假 scene_gen 用真生成器出 meta，假 collect 写指定轨迹）走到 `eval.json`，冻结旧键集合（取自 main a714b54 的真实输出）、锁分母与失败集；`summarize.py` 与 `eval_closed_loop` 共用同一份 `block_outcomes`；`aggregate` / `summarize_episode` 的键集合不变。

## 没做什么

1. 没让 `summarize.py` 改用 `blocks_passed`：它要的是逐块明细（每块是否通过、失败归属、过线步号、过线 `|y|`），`blocks_passed` 只返回块数。卡里「import 它并删掉自己那份」我读成：判据只留一份，所以把 `block_outcomes` 移到 `eval_closed_loop.py`，`blocks_passed` 是它的封装，`summarize.py` 导入 `block_outcomes`。读法见「待确认」第 1 条。
2. 没改 `aggregate()` 与 `summarize_episode()`：原因见上，共用方的输出要逐位不变。
3. 没把逐集飞行路程写进 `per_episode`：卡的第 2 条列了 `blocks_passed` 与 `blocks_total`，没有路程键，「新键只在卡里写的条件下出现」。代价：`eval.json` 里只有 `collisions_per_100m` 这一个比值，零碰撞的臂拿不回分母；原始轨迹在 `<out>/episodes/seed_N`，可用 `flight_path_m` 重算。
4. 没改 `docs/EVAL_STANDARD.md`：卡没列；W1-2 的卡要在它的 §5 追加主比较协议，并行分支改同一文件容易冲突（W1-0 的那一节已经在 main 里）。新键的定义写在函数 docstring、本文和报告里。
5. 没改 `experiments/2026-11-10-rule-oracle-v1/summarize.py` 里自带的那份 `block_outcomes` 副本：卡只点了长课程那份，那份是冻结实验的脚本。
6. 没起 Gazebo、没跑真实评测：卡不要求，机器也被 W1-0 第二轮占着。真实 cf_sitl 评测下新键的数值未核实；验证用合成轨迹加离线重算既有实验。
7. 没新增 `docs/experiments/` 文件：没有跑新实验。
8. 没跑 C++/CUDA 构建、CTest、GPU 测试、cf_sitl：`check.sh --python-only` 本来不含这些，它的末行也写明了（见「验证到哪一步」）。

## 待确认（主会话）

1. 卡里「`summarize.py` 改为 import 它并删掉自己那份」：我的读法见「没做什么」第 1 条（导入 `block_outcomes`，不是 `blocks_passed`）。如果要求 `summarize.py` 只经 `blocks_passed` 取数，需要先放宽它对逐块明细的使用。
2. `--corridor-half-width` 没开（缺省 None）时，`blocks_passed` 不查横向，与那次评测的 `success` 同口径；`summarize.py` 离线读到 None 时仍按 3.0 判（它原来的做法）。长课程评测现在都带 `--corridor-half-width 3.0`，两者一致；如果要求任何情况下都按 3.0 判，改 `run_episode` 里传的那个参数即可。
3. `collisions_per_100m` 的分子取每集 `collision` 为真的集数，与 `collision_rate` 的分子同口径。路程只量到首次碰撞、越界或过线，所以过线之后才发生的碰撞会进分子、不进分母；sim09.v2 下路线集过线即结束，这种集不会出现。
4. 逐集路程不落盘（见「没做什么」第 3 条）。要落盘就是在卡外多一个键，需要主会话点头。
5. `EVAL_STANDARD.md` 是否补一节：W1-2 在改同一文件（§5），建议合并时由主会话统一写。

## 风险与遗留

- `summarize.py` 现在依赖 `eval_closed_loop.py` 里有 `block_outcomes`：W1-4 之前冻结的 `code/sim/tools` 快照里没有，把新 `summarize.py` 拷进那样的旧实验目录会 `ImportError`。新实验起跑时冻结的快照带这个函数；旧目录里原来的 `summarize.py` 副本自带旧函数，不受影响。
- `block_survival` 的分母是请求集数；被中断的评测（`partial=true`）里未跑到的集算没通过，不能当完整结果报。离线汇总脚本的 `--present-only` 口径（分母 = 有轨迹的集数）与它不同。
- 采集中止的集（如 calswa-s0 的 2 集 FAILSAFE）在 `failed[]` 里，不进 `per_episode`，所以不进 `block_survival` 的分子；`summary.md` 里它们按部分轨迹算块数。离线重算的 7 个臂里，两个口径（有轨迹的全部集 / `eval.json` 完成集）的分子逐臂相同，calswa-s0 那 2 集通过 0 块；分母不同（有轨迹集数 / 请求数 20），被中断的 4 个臂（teacher 16 集、guard2-calswa-s2 17 集、calswa-s1 3 集、calswa-s2 2 集）差在这里。
- 真实评测下新键的数值没有跑过（见「没做什么」第 6 条）。
