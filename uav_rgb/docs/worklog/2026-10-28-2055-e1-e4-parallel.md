## E1 实测结果（真实输出）

- **纯 headless（`gz sim -s -r` 无 DISPLAY）跑不通相机**：Ogre2 EGL 去初始化无驱动的 NVIDIA
  `/dev/dri/card1` → `eglInitialize failed` → `OpenGL 3.3 not supported` → segfault，`/uav/camera` 不发布。
- **workaround 实测可用**：`DISPLAY=:20 gz sim -s -r sim/worlds/uav_rgb.sdf` 走软件 GLX 回落，
  `WORLD_READY`、`/uav/camera` 发布、抓帧 230400 字节 RGB、地标清晰；速度指令后 z 连续上升（0.055→0.354），四旋翼能飞。
- **未下载官方 X3 Fuel 网格**（fuel.gazebosim.org ~15KB/s 太慢），世界把四旋翼 inline 成 X3 等价体，
  视觉用 box/cylinder 替代 COLLADA 网格；README 写明可换回官方 `<include>`。

## 没做什么

- E4 只做了 **Linear 一层**，没做 Conv、softmax-CE 的 CUDA loss/grad、Adam。
  - 原因：按任务约束「优先只做 Linear」；其余待 E5 训练器起步再补。
- E4 的 CUDA 包装每次临时 `cudaMalloc/cudaFree` + 每 kernel 全量同步，没做持久设备缓冲 / 异步流水。
  - 原因：parity 自检专用 shortcut；生产训练层要改持久缓冲复用（已在 header 注释说明）。
- E1 没做速度指令 + 相机帧 + 位姿按 sim-time 对齐的采集循环、没做 128×128 下采样写 episode、没做相机内参标定/reset 复位校验。
  - 原因：E1 只做「世界 + 相机 + 四旋翼」脚手架，采轨迹属 E2/E3；内参标定/reset 校验属 GZ1 验收。
- E1 没实测 `record_video` 的 mp4 落盘（只确认 service 已注册）。

## 风险与遗留

- 纯 headless 相机渲染依赖容器内 `DISPLAY=:20` 的 Xorg 软件 GL；若该显示服务消失，相机退回 segfault。
- 2080 Ti 消费级无 ECC，CUDA 训练留意数值稳定与显存（22GB 魔改版）。
- E4 CUDA 目前每次调用都同步 + 临时分配，训练时吞吐会低一个数量级，E5 前要改成持久缓冲 + 异步。
- E1 世界用 inline 的 X3 等价体而非官方网格模型；物理参数一致但视觉不同，若需要官方模型外观需另解决 fuel 下载。
