# 专家策略卡死修复（三带全堵 → 永远 SAFE_NEUTRAL）

- 时间：2026-10-29 00:04
- 范围：`sim/tools/teacher.py`
- 结论：完成（实跑验证：12 步不再卡死，动作含转向）

## 做了什么

把 `expert_action` 的判定阈值从「固定安全距离」改成「转向距离 + 紧急距离」两级：

- 旧签名 `expert_action(depth, w, h, min_clear=2.0, prev_action=None, switch_margin=0.75)`
- 新签名 `expert_action(depth, w, h, turn_dist=1.5, emergency=0.8, prev_action=None, switch_margin=0.75)`
- 旧逻辑：某侧 < `min_clear` 就不算「可走」，三侧都不可走 → `SAFE_NEUTRAL`
- 新逻辑：中心 ≥ `turn_dist` 才前进；三面**全部** < `emergency` 才算真被围死；否则转向更空的一侧
- 新增 2 条回归用例（三带都 1.88m 不卡死、三带都 1.2m 转向而非停住），自测 20 → 22 项全过

## 为什么改（实测根因）

实跑 10 步专家策略，得到：

```
step0..2: FORWARD_SLOW    x 0.06 → 0.35
step3..9: SAFE_NEUTRAL    x 冻结在 0.418，只有 z 在爬升
```

诊断三带深度（相机在 x+0.2 处）：

```
x=0.42 z=1.65 | L=1.88 C=1.88 R=1.88  -> SAFE_NEUTRAL
```

红色地标是 1m 立方体（x 2.5–3.5），相机在 x=0.62，到正面正好 **1.88m < min_clear 2.0**。
而 1.88m 处该地标横向张角 ±15°，**同时落进左/中/右三条带**，于是三带读数完全一样（都是 1.88），
旧逻辑判定「三面堵死」→ 永久停住。

本质缺陷：`min_clear` 要求「某一整侧都 ≥ 2m」，但单个近处障碍会同时污染三条带；
而实际场景里前方只有一个方块，左右绕开完全可行。

## 风险与遗留

- 新策略更「敢飞」：三面都 0.8–1.5m 时仍会选择转向而不是停，若场景真的无路可走会来回转。
  真正的死胡同需要靠 `emergency` 兜底，本轮未构造该场景验证。
- 采样周期仍是 ~1.7s/步（echo 开销主导），采集吞吐低；数据量要求 2000 episode 时需先换 gz-transport 直连。
- 单目细障碍（2cm 线缆）依然是物理极限，专家用深度相机能看到，学生用 RGB 学不到 —— 这条信息差必须写进最终报告。
