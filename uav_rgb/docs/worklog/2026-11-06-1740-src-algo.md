### ② 改前每步耗时拆解（nsys，batch 128，与用户 YOLO 共享 GPU）
每步 ≈ 1905 ms：conv dW 314 ms、conv db 110 ms、H2D 1.7 GB/步 215 ms、D2H 1.3 GB/步 188 ms、cudaMalloc/Free 81 ms、conv dx 11 ms、conv 前向 10 ms、其余 kernel 4 ms，剩下 ≈ 970 ms 是 host 侧（uint8→float、每层 `Tensor::zeros` 157 MB 分配页错误、argmax host 校验、reshape 拷贝）。

### ③ parity 测试改多 block 形状（0c09d66）
conv/relu/pool/linear/softmax/adam/clip 的 CPU-CUDA 对拍原来都是单 block 能装下的小形状，改成跨 block、非整除的形状（如 conv x `[3,2,40,17]`、linear n=300、softmax n=600），并补 pad=0 的卷积配置。

### ④ conv 反向并行化 + 设备指针级 API（05ebcfb）
- dW：grid(权重块, n, oh/16)，每线程算一个权重元素在一个样本 16 行内的部分和；db：每 (out, n) 一个 block 的共享内存树形归约。部分和写进工作区（`conv2d_backward_workspace`），再由 `reduce_rows_kernel` 按固定顺序求和（458980e）。单步 dW 314 → 9.9 ms，db 110 → 0.5 ms，归约 0.1 ms。
- 第一版用 float atomicAdd 归约（05ebcfb），求和顺序随调度变化，训练轨迹不再逐位可复现，`test_soft_targets_train`（阈值按确定性轨迹定）12 次挂 2 次（旋转软标签 val_acc 0.35 > 门槛 0.30）。458980e 改成上面的确定性归约后 8 次结果逐位相同（0.717 / 0.033）；文本 embedding 梯度同样由原子加改为每 (id, d) 顺序扫 token。
- 新增 `uavrgb::dev` 命名空间（`ops_dev.hpp`）：只接设备指针、不分配不拷贝不同步，host 包装与常驻路径共用同一份 kernel。
- `conv2d_backward_cuda(..., need_dx)`，c1 不再算输入梯度（每步省一个 157 MB 的 dx）。

### ⑤ 设备常驻训练/评估路径（07100f2）
- `model_dev.hpp/.cu`：`DeviceCnn` 把参数、梯度、Adam m/v、全部激活放在显存；每步只 H2D 一批 uint8 图像（7.4 MB）+ token id，D2H logits（2 KB）与梯度范数（8 B）。loss / dlogits 仍用 host 现有函数（logits 只有 N×C 个数）。ReLU 原地；FiLM 文本分支也在设备侧（`__fmul_rn/__fadd_rn` 保证与 CPU 逐位一致）；uint8→float 用 `/255.0f` 与 `infer.cpp` 同一舍入。

`infer.cpp` 构造 `DeviceCnn(model, 1)`，每帧只上传 57.6 KB uint8（HWC→CHW 仍在 host，不转 float）。协议不变。

### ⑦ 算法 A/B 开关（325dd26、5aac3e4）
- `--augment all|photo,shift,flip`：设备侧增强（`augment_dev.cu`），host 每批多传 24 B/样本；翻转只给纯视觉模型并互换 YAW_LEFT↔YAW_RIGHT；增强 rng 与打乱 rng 分开（A/B 时样本顺序不变）；与 `--soft-targets` 互斥。

## 没做什么（含原因）

- **GAP 头（19200→4 fc 换 GAP+Linear 64→4，ckpt v6）没做。** 任务定为可选、且只有 A/B 更好才做；导航决策依赖目标在画面中的位置，GAP 丢空间布局，预期有害；结构改动波及 host 路径、常驻路径、checkpoint v6、推理 meta，不该在无证据时花这笔。fc 76.8k 参数是权重体积的 77%，但 MAC 只占 0.15%，对 SG2002 延迟无影响。
- **没有采纳任何 A/B 开关为默认值**：全部在 4 颗种子的噪声（±0.005）内或更差。
- **`src/device/`（uavrgb_device 库）没有接入**：它依赖 uavrgb_core，trainer 在 core 里，反向依赖会成环；其 8 段固定布局也放不下文本分支。DeviceCnn 自己做了约 30 行扁平缓冲管理。
- **loss/dlogits 没搬到设备侧**：logits 只有 N×C 个数，host 算 ≈ 1 ms；剩余每步 ≈ 12 次 cudaMalloc 来自 `class_weighted_loss/grad` 与 `softmax_ce_loss_cuda` 包装，约 2 ms/步，占比 5%，没必要再动。
- **conv 前向/dx kernel 没优化**：直接卷积 ≈ 1.4 TFLOP/s，仍是每步 27 ms 的主体；要再快需要 tiling/共享内存，与 sm_75 限制和「不引入 cuBLAS/cuDNN」无冲突但超出本轮范围。
- **README 的「25/25 CTest」没改**：它是写明日期（2026-11-03）的历史记录；现在是 27 项，合并后可由文档负责人更新。
- 文本模型（text_dim>0）的真实 checkpoint 一个都没有，FiLM 常驻路径只有 `test_device_train_step` 的对拍证据（第一步 logits 逐位相同）。

## 风险与遗留

- shortcut: `DeviceCnn` 全部在默认流，读图（host pread 7.4 MB）与 GPU 计算串行，≈ 2 ms/步；若要再提速需双缓冲 + 独立流，当每步 GPU 时间降到 10 ms 以下时必须做。
- shortcut: 梯度范数的 `sumsq` 是每元素 atomicAdd 到一个 double，146k 参数 ≈ 0.14 ms/步；参数量涨 10 倍以上时必须改成 block 归约。
- shortcut: AdamW 的衰减作用于全部参数含 bias，与 PyTorch 默认一致；若采纳 AdamW 为默认值需评估是否排除 bias。
- shortcut: `--augment` 等新开关没进 resume 契约校验（只写 config.json），续训时要手动传同样的 flag；若任一开关成为默认值必须补进 `check_resume_contract`。
- 显存：batch 128 时 DeviceCnn 常驻 ≈ 0.83 GB（激活按 max_batch 预分配，不复用缓冲；conv 反向部分和工作区三层合计 ≈ 30 MB）。
- shortcut: dW 部分和工作区大小 = n × ceil(oh/16) × 权重数，c3 在 batch 128 时 19 MB；batch 1024 以上或通道数翻倍时要把行分块改成按样本分块再归约。

## 导出到 SG2002 要注意什么

- 结构全部是 NPU 友好算子：Conv3x3(pad1)+ReLU+MaxPool2 ×3 → Flatten → Gemm(19200→4)。池化尺寸 120→60→30→15、160→80→40→20 全是偶数，没有 floor/ceil 歧义。本轮没有改结构、没有改 checkpoint 格式（仍 v5），导出脚本不受影响。
- 输入契约是 **uint8 NCHW RGB，缩放 1/255**（训练与推理现在都是 uint8 进设备再 `/255`）。TPU-MLIR `model_transform.py` 用 `--mean 0,0,0 --scale 0.003921569 --pixel_format rgb`，把归一化折进模型；运行时直接喂摄像头 uint8，不要在 CPU 上再做一次 /255。
- INT8 校准集直接从 `dataset.uavr` 图像区抽 200–500 帧（已是 NCHW uint8，不必过 Python 预处理）；验收指标不是 cosine 而是 test split 上 fp32（本仓库 `uavrgb_infer`）与 INT8 bmodel 的 action 一致率与 macro_f1，`compare_infer.py` 可直接改成对比用。
- 19200→4 的 Gemm 输入动态范围大（conv3 的 ReLU 输出），per-tensor 量化容易掉精度；优先 per-channel 权重量化，必要时把 Gemm 留 BF16/FP32（MAC 只占 0.15%，不影响延迟）。
- 单帧 ≈ 52.6 MMAC，最大中间张量 c1 输出 16×120×160 = 307 KB int8，SG2002 的片上内存放得下；预计 NPU 推理 1–3 ms，瓶颈会在 ISP/VPSS 的取帧与 resize 到 160×120。
- 文本分支（FiLM：逐通道 γ/β 乘加 + embedding 查表）不是本轮交付的 vision-only 权重的一部分；若将来导出文本模型，embedding 查表与 film Linear 放 CPU，只把 γ/β 作为第二个输入喂 NPU 做 Mul/Add。
- argmax/softmax 不要放进 NPU 图：logits 4 个数在 CPU 上算，与 `infer.cpp` 现在的做法一致。
