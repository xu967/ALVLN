## 做了什么

- 新增 `sim/tools/collect.py`（纯 stdlib，导入同目录 `teacher`）：
  - `ACTION_TO_TWIST` 动作→速度指令映射（forward=+X linear x，yaw 正 z=左转）。
  - `take_off()` 升到巡航高度（z≈1.8m）。
  - 主循环每步：读深度 → `expert_action` → 发 twist → 持 hold 秒 → 抓 RGB 存 PNG + 读位姿。
  - 落盘：`rgb_%05d.png`（320×240 原图）、`actions.jsonl`（step/action_expert/action_executed/collision）、`oracle.jsonl`（step/pose）。
- 场景修正（上一版柱子在 x=1.5 太近，无人机飞到 0.94m 时柱子填满视野、专家三向都判堵死→卡 SAFE_NEUTRAL）：
  - 柱子挪到 x=3.0（给足「前进→发现→转向」的空间）。
  - `teacher.expert_action` 默认 `min_clear` 1.0→2.0m（更早转向，柱子仍落在中心带内）。

## 修的两个 bug

1. **`read_pose` KeyError**：`/model/x3/pose` 发 `gz.msgs.Pose_V`，JSON 是 `{"pose":[{position,...}]}`，不是 `msg["position"]`。改为取 `msg["pose"][0]["position"]`。
2. **专家地面误判**：深度图底边照到地面（~0.13m）会让「整列取最小」永远判「前方被挡」。改为只取中间水平带（行 [0.4h,0.6h)）。

## 没做什么（如实）

- **碰撞检测未做**：`collision` 恒为 False（代码里标 `shortcut:`）。原因：世界未加接触传感器；后续加 contact sensor 或位姿卡滞判定再补。
- **RGB 未降采样到 128×128**：存 320×240 原图。原因：128×128 属训练预处理，留给 doc 04 的预处理步骤。
- **RGB/深度/位姿未按 sim-time 精确对齐**：三次独立 `gz topic -e -n 1`，各自取最新帧，非同一 sim-time。原因：精确对齐要照 doc 03 的 `advance_until`，属后续优化。
- **episode 元数据未写**（episode_id/scene_id/seed/version 未落盘，`EpisodeMeta` 只冻结未用）。原因：先验证采集循环，元数据随「冻结 episode 文件格式」一起补。
- **单一固定场景，无随机化**：柱子/地标位置固定。原因：随机化场景生成器后续上。
- **未做 reset 复位校验、相机内参标定**：属 GZ1 验收。

## 待确认

- 专家「更空一侧」是否要加滞回，避免左右反复抖（本次轨迹没抖，但近距离可能）。
- `min_clear=2.0m` 与 hold 时长（0.5s）的取值是否合适；正式采集要按实测 RTF/帧率调。

## 风险与遗留

- 采集依赖 `DISPLAY=:20` 软件 GLX（同 E1/E2），纯 headless 会 segfault。
- `read_depth` 全帧 float32 320×240 经 JSON/base64 每步 ~0.4MB，吞吐低；正式采集量大时要换 `gz-transport` C++ 或二进制通道。
- 碰撞恒 False 会导致「撞柱仍记录成功」的假数据；在加接触传感器前，这批数据只用于验证链路，不能当正式训练集。
