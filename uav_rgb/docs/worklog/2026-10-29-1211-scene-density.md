# 场景密度提升（类别不平衡从 89.2% → 80.0% FORWARD）

- 时间：2026-10-29 12:11
- 范围：`sim/tools/scene_gen.py`、`sim/tools/collect_parallel.py`
- 结论：完成。**代码由 subagent 实现，它在验收前因 API 余额不足中断两次；本文档由主会话补做验收并撰写**

## 做了什么

把随机场景从「2–5 根稀疏柱子」改成「**8–9 根车道式蛇形排列**」：

| 参数 | 旧 | 新 |
| --- | --- | --- |
| 障碍数 | 2–5 | **8–9** |
| 障碍 x 范围 | 近组 [1.5,4.0] + 远组 [4.5,6.0] | **[1.5, 5.0]** |
| 障碍 y 范围 | (-3.0, 3.0) 均匀 | **(-1.5, 1.5)** |
| 车道间距 | 无 | **1.302 m**（柱宽 0.4 + 缝 0.902） |
| 中心车道摆动 | 无 | ±0.19 m |
| 缝隙约束 | ≥0.9 m | ≥0.9 m（不变） |
| 出生区净空 | x < 1.0 | x < 1.0（不变） |
| 门柱 | \|y\|≤0.25 一根 | \|y\|≤0.25（不变，`GATE_Y_ABS_MAX`） |

新增 `LANE_SEP` / `LANE_CENTER_ABS_MAX` / `PILLAR_COUNT_RANGE` 等模块级常量，单位写进注释。

## 验收（主会话实跑，6 实例 × 1 episode × 20 步，hold=1.0，base-seed 0）

### 类别分布（核心指标）

```
scene 0: RRFFFFFFRRFFFFFFFFFF   非F=4/20  碰撞=0
scene 1: RRFFFFRRFFFFFFFFFFFF   非F=4/20  碰撞=0
scene 2: LLFFFFLLFFFFFFFFFFFF   非F=4/20  碰撞=0
scene 3: RRRFFFFFRFFFFFFFFFFF   非F=4/20  碰撞=1
scene 4: LLFFFFLLFFFFFFFFFFFF   非F=4/20  碰撞=0
scene 5: RRFFFFRRFFFFFFFFFFFF   非F=4/20  碰撞=0

FWD=96 (80.0%)   LEFT=8 (6.7%)   RIGHT=16 (13.3%)
非 FORWARD = 20.0%    碰撞步 1/120   含碰撞 episode 1/6 (16.7%)
```

| 指标 | 目标 | 实测 | 判定 |
| --- | --- | --- | --- |
| 非 FORWARD 占比 | ≥15% | **20.0%** | ✅ |
| 含碰撞 episode | ≤20% | 16.7% | ✅ |

### 生成器自检

```
scene_gen self-check: 200/200 seeds OK, pillar count distribution {8: 107, 9: 93}
seed 0 两次生成 sha256 均为 ac307b73e9bf0629...  match=True pillars=9
scene_gen self-check: PASS（同 seed 字节级一致，障碍 8–9 根，缝隙契约全过）
gz sdf -p → OK
```

### 吞吐

6 实例 × 20 步 = 120 步，`collect=46.4 s`，端到端 **2.588 步/s**（单实例均值 0.436 步/s）。

## 没做什么

- **没有做场景结构多样性**：目前所有场景都是同一套车道网格，只是 y 偏移和左右交替不同。
  实测动作序列模式高度相似（`RR FFFF RR ...`）。真正的多样性（随机布局、不同密度）没做。
- **没有跑 12 实例验收**：只跑了 6 实例。
- **没有做 2000 条规模的压力测试**。
- 没有 subagent 报告（它两次 402 中断），负面清单由主会话按代码与实测反推。

## 待确认

- 20% 非 FORWARD 是否够训练。spec 只要求「不能全是向前」，没给下限；
  经验上 15–25% 可训练，但少数类（LEFT 6.7%）样本仍然偏少，建议靠类别权重补。
- 车道式布局让「障碍位置可预测」（固定 0.4375 m 递进），模型可能学到位置先验而非视觉特征。
  如果闭环评测发现泛化差，应改回随机布局。

## 风险与遗留

- **动作序列过于规整**：6 条 episode 都是「转 2 步 → 直飞 4 步 → 转 2 步 → 直飞」，模型可能记住节奏而非学会看画面。
  这是当前最大的数据质量隐患，需要用闭环评测验证。
- 碰撞率 1/6 是个案，样本太少不足以下结论；采 200 条后应重测。
- 障碍全部落在车道 grid 上，x 位置只有 9 个取值，空间多样性低。
- RTF 在 6 实例下实测仍为 0.97，并行未退化；但两个 agent 同时在跑 12 个实例时 RTF 会掉到 0.15–0.28，
  导致起飞超时与 `stuck` 误报碰撞——**并行采集必须串行化，不能多个任务同时占用仿真**。
