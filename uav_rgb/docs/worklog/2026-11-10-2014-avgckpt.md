## 做了什么

### 1. `tools/average_ckpt.py`（276 行）

- 命令：`python tools/average_ckpt.py --run <run 目录> --data <dataset.uavr> --out <ckpt> [--last-k 10] [--no-calibrate] [--infer-bin <uavrgb_infer>]`。
- 平均：run 里编号最大的 `ckpt_epNN.bin` 为末轮，取末 k 个；全部参数张量按 float64 累加、除以 k、转 float32；
  头、训练契约、Adam 状态沿用末轮（模型没有归一化层，没有统计量要重估）。
- 校准：真实 `uavrgb_infer` 在数据集 val 分区逐帧推理（碰撞步剔除，含义同 `src/dataset.cpp` 的 `drop_collision`），
  二分求 δ，使预测为 FORWARD_SLOW 的占比等于 val 标签里该类的占比，再 `fc.b[1] += δ`；
  对写出的成品再真实推理一遍核对占比，过了才落盘。
- 格式：只认 UAVRCK01 v6（布局对照 `src/include/uavrgb/checkpoint.hpp`、`src/checkpoint.cpp`、`src/tests/test_checkpoint_versions.cpp` 核过，文件没有校验和）。
  其他版本、长度不符、非有限值、缺文件、文件头 epoch 与文件名不符、形状不一致都报错退出，不猜。
- 不静默算错 δ：
  - ckpt 带文本条件、prev-action、双帧输入时，校准报「暂不支持」（`shortcut:` 注释写了升级条件）；
  - `--data` 的 sha256 与 ckpt 训练契约里的数据集 sha256 不同，报错；
  - `collision_flags` 缺失、长度不等于 N、含 0/1 以外字符，报错，不当成无碰撞。
- 旁文件 `<out>.json`：输入文件与 sha256、k、末轮、δ、val 帧数、校准前后（真实推理）FORWARD 占比与目标占比、推理二进制 sha256、数据集 sha256、输出 sha256。
  `<out>` 或 `<out>.json` 已存在时拒绝覆盖。
- 依赖只有 numpy 与标准库；数据集用 `tools/DATASET_FORMAT.md` 的布局自己读，不 import `select_ckpt`（它经 `student` 拉进 PIL 与 teacher）。

  缺文件报错；形状不一致报错；文件头 epoch 与文件名不符报错；非 v6、截断、尾部多余字节报错；拒绝覆盖。

  碰撞标志缺失或格式错、文本/prev-action/双帧、`--data` 缺失、数据集 sha256 不符，各自报错。

## 没做什么

- 没接流水线。原因：本轮任务书明确只写接入点。接入点见 `reports/avgckpt.md` 的「流水线接入」一节。
- 没支持文本条件、prev-action、双帧 ckpt 的校准。原因：行协议要逐集 `--text`、读 `dataset.aux` 的 prev 索引，
  本轮没有这类 ckpt 要用；遇到时报「暂不支持」，加了 `shortcut:` 注释。
- 没支持 v2..v5 ckpt。原因：当前训练器只写 v6；`shortcut:` 注释写了要照 `checkpoint.cpp` 逐版本补。
- 没给推理子进程加读超时。原因：接流水线时由外层守护脚本兜；`shortcut:` 注释已记。
- 没把末轮与 `config.json` 的 epochs 对账。原因：续训时 epochs 的含义不同；被中途杀掉的 run 会平均到不完整窗口，接流水线时靠训练的 done 标记保证。
- 没改 `progress.md`。原因：任务书没要求；本阶段多个分支并行，各自改同一个文件会在合并时冲突（推断，未核实其他分支是否在改它），
  这一轮的进度以本文件和 `reports/avgckpt.md` 为准，由主会话汇总进 `progress.md`。
- 没跑 C++/CUDA 构建、CTest。原因：本次没改 C++；`check.sh --python-only` 的「未检查」清单里有这些项。
