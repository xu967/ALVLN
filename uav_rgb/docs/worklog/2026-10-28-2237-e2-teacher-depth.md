# E2：专家策略（TeacherPlanner）+ 特权深度相机 + 障碍

- 时间：2026-10-28 22:37
- 范围：`sim/tools/teacher.py`、`sim/worlds/uav_rgb.sdf`
- 结论：完成（专家策略自测通过；深度相机实测出帧；障碍已入世界）

## 做了什么

- 新增 `sim/tools/teacher.py`：`expert_action(depth, w, h, min_clear=1.0)` 专家避障策略。
  - 把深度图分左/中/右三条竖带，只在**中间水平带**（行 [0.4h,0.6h)，对应无人机正前方飞行走廊）取各带最小深度。
  - 前方空 → FORWARD_SLOW；前方挡 → 朝更空一侧 YAW；三面堵死 → SAFE_NEUTRAL。动作枚举与 `src/include/uavrgb/action.hpp` 对齐。
- `sim/worlds/uav_rgb.sdf` 增加：
  - 两根落地高柱（0.4×0.4×3，z∈[0,3]）：`pillar_center`(1.5,0)、`pillar_right`(1.5,1.4) —— 中/右堵、左开，逼专家 YAW_LEFT。
  - 深度相机 `depth_camera`（`/uav/depth`，320×240 R_FLOAT32，与 RGB 同 pose/FOV/分辨率对齐，far=20m）。
- 实测深度相机出帧（见「验证到哪一步」）。

## 为什么中间带（关键修 bug）

深度相机照到**底边地面**（无人机近地时地面深度 ~0.13m）。若对整列取最小深度，专家会
把「地面」当成「前方障碍」，永远误判被挡。故只在正前方水平带取深度，排除地面与天空。

## 没做什么

- 没写采集器（E3：驱动四旋翼 + 录 RGB/深度/专家动作/位姿 + 写 episode）。
  - 原因：本步只做「专家 + 特权深度 + 障碍」；采集器是下一步。
- 没做相机内参标定（fx/fy/cx/cy 仍为 null）。
  - 原因：属 GZ1 验收项，数据协议里保留 null 直到真正标定。
- 没做随机化场景生成（seed 随机布障碍）。
  - 原因：先固定世界验证整条链路，随机化生成器后续再上。
- 没把深度帧存成 evidence png（R_FLOAT32 不是常规图片）。
  - 原因：已用解码脚本打印真实数值验证，无需存图。

## 待确认

- 专家策略用「中间带取最小深度 + min_clear=1.0m」的阈值是否合适；转弯方向取「更空一侧」是否要加滞回（避免左右反复抖）。
- 障碍布局（中/右堵、左开）是否足够；正式数据要按 seed 随机化，这一步是固定世界。

## 风险与遗留

- 深度相机与 RGB 都靠 `DISPLAY=:20` 软件 GLX 渲染；纯 headless 仍会 segfault（同 E1）。
- 无人机起飞前近地时，中间带底部仍可能扫到地面（~0.6m），瞬时可能误判；采集前应先让无人机升到巡航高度再跑专家。
- R_FLOAT32 的「无命中」是 inf，采集器写入 oracle 时要处理 inf（转成约定值或跳过）。
