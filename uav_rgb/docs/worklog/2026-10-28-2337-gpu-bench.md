## 没做什么

- **没有实现优化版 conv kernel / device-resident 管线**：任务只要求说明偏差并给估算；重写 kernel 会引入新实现与正确性对拍，超出本次范围。`opt` / `kernel-only` 已明确标为估算（kernel 时间本身是 nsys 实测，拷贝分量为单独实测）。
- **没有测 Linear / Softmax**：本次任务只要求 Conv2d。
- **只测 FP32、3×3、pad=1、stride=1、128×128**：未测 FP16/Tensor Core、1×1/5×5、stride>1、224×224 等；原因：超出本次范围，且 22 GiB/batch 结论已给出缩放公式。
- **没有用 ncu**：`ERR_NVGPUCTRPERM`，需要系统改权限；未获授权，不静默改系统配置。
- **没有把模型/训练全流程跑起来**：只测单层 Conv2d fwd/bwd；未含 loss/optimizer/数据加载。
- **没有实测 22 GiB 极限 batch**：显存上限为解析计算（按设备缓冲/激活字节数），未真的分配 ~20 GiB 去触发 OOM；原因：会把并行 agent 共用的卡推到极限，风险大于收益。
- **没有多轮统计显著性**：只跑了 2 次完整基准 + 1 次 nsys；host 侧抖动已量化（小层最大约 20%），未做更多轮次。
- **没有改 `src/` 的任何文件、没有重建 `src/build`**：遵循并行工作约束，直接链接已有静态库。

## 结论：22 GiB 下建议的 batch size 和模型规模

- **batch**：128×128 输入、3–5 层小 CNN → **128–256**。显存能到约 1200（整网训练每样本 ≈17.4 MiB），但时间随 batch 线性增长、吞吐平坦，再大没有收益。256×256 → **64–128**（显存上限约 303）。推理 batch 256 激活约 1.84 GiB，显存允许约 2900–3500，但实时性依赖 device-resident 管线。
- **模型规模**：22 GiB 对 128×128 的 ≤128 通道小 CNN 非常宽裕；按 `max_batch ≈ 20.6 GiB / (2.4 × A)`（A=Σ C_out·H·W·4 B/样本），A=7.2 MiB→~1200，A=29 MiB（256²）→~300，A=72 MiB（约 10× 本网络）→~120，A=230 MiB→~38。真正限制是算力（前向 0.76–0.95 TFLOP/s、反向 0.16–0.29 TFLOP/s），不是显存。

## 风险与遗留

- **数字归属**：§3 原始吞吐是“parity 包装 + 本机共享环境”的真实值，不是 GPU 算力上限；换实现/换主机不可直接横比。host `Tensor::zeros` 在本机只有约 1.6 GB/s（page-fault 主导），是包装最大的单项开销之一。
- **并行干扰**：与多个 agent 共用同一张卡和 CPU；两次完整运行 host 侧小层差异最多约 20%。表格采用内部一致的 run2，run1 用于交叉检查；GPU 峰值利用率两次为 98% / 85%（采样窗口对齐差异）。
- **估算误差**：程序内“总时间 − 各分量”的逐格估算在 kernel 占比小的格子里会为 0 或非物理值（stdout 可见），不要引用；RESULTS.md §4 的 kernel 时间用 nsys 实测替代，`opt`/`kernel-only` 仍是估算（拷贝分量用预分配缓冲的最小值，实际优化实现受 tiling/L2/occupancy 影响）。
- **显存上限**是解析值，未真实拉到 OOM；未计显存碎片、CUDA context 增长、驱动保留（cudaMemGetInfo total 22001 vs nvidia-smi 22528 MiB）。
- **依赖预构建静态库**：`src/build/libuavrgb_core.a` 若被其他 agent 重建/改动，本基准需重跑才能对应当前源码。
- 一次性脚本/临时文件已清理（`/tmp` 下的 microbench、nsys trace）；仓库内只保留 `experiments/gpu_bench/` 与本 worklog（另有一份 `docs/worklog/` 文档）。
