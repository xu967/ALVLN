## 做了什么

1. 许可核实：Mip-NeRF 360 项目页（jonbarron.info/mipnerf360）无许可文字，只有 360_v2.zip（12.5 GB）/ 360_extra_scenes.zip 链接；CC-BY 4.0 出自同一作者组 SMERF 页面的声明。Inria 预训练包 `models.zip`（14.66 GB）无单场景链接（目录 403），模型没有单独许可声明，gaussian-splatting 软件是非商业研究许可。结论写进两份 scene.json 的 `license`：仅研究用途，署名 Barron 2022 + Kerbl 2023。
2. 取数：服务器支持 HTTP Range → `remote_zip.py`（可 seek 的 HTTP 文件对象 + `zipfile`）只读 zip 中央目录再抽成员，不下整包；守护进程抽了 garden / bicycle / stump 三个 30k PLY（1.45 / 1.52 / 1.23 GB，合计 4.2 GB < 10 GB 预算）+ cameras.json / cfg_args / input.ply，sha256 `.ok` 标记。本地 `kitchen/kitchen.ply`、`bicycle/bicycle.ply` 识别为 HF 7k mini，没用。
3. 尺度 / 重力 / 地面（通用方法，`probe_align.py` + `build_scene.py`）：COLMAP 稀疏点 RANSAC 地面法线（与相机 down 均值、轨道平面法线夹角 < 2°；Mip-NeRF 360 世界系相对 −y 斜 garden 29° / bicycle 14° / stump 47°，`bicycle_v2.json` 的 `--up=-y` 翻转会让地面斜着）；已知尺寸物体的水平面峰定尺度（garden 桌面 0.75 m ↔ 1.351 单位 → 0.5550 m/单位；bicycle 长椅座 0.45 m ↔ 0.480 单位 → 0.9367 m/单位，靠背 0.89 m 自洽）；尺度烘进 PLY（`ply_scale.py`：xyz×s、log-scale+ln s、球谐原样），旋转平移进 `nav_to_world`（刚体），nav 原点 = 轨道中心投到地面，`ground_z=0`。
4. 高度验证（Callinstrasse P0 教训）：俯视 −89° 中心深度在 nav z=1/2/3 处给出地面高 0.00–0.10 m（两场景 6 个点全部）；平视底行深度与平地几何 h/tan(VFOV/2) 相差 < 7%（bicycle 三个点、garden 开阔点）；高度阶梯图 z=1/2/3 肉眼可辨；训练相机位姿复现图像手持高度；占据切片 z∈[1.8,2.2] 只剩树（garden 树 (2.3..4.7, −1.5..2.5)；bicycle 树丛 (4..7, −2.5..1.5)），桌子 / 长椅 / 花盆都在飞行高度之下。
5. `tools/scene_probe_quality.py`（新）：沿 A* 路径每 0.5 m 渲染机载帧（航向 = 前视 0.7 m 路径点，与教师纯追踪一致），每帧 lapvar / hole_frac / low（判定函数与阈值直接 import `collect_3dgs.frame_quality / FRAME_LAPVAR_MIN`，不另写一份），路线级 low_frac 门槛 10%；产物 `routes_quality.json`（schema `uavrgb.3dgs_routes_quality.v1`）+ 关键帧拼图 + 高度阶梯图；`--candidate name:x,y,yaw,wx,wy[,z]` 探还没写进 scene.json 的候选；`--self-check` mock 渲染器 + 合成走廊；配置区在顶部。`tools/test_scene_probe_quality.py` 10 个用例（阈值同对象、采样间距 / 航向 / 拐角、low_frac 门槛边界、候选解析、拼图尺寸、自检子进程）全过。
6. 路线：每场景 6 条（8–12.5 m，含直线 / 绕树 / 大转向），planner 校验全部 feasible / clear_ok，探测 0 低质帧，拼图逐条人看。淘汰：garden 出生点在墙里的 2 条、终点贴东墙漂浮碎片的 1 条；bicycle 终点朝东南树丛（雾墙但 lapvar >1000）的 2 条。`max_steps` = `route_check` 预算；routes[0] 同步到顶层 spawn/waypoint。
7. 冒烟：`collect_3dgs --policy astar --dynamics cf_sitl --episodes 2 --hold 0.5 --stop-on-collision`，每路线 2 集 + `sim.3dgs.video` 三视角：24 集 0 碰撞、23/24 到达、goal-stop 23、低质帧 0、飞行高度 1.97–2.04 m；明细在两份 experiments 文档 §6 和报告 §4，产物 `3dgs-smoke-20261107/`（679 MB）。

## 没做什么（及原因）

- `sim/3dgs/*` 没改（只读域）。建议项写在报告：`splat_to_ply.py` 加 `--scale` / 吸收 `ply_scale.py`；`collect_3dgs.frame_quality` 的 lapvar 抓不到漂浮碎片（高频噪声 lapvar 反而高），需要第二个指标（如深度方差 / 与邻帧一致性）。
- stump 只做了对齐（align_stump.json，相机高 1.5 m 低置信，无已知尺寸物体），没建 scene.json，没路线。kitchen / room 没碰。
- 没下载 Mip-NeRF 360 原始照片，训练相机复现只看「像不像手持照片」。
- 尺度只靠一个参照（garden 桌面；bicycle 长椅 + 靠背自洽），误差 ±4%，没有第二类物体交叉。
- 飞行高度维持 2.0 m；1 m 版本（桌子 / 长椅成障碍）没试。
- cf_sitl 二进制 06:59:55 被主仓 2b479cc 重编（新参数 `tilt_int_max_deg`），worktree 的 `e1_mini.json` 是老版本，冒烟改用 `--dynamics-params` 只读借主仓的参数文件；worktree 的 `dynamics.py` 没有 2b479cc 的「窗口末刻半步余量」，所以每个 0.5 s 窗口末刻执行器会回 SAFE 一个 tick（trace 里 action=-1），不影响步级结果但 trace 与主仓口径有差。第一次冒烟（老二进制）跑完 garden r0/r1 后失败，产物留在 `3dgs-smoke-20261107-attempt1-oldbinary/`。
- 旧 bicycle 变体（`bicycle*.ply` 7k、`bicycle_v2.json` 等，0.7 GB）没删。

## 风险与遗留

- 外围（离轨道 >4 m）发糊 / 漂浮碎片是 Mip-NeRF 360 的固有限制，路线只能在中心 ±6 m 内；更长路线需要别的场景。
- 占据代理 v2 只看 opacity ≥ 0.3 的椭球，细枝 / 伞沿可能漏；v3 真值源（Wanderland 那套）这里没有 LiDAR 可用。
- cf_sitl 二进制和参数文件由别的 agent 维护，再被重编时冒烟脚本可能再次失配。
