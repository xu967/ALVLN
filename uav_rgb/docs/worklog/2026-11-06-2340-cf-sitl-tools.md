## 做了什么

- `sim/cf_sitl/proc/cf_sitl_proc.cpp`（195 行）：BRIEF §4 协议进程。`--params <json> [--seed N]` 启动即 `cf_sitl_init`；每行一个 JSON 请求、一行应答、立即 flush；`reset / takeoff / act / step / state / quit` 六条命令，任何坏输入（非 JSON、空行、缺 cmd、未知 cmd、字段类型/范围错）都应答 `{"ok":false,"error":"…"}` 且进程不退出；`quit` 或 stdin EOF 退出 0。`state` 输出 `cf_sitl_state` 全部字段（含后加的 `sticks[4]`，用模板探测成员，旧头文件也能编）。进程启动后把 fd 1 改道到 stderr，应答只走 dup 出来的描述符，固件/库里任何杂散输出进不了协议流。
- `sim/cf_sitl/proc/CMakeLists.txt`：`cf_sitl_proc` 链接 target `cf_sitl`；json_min 另编一份静态库 `cf_sitl_tools_json`（库用 `-fvisibility=hidden` 不导出 Json 符号），`if(NOT TARGET)` 守护，三个子目录谁先进都行；可执行文件放构建根目录。
- `sim/cf_sitl/proc/README.md`：协议表、state 字段、Python 调用示例、测试说明。
- `sim/cf_sitl/selftest/`：`cf_sitl_selftest --params … --out <dir> [--seed N]`，退出码 = 失败数，同时写 `<out>/selftest.txt` 与各场景 CSV。
  - `selftest_config.h`：全部超参数（时长、注入量、阈值），每行一个、行尾写依据。
  - `selftest_util.h`：报告（stdout + TXT）、CSV、四元数几何、逐字段 FNV 哈希、`takeoff_until_ready`。
  - `scenario_frame.cpp`：外部模式注入世界系 ω/acc，自积分真值四元数与固件 `att_est` 比较。陀螺链绕 x/y/z 各转 0.5 rad/s × 1 s（转动时注入 1.5 m/s² 竖直加速度让固件 `landed=false`，否则 imu.ino 的落地零偏校准会把转速吸进零偏）；加计链静止倾斜 10°（roll、pitch）看 estimate.ino 的加计修正把估计拉到真值。
  - `scenario_hover.cpp`：READY 后 10 s 倾角 RMS、高度误差 RMS、水平漂移。
  - `scenario_actuator.cpp`：一集顺序跑 arm_takeoff → 高度保持 2 s → FORWARD 3 s → SAFE 停住 → YAW_LEFT 3 s → SAFE 10 s；速度/偏航角速度由真值 pos/quat/vel 导出（状态结构体没有 ω，偏航角速度用解缠偏航 0.1 s 差分）。
  - `scenario_determinism.cpp`：同脚本 10 s 在本进程 + 两个子进程（本程序 `--hash-run`）各跑一遍，三哈希逐位比较。
  - `scenario_battery.cpp`：起始 SoC 由参数文件 `sim.value.battery_soc_init`（0.5）决定，自检写一份改成 1.0 的副本到 `--out` 再 `cf_sitl_init`，结束后恢复；悬停到固件 L3（fw_mode=AUTO）/落地/600 s，记录 V_bus、悬停油门杆、油门杆、电机均值、高度、fw_mode、exec_state。

  - `CMakeLists.txt`：target `cf_sitl_selftest`，放构建根目录。

## 没做什么

- 固件级打杆阶跃（俯仰 +0.5 → 15°、偏航 +0.5 → 150°/s）：自检里标 SKIP。
  - 原因：要绕过执行器直接写固件杆量，冻结接口没有入口；已向 SITL-core 提请求（见「待确认」）。
- 坐标系场景没有直接比对固件 gyro/acc 数值（任务原文「固件 gyro/acc 读回一致」）。
  - 原因：`cf_sitl_state` 不含固件 gyro/acc；改为比固件估计姿态与注入真值（轴错/符号错时误差 ≥ 57°，实测 < 0.9°），判据等价但间接。
- 电池场景没有真正「到 SoC 0.3 为止」。
  - 原因：SoC 不在接口里，不可观测；改为跑到固件 L3/落地/600 s，并记录 V_bus 首次过 3.5 V / 3.0 V 的时刻。固件 L1 在悬停中只阻止解锁/怠速上锁，没法在飞行中观察到；要测 L1 需要能设起始 SoC 后解锁。
- 执行器单元测试（HANDOVER 分工里列了「理想传感器序列 → 杆量符号与限幅；ToF 失效 → FAILSAFE」）。
  - 原因：用户本次任务清单没有这项；且 `exec/executor.c` 只编进 `libcf_sitl.so` 并被 `-fvisibility=hidden` 藏住，测试要直接再编一遍 core 的源文件，等 core 确认后再加。
- 没在桩库上跑 CTest 全集。
  - 原因：写测试时真库已经出现，直接用真库；桩库只验证了 proc 协议往返与 proc 的编译链接。
- 完整 `tools/check.sh` 用现成的 `baseline-20261106/build-check` 跑失败（`CMake Error: The source … does not match the source … wt-baseline-20261106 … used to generate cache`）。
  - 原因：那个缓存是从 git worktree 生成的，与工作树路径不同，与本次改动无关；改用独立构建目录重跑，结果见下表。
- 没改 `src/`、`exec/`、顶层 `CMakeLists.txt`、`sim/dynamics/e1_mini.json`、`gz/`、CF-Drone；没 git commit。

## 风险与遗留

- 自检阈值是对「假定参数」的合理性判据，不是真机验收标准；`calibrated=false`。
- `scenario_battery` 用改过 `battery_soc_init` 的参数副本重新 `cf_sitl_init`，之后再用原文件 init 恢复；自检里电池是最后一个场景，顺序改了要留意。
- `test_external_vs_standalone` 把 `plant.h` 的积分方程抄了一份（必须同一套才能逐位一致）；core 改积分器时这项会先红，届时同步。
- `cf_sitl_state` 再追加字段时要同步 `proc/cf_sitl_proc.cpp` 的 `state_json()` 与 `selftest_util.h` / `tests/test_reset_determinism.cpp` 的哈希字段列表（哈希少喂字段不会误报，只是覆盖面小）。
- 数据盘临时产物（保留）：`/root/rivermind-data/uav_rgb/tmp/agent-sitl-tools/{PROGRESS.md, stub-build/, selftest-run1/, check-run/, build-check/}`、`/root/rivermind-data/uav_rgb/tmp/build-cf-sitl-tools/{real, check-cf-sitl}`；已删除：`build-cf-sitl-tools/stub/`（桩库构建树）。
