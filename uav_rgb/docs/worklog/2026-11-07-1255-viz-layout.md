## 做了什么

1. **一份版式代码**：`sim/tools/view_layout.py`，纯函数、cv2 当参数传入（测试能注入假 cv2 记录画了什么）。常量 `W/H=1280×720`、`CW/CH=640×360`、`CELL_TL/TR/BL/BR`、`ACTIONS/ACTION_BGR`；`paste`（等比缩放居中、原生尺寸不重采样、标签 + 角标）、`panel`（文字行 / 动作框 / 标志行 / 结果 / 动作时间条，单位由调用方决定）、`onboard_label`。`record_views.py` 删掉自己的 `_paste`、`ACTIONS`、`onboard_label`，`_panel` 保留原签名只做「本集数据 → 几行字 + 动作段」的适配。
2. **Gazebo 行为不变**：`test_record_views.py` 未改一字，PASS。另外用真机一集做了无损对比（见验证表 #5）：面板逐像素相同，三个画面格的差异全部落在标签 / 角标文字带内，是新加的 1 px 黑描边（为了 3DGS 的亮背景也能读字；cv2 5.0 的 putText 走内置 TTF、thickness 是字重，描边只能用 8 方向偏 1 px 的黑字垫底）。
3. **3DGS 接入**：`sim/3dgs/video.py` 输出 1280×720 同一网格；FOLLOW 640×360 原生渲染（`_render` 任意分辨率）；TOP 640×360、朝向改成和 Gazebo 一致（图右 = +x、图上 = +y），1 m 网格、比例尺、图例、到达圈 / 终点 / 出生点、航向三角；ONBOARD 仍 320×240（模型输入不变）由 `paste` 放大到 480×360 居中；面板行：标题、`route i name  step k/n`、`sim t (video +x s)`、pos、speed/yaw/roll/pitch，碰撞标志，末尾定格 1.5 s 写 `SUCCESS reached` / `COLLISION` / `ANOMALY kind` / `NOT REACHED`。CLI 加 `--out-name`（默认仍 `views.webm`，`demo_3dgs_routes.py` 等旧调用方不受影响）和 `--allow-scene-mismatch`（manifest 的 `scene_json_sha256` 与传入 scene.json 不一致就退出）；关键帧名跟随输出名（`views_1280_key_NN.png`），不覆盖旧 `views_key_*`。
4. **批量重合成 48 集**（`batch/run_batch.sh`，2 条链 2 个 GPU 进程）：Callinstrasse v3-fov60 12、Wanderland smoke 12、garden 12、bicycle 12，全部 rc=0，每集多出 `views_1280.webm` + 4 张 `views_1280_key_0{0..3}.png`。
5. **`tools/make_demo_reel.py` v1**：章节制配置 `SECTIONS`（章节卡两行 + 每段 `(路径, (start_s, end_s), 中, 英, (代表帧秒, 文件名)|None)`，负 start 从片尾倒数，每段 ≤ 20 s 超了报错），`fit_frame` 对 1280×720 恒等（统一版式素材逐像素进片），中英两行字幕叠在左下 ONBOARD 格底部 64 px（不遮右下面板的动作时间条），结尾 `table_card` 四组对照表 + 口径两行，`fit_font` 长标题缩字不裁字（第一版结尾表标题 34 px 两侧被裁，自检加了左右 20 px 底色断言），`<OUT>_manifest.json` 记每段来源 / 起止秒 / 在片内位置，代表帧 PNG 导出。`--self-check` 合成 960×276 与 1280×720（22 s）两段素材验证恒等、字幕区、截取（含 >20 s 报错）、帧数与代表帧。
6. **成片**：`$DATA/uav_rgb/demo-e1-20261107/reel/demo_reel_v1.mp4`，239.0 s（3:59），2390 帧，22 段；第一版 3DGS 每段 9 s 总长 255 s 超了 BRIEF 的 3–4 min，改成每段 8 s。代表帧 10 张 `reel/stills_v1/`。
