# 数据生成思路审核 + 代码方向审核

- 时间：2026-11-01 00:50–01:40
- 范围：L1 v2 500 集（`l1-stop-500-173307`）、`sim/tools/` 生成链路、`docs/EVAL_STANDARD.md`
- 结论：**数据内部自洽（audit 18/18 是真 PASS），但任务信号只占 22%、
  34% 的帧是纯色废帧、test 与 train 视觉上不可分**。问题不在"采得不够多"，
  在"采集前没有定义什么叫一份有效数据"。修复不需要重采。

## 做了什么

### 一、别人的数据集怎么生成

调研 2026-11-01，来源为 arXiv / 官方仓库，未核实处已标注。

| 数据集 | 平台/场景 | 规模 | 指令从哪来 | 轨迹从哪来 |
| --- | --- | --- | --- | --- |
| AerialVLN（2308.06735） | UE4+AirSim，25 场景 | 8,446 轨迹 / 25,338 指令 | AMT 看飞行视频写，3 人/条+复核 | **持证飞手先手飞** |
| TravelUAV（2410.07087） | AirSim，22 场景 | 12,149 轨迹 | GPT-4 看 5 视图写描述 + 专家删幻觉 | 人按描述飞，DAgger 补 |
| CityNav（2406.14240） | 真实点云，34 场景 | 32,637 轨迹 | 人工目标描述（CityRefer） | MTurk 按描述飞，有资格考+重采 |
| AirNav（nopride03/AirNav） | 真实航拍 | 137K 样本 | GPT-4o 读轨迹+地图+节点，10 persona+迭代 QC | 先合成动作序列 |

对我们的五条结论：

1. **目标在出生时看不见，指令带地标/空间关系。** 我们的目标从第 0 帧就在画面里，
   指令只有"颜色"两个选择（1 bit）。视觉能替代语言时，模型忽略文本是**最优解**，
   不是 bug。CAST（2508.13446）专门用同观测生成反事实指令来证明这点。
2. **轨迹是人飞的，天然含绕行、犹豫、恢复。** CityNav 同一模型：最短路径训练
   SR **2.37**，人轨迹训练 SR **4.92**（2406.14240 Table 3）。我们用的是纯 A* 最优轨迹。
   TravelUAV 明确用 DAgger + 碰撞回退补恢复样本（1011.0686）。
3. **规模按"场景数"算，不按"集数"算。** 最小官方变体 AerialVLN-S 也有 17 场景 /
   3,916 轨迹；我们 1 个场景 500 条。BabyAI/gSCAN（1810.08272、2003.05161）
   这种受控合成任务可以很小，但它们定位是诊断，不是 benchmark。
4. **反事实配对是验证"语言真的被用"的标准做法**（Parvaneh NeurIPS 2020；
   CAST 2508.13446）。这一点我们已经补上了（`make_counterfactual.py`），
   但样本被 78% 无关数据稀释。
5. **评测要 scene-disjoint unseen + SR/OSR/NE/SPL + 人基线。** 我们 49 个 test 任务，
   p=0.5 时 95% CI 约 **±14 pp**，而且和 train 同分布（见 F2）。
   另外 BC 有 copycat / causal confusion 两个已知坑（2010.14876、1905.11979）：
   **"保持/中性"动作最容易被复制**——我们的 SAFE_NEUTRAL 正是这一类，
   而 34% 的帧是冻结姿态的 SAFE。

三个最关键的结构差异：**信息结构**（目标可见 + 1 bit vs 目标不可见 + 地标关系）、
**轨迹分布**（单一 A* 最优 vs 人飞含恢复）、**规模与切分**（1 场景同分布 vs 17–34 场景 unseen）。

### 二、我们的数据到底哪里坏了（实测，不是推测）

完整数据见 [`docs/experiments/2026-11-01-l1-v2-data-forensics.md`](../experiments/2026-11-01-l1-v2-data-forensics.md)。
六条实测结论：

| # | 发现 | 数字 |
| --- | --- | --- |
| F1 | 整集纯色图（相机贴着柱面 0.1 m 拍） | 90/498 集 = **3600/10442 帧（34.5%）**，标签 100% 是 SAFE |
| F2 | test 帧到最近 train 帧的距离 ≈ train 内部最近邻 | 0.019 vs 0.021；同集相邻帧 0.147 |
| F3 | 10442 步只在世界前 3.4 m | x ∈ [−0.5, **2.89**]，世界到 5.0；\|yaw\| ≤ 62° |
| F4 | 换目标色会改标签的步只有 | **2274 / 10442（21.8%）** |
| F5 | audit 18 项全是内部自洽，无一检查图像内容/覆盖/语言信号 | F1–F4 在 18/18 PASS 下存在 |
| F6 | test 里纯色集 | 5/49 集 = 200/973 帧（20.6%）白送分 |

F1 的根因是一行代码级的：`scene_gen.make_spawn(mode="safe")` 把机体放在柱心
0.5 m 处，SDF 里相机是 `<pose>0.2 0 0</pose>`（机头前 0.2 m），于是**相机离柱面
只有 0.10–0.125 m**，柱子填满 60° 视场。`_spawn_collides` 只查机身和桨盘，不查相机。
这 100 个"safe 出生集"每个都是同一姿态静止 40 步，除了刷 SAFE 样本没有任何信息。

### 三、生成思路的四个结构性错误

**E1　先采数据，再定义"什么算有效数据"。**
v1 400 集报废是因为 teacher 0/400 到 goal；v2 500 集 34% 是纯色帧。
两次都是"采完才发现口径不对"。audit 只验证了**内部一致**（时间、标签复算、
碰撞、版本），没有验证**这份数据能不能教会任务**。18/18 PASS 是真的，
但它回答的是错的问题。

**E2　随机化加错了轴。**
场景生成随机的只有柱子的 y（±0.2 m）和左右车道翻转；真正决定任务难度的
三个轴——**出生位姿（x/y/yaw/z）、目标距离、指令结构**——全是固定的。
结果：498 个"场景"在像素上几乎是同一张图（F2），test 切了等于没切。

**E3　标签和像素绑死在一起采。**
每次任务口径变化都要重采 3 小时。但 `make_counterfactual.py` 已经证明：
**只要存了 `pose_before/yaw_before`，任何新任务都能用 teacher 在分钟级重标注**。
该采的是"覆盖"，不是"任务"；标签是可再生的，像素才是贵的。

**E4　只采 teacher 的最优轨迹。**
398 个 astar 集全是"从出生点沿最优路径到目标"，没有任何偏离/恢复状态。
闭环里 student 一偏就进了没见过的分布（这正是 DAgger 要解决的问题）。
我们的 8-seed 闭环 2 次失败（final_wp 1.74/1.99 m）就是这个。

### 四、代码方向审核

1. **过去 48 小时的改动 80% 在模型层（mean-pool → 位置拼接 → 文本列放大 → FiLM），
   但所有证据都指向数据层。** 方向应该反过来：先修数据构成，再谈结构。
2. **FiLM 的表达力够用**：c3 是 64×15×20，flatten 进 fc（19200→4），fc 能看到
   空间位置，γ/β 能按通道选颜色。文本进不了决策不是"表示能力上限"，
   是 78% 的样本不需要文本 + 图像分支已饱和。**先别加 attention/GRU。**
3. **基线只有一半。** 离线多数类先验有（`tools/baseline_priors.py`），
   但**闭环的两个基线都没有**：盲前进和**颜色 oracle**（用真值颜色从图里挑
   目标柱 → 动作）。没有颜色 oracle，说不清 CNN 到底比"按颜色阈值"多做了什么。
4. **闭环样本量不够做消融。** 8 个 seed 的 SR 0.75，95% 置信区间约 ±30 pp；
   要判 L/I/S 的 10 pp 差异，至少 40–50 个任务 × 3 模式。
5. **audit 是正确方向，但度量错了对象。** 补四项就能覆盖已知的全部坑
   （见下）。
6. **`sim/tools` 的一次性脚本在膨胀**（`make_counterfactual` / `make_decisive` /
   `probe_text_effect`），三者本质是同一件事：**从已记录位姿重标注**。
   应合并成一个 `relabel.py`——这同时就是 E3 的基础设施。

### 五、建议（按性价比排序，前三条都不需要重采）

**立刻（今天）**
1. 丢掉 90 个纯色集：498 → **408 集 / 6842 步**，SAFE 从 49.7% 降到 23.3%
   （与 pilot 的 21.5% 吻合）。重新 preprocess + 重训一版，看离线与决定性帧。
2. `make_spawn(mode="safe")` 加最小观察距离（相机到柱面 ≥ 0.8 m）。
3. audit 增四项门禁：
   - `frame_not_uniform`（整帧灰度 std < 1e-3 直接 FAIL）——今天就加；
   - `decisive_share`（换色改标签的步 ≥ 20%）；
   - `pose_coverage`（x/y/yaw 覆盖阈值）；
   - `split_near_duplicate`（test→train 最近邻不得显著小于 train 内部最近邻）。

**本周**
4. 语言门槛从 `flip` 改成 `follow`（同一帧两种文本都要对），只在决定性帧上报。
5. 补两个基线：颜色 oracle + 盲前进，闭环跑 49 个 test 任务。
6. 若净化后 `follow` 仍 < 0.5，再加 match/mismatch 辅助头（数据现成：
   `ds-cf` 每张图都有两种指令）。

**下一步唯一值得采的一轮（覆盖，不是任务）**
7. 出生位姿随机化：x/y/yaw/z 全随机，目标柱随机；标签**事后**用 teacher 重标注。
   目标：x 覆盖到 4.5 m，\|yaw\| 到 ±90°，每个状态附近都要有"可停"和"可飞"两种监督。

## 没做什么

- 没改 `scene_gen.py` / `audit_dataset.py`：本轮只审核 + 取证，修复未排期执行。
- 没重采：全部结论基于现有 498 集。
- 没重训净化后的模型：`run-film-dec-ft` 仍在跑，用的是含 90 个纯色集的 `ds-cf`。
- 没跑 L/I/S 闭环：语言门槛还没过，现在跑只会得到噪声。
- 没验证"去掉纯色集后 test 指标掉多少"：需要重建数据集后跑 eval-only。
- 没做 teacher 标签的独立复核：`label_recompute` 用的是同一个 teacher 实现，
  属于循环验证；要真正复核需要第二套实现或人工抽查（本轮未做）。

## 风险与遗留

- `run-film-dec-ft` 的训练集含 34% 纯色帧，结果会低估干净数据上的表现。
- 现有 `test macro_f1 0.8595 / acc 0.9106` 包含 20.6% 白送分，不能作为对外数字。
- 单场景数据的结论不能外推到"泛化"，只能说明"拟合"。
- F2 的相似度用的是 32×32 灰度 RMSE，对颜色不敏感；彩色维度未单独验证。
