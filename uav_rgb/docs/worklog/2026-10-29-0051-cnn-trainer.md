## 1. 做了什么

### 1.1 模型 `src/include/uavrgb/model.hpp` + `src/model.cpp`

```
Conv(3→16,3×3,pad1) → ReLU → MaxPool2   # 120×160 → 60×80
Conv(16→32,3×3,pad1) → ReLU → MaxPool2  # 60×80  → 30×40
Conv(32→64,3×3,pad1) → ReLU → MaxPool2  # 30×40  → 15×20
Flatten(64·15·20=19200) → Linear(19200→4)
```

- `struct CnnModel { Conv2d c1,c2,c3; Linear fc; int in_h, in_w; }`，`make_cnn(in_h,in_w,seed,num_classes)`
  用 Xavier-uniform 初始化 W、b 置零（seed 固定即可复现，自检靠这一点拿到「训练前」参数）。
- **参数量 100388**（c1 448 + c2 4640 + c3 18496 + fc 76804）< 1M。
- 输入 H/W 不写死：Flatten 维度按 `64·(H/8)·(W/8)` 算，因此 128×128 数据集也能跑（H/W 必须能被 8 整除）。
- `forward(m,x,&cache)` 保存反向所需激活（x、每层 ReLU 前后、pool 的 argmax、flatten），
  `forward(m,x)` 不存（评估用，省内存）；`backward(m,cache,dlogits)` 逐层反传 fc → pool3 → relu3 → conv3 → … → conv1；
  `backward(m,x,dlogits)` 是内部先跑一次带 cache 的 forward 的便捷版，训练循环**不用**它（否则前向算两遍）。
- `cnn_params()` 的固定顺序 `c1.W,c1.b,c2.W,c2.b,c3.W,c3.b,fc.W,fc.b` 是 checkpoint 与 Adam 状态的约定。

### 1.2 数据集读取 `src/include/uavrgb/dataset.hpp` + `src/dataset.cpp`

严格按 `tools/DATASET_FORMAT.md` v1：

- 读 48 B 小端头，校验 `magic/tag/version==1/header_size==48/channels==3/dtype==1/1`、
  `images_offset==48`、`labels_offset==images_offset+N*C*H*W`、`meta_offset==labels_offset+N`、
  `file_size==meta_offset+meta_len`；**H/W/C 全部来自文件头**，未假定 160×120。
- 标签区读后校验 `0..3`；meta 只做最小扫描：取 `episodes[]` 每项的 `sample_start/sample_count/split`
  切 train/val/test，缺字段或 split 非法直接抛错（不实现通用 JSON 解析器，字段缺失宁可失败）。
- `load_images()` 按需 `seekg+read` 单个样本（文件不整体进内存），NCHW 直接对应 `Tensor` 布局，
  像素 /255 归一化到 [0,1]，输出缓冲跨 batch 复用。

### 1.3 checkpoint `src/include/uavrgb/checkpoint.hpp` + `src/checkpoint.cpp`

自定义二进制 v1（小端、float32、无填充），布局写在头文件注释里：

```
0  "UAVRCK01"(8) | 8 u32 version=1 | 12 u32 param_count=8
16 i32 in_h,in_w,in_c,num_classes      ← 模型结构元信息
32 u32 adam_t（step 数）| 36 u32 epoch
40 逐参数：u32 ndim、i64 dims[ndim]、f32 data[numel]
   再逐参数：f32 m[numel]    再逐参数：f32 v[numel]
```

- 先写 `<path>.tmp` 再 `rename`，中途失败不会毁掉旧 checkpoint。
- 读回时校验 magic/version/param_count/结构元信息/逐参数 dims/m/v 形状/文件尾无多余数据，
  任何不符抛 `std::invalid_argument`，**不做部分加载**。lr/beta/eps 不入盘（恢复时以 CLI 为准）。
- 往返是逐位相同的（自检里 `memcmp` 参数、m、v）。

### 1.4 训练器 `src/include/uavrgb/trainer.hpp` + `src/trainer.cpp` + `src/train_main.cpp`

- 循环：分 batch → `forward`(带 cache) → `softmax_ce_loss_cuda` → `softmax_ce_grad_cuda` →
  `backward` → `clip_grad_norm_cuda`(global L2, 默认 5.0) → 逐参数 `adam_step_cuda`。
- `results.csv`：表头固定 `kResultsCsvHeader`，每 epoch 追加 `epoch,train_ce,dev_ce,dev_accuracy`；
  续训时 epoch 从 checkpoint 里的 `epoch` 接着编号（不自 1 重来）。
- `metrics.jsonl`：每 step 一条 `train_step`（step/total_steps/loss/action_accuracy/lr/elapsed_sec/eta_sec），
  每 epoch 一条 `validation`（split="val"），另有 `status`（启动/完成）与 `error`（loss 非有限值 → FATAL 并中止；
  数据集无 val split → WARN 且 dev 回退到 train）。每步 `flush()`，监控台按追加偏移增量读。
  字段名与 `event.hpp` 的 `MetricsEvent` 一一对应（自检里用 `keys_of()` 逐事件比对键集合）。
- CLI：`uavrgb_train --data <dataset.uavr> --epochs N --batch B --lr L --out <run_dir> [--resume <ckpt>] [--seed S] [--max-grad-norm G]`，
  结束打印样本数/墙钟/样本每秒。

### 1.5 自检

- `src/tests/synthetic_dataset.hpp`：按 v1 格式写合成 UAVR（**纯均匀噪声图 + 随机标签**，图像与标签无真实规律，
  只能靠记忆拟合），既有 train 也有 val episode 的变体。
- `src/tests/test_trainer.cpp`：64 样本（48 train / 16 val）、batch 32、10 epoch = 20 step，断言
  loss 末 5 步均值 < 首 5 步均值、参数确实变了、checkpoint 往返逐位相同（参数 + m/v/t + epoch）、
  结构不符的模型被拒、`results.csv` 表头/列数/epoch 连续、`metrics.jsonl` 每类事件字段名与 event.hpp 一致。
- `src/tests/test_overfit.cpp`：16 个固定样本、batch 16、200 step，训练准确率 > 95%。

## 2. 没做什么（明确清单）

| 项 | 状态 | 说明 |
|---|---|---|
| CPU 还是 CUDA | **CUDA** | 前向/反向全走 `src/*_cuda.cu` 的算子。实测 CPU 朴素实现慢 20–100 倍（batch 32、c1 前向 CPU 0.644 s vs CUDA 0.032 s；c1 反向 0.928 s vs 0.079 s），CPU 完全不可用于训练。 |
| device-resident 优化 | **没做** | 仍是 parity 模式：每次算子调用内部 `cudaMalloc` + `cudaDeviceSynchronize` + pageable H2D/D2H，激活张量每层都往返一次 host。这是当前吞吐的第一瓶颈，见 §4。 |
| 数据增强 | **没做** | 只做 /255 归一化。 |
| lr 调度 | **没做** | 全程恒定 lr（Adam 的 β1/β2/eps 也是默认值）。 |
| 数据加载并行 / 预取 | **没做** | 单线程 `seekg+read`，靠 OS page cache。 |
| 混合精度、BN、dropout | **没做** | 纯 FP32。 |
| test split 评测、闭环评测 | **没做** | 只统计 train/dev；`test_idx` 读出来但没用。 |
| 「别调 Tensor::zeros」这条优化 | **无法落地** | 本仓库 `Tensor(dims)` 与 `Tensor::zeros(dims)` 实现完全相同（都 `data_.assign(numel(), 0.0f)`），没有「不初始化分配」的接口；而且实测清零不是瓶颈（见 §4）。 |

## 4. 风险遗留

1. **吞吐只有 ~59–62 样本/秒**。用户给的参考是 batch 256 朴素包装 48 样本/秒，本实现 batch 256 是
   58.9 样本/秒——只快约 20%，而且 batch 大小对吞吐几乎不敏感（说明瓶颈不是算力，是每层固定的往返开销）。
2. 瓶颈实测在 parity 模式的 host↔device 往返，不在清零。batch 64 单步约 1.2 s 的拆解：
   relu 前后向 ~0.16 s、maxpool 前后向 ~0.20 s、三层 conv 前后向 ~0.36 s、linear+softmax ~0.02 s、
   裁剪+Adam ~0.006 s。层 1 的激活是 78.6 MB，一次 `relu_forward_cuda` 要 2 次 cudaMalloc + 157 MB
   pageable 拷贝，耗时 72 ms，而 kernel 本身只有几毫秒。**真正的修法是 device-resident 引擎**
   （权重常驻、层间不落 host、算子融合），那是另一轮工作，本轮明确没做。
3. checkpoint 没有校验和，损坏只能靠形状/dims 校验发现；格式变化没有向后兼容（版本号会拦）。
4. 训练器按样本 `seek+read`，数据集大到超过 page cache 时会掉速；没做预取。
5. `ui/monitor.py` 的「启动训练」会给命令追加 `--config <path>`，`uavrgb_train` 不接受这个参数。
   监控台**能监视**本训练器产出的 run_dir（解析已验证），但不能用它的启动按钮直接拉起本二进制。
   未改 ui/，留给后续对齐。
6. 本轮的合成数据是纯噪声，任务本身不可泛化——它只证明链路能学，不代表真实数据上能学到东西。
   真实数据（`tools/preprocess.py` 产出）本轮**没有**跑过，因为仓库里没有现成的 `.uavr`。
7. 训练循环单线程、无早停、无最优 ckpt 保留（每 epoch 覆盖写同一个 `ckpt.bin`）。
