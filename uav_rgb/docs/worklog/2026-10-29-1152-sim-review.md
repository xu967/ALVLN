### 实现与 uav_rgb 的关联

- TinyAerialVLN 的 server 是标准库 HTTP 管理台：回环监听、Host/Origin 门禁、
  注册 profile 执行、进程组停止、CSV→事件转发、审计 ZIP。真实 registry 六个
  资源数组均为空；train/eval/sim/board/uart 入口返回 BLOCKED/3。
- 它没有调用 `uav_rgb/src/build/uavrgb_train` 或 `uav_rgb/sim/tools/collect_parallel.py`。
  示例训练 profile 使用 `--config/--output`，与 uav_rgb 的 `--data/--out` 不兼容，
  不能仅把 executable 路径换成 uavrgb_train 就宣称集成完成。
- TinyAerialVLN 的场景生成器包含 2.5D 膨胀栅格 A*、彩色语义地标和 distractor，
  产物仅静态世界/oracle，无相机或四旋翼；与 uav_rgb 的实际四旋翼世界不是同一个后端。
- C++ 只有 FP64 Linear/CE 数值探针；`training_monitor.hpp` 是未接入 CMake/trainer
  的未来钩子。不能把这些代码或管理台测试当作 ECPT/VLN/GRU 已实现。

### 发现与风险

- **实测测试入口遗漏**：`tests/test_engineering.py:112` 的 `unittest.main()` 在
  `TestManagedJobs` 类定义之前。unittest discover 跑 23 项，而直接执行该文件
  仅跑 21 项、仍返回成功，漏掉托管进程测试。
- **数据门禁只是 ID 层**：`server/core.py:266` 仅拒绝 train/val cache ID 相同；
  不核对场景、几何 hash 或真实数据来源，不能替代 uav_rgb 的数据泄漏检查。
- **产物默认位置不合当前根目录约定**：`server/core.py:24` 固定 `ROOT/artifacts`，
  `tools/scene_generator.py:140` 默认同目录 artifacts/scenes，未走 DATA_ROOT；
  若未来接真实训练，需要先改为代码外产物目录。本轮没有启动真实 profile。
- **停止语义不完整（源码观察）**：`server/core.py:321` 只发 SIGTERM，不设收尾
  超时或 SIGKILL 升级；任务忽略 TERM 时可一直运行。服务退出也没有主动处理
  存量子进程；重启只标 interrupted 并明确不误杀，真实任务的接管仍需设计。
- **数值探针边界（源码观察）**：`tensor_ops.hpp` 的构造未验证维度，`grad(label)`

- HTTP 默认门禁阻断未注册执行项，未发现由用户 payload 直接拼 shell 命令的路径。
