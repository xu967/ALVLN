# E6-1：常驻推理进程与 checkpoint 头读取

- 时间：2026-10-29 22:26
- 范围：`src/`（推理入口）、`docs/TASKS.md`
- 结论：完成。闭环评测的第一个前置（单帧推理）已可用，19/19 CTest EXIT=0。

## 做了什么

- `src/include/uavrgb/checkpoint.hpp`、`src/checkpoint.cpp`：新增 `CheckpointMeta` 与
  `read_checkpoint_meta()`；把 magic/version/结构头解析抽成 `read_header()`，`load_checkpoint()`
  复用同一份格式，避免两处走样。
- `src/include/uavrgb/infer.hpp`、`src/infer.cpp`：`run_infer_loop()` 从输入流按
  `in_h*in_w*in_c` 字节读 RGB uint8（HWC），写一行
  `{"action":..,"probs":[..],"infer_ms":..}`；截断帧/写失败抛 `runtime_error`。
- `src/infer_main.cpp`：`uavrgb_infer --ckpt <ckpt.bin>`；启动先输出一行结构头
  `{"in_h":..,"in_w":..,"in_c":..,"num_classes":..}`，再由 Python 按尺寸喂帧。
- `src/CMakeLists.txt`：`infer.cpp` 进 `uavrgb_core`；新增 `uavrgb_infer` 与 `test_infer_io`。
- `src/tests/test_infer_io.cpp`：8×8 小模型验证单帧/空输入/截断帧/同帧确定性。
- `src/tests/test_trainer.cpp`：checkpoint 保存后校验 `read_checkpoint_meta` 的尺寸。

## 没做什么

- **没做 Python 侧闭环脚本**（E6-2）。原因：本任务只交付单帧推理进程。
- **没做图像缩放/预处理**。原因：`run_infer_loop` 只收模型尺寸的 RGB；缩放放 E6-2，
  复用 `tools/preprocess.py` 的 PIL bilinear 口径，避免两套插值。
- **没做批量推理/多帧流水**。原因：闭环按步决策，单帧 6.6 ms 已远低于动作窗口。
- **没做协议版本号**。原因：当前只有本仓库两个进程用，hello 行已带尺寸；等外部接入再加。
- **没测长跑内存**。原因：100 帧冒烟只验证确定性/延时；E6-2 闭环会自然覆盖数千帧。

## 待确认

## 风险与遗留

- Python 端必须读 hello 行拿尺寸，不能硬编码 120×160；换数据集尺寸时否则会读错帧边界。
- `probs` 用默认 6 位有效数字输出；若后续要数值对账，需固定 `setprecision`。
- 推理进程目前单线程阻塞；闭环一帧 6.6 ms，暂不需要流水线。
