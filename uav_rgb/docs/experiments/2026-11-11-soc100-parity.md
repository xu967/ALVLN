## 0. 要解决的问题

SITL 每集从 50% 电量起飞，推力余量约 100 s 耗尽，一集最多约 100 步（hold 1.0 s）；长任务要满电起飞。起始电量只能经 params JSON 的副本覆盖
（`sim.value.battery_soc_init`），副本的 `dynamics_profile` 与默认不同，数据不与现有数据混包。要回答两件事：

1. `collect.py --cf-sitl-params` 给了副本，Gazebo 里的插件实际读的是不是副本。
2. 满电档的单步动力学与成败，是否与 50% 档的数据可以互用。

## 1. 插件读哪份参数（起跑前查清）

- 证据（代码）：`sim/cf_sitl/gz/CfSitlSystem.cc` 的 `Configure` 只读世界 SDF 里 CfSitlSystem 插件块的 `<params>`（`sdf->Get<std::string>("params")`），
  相对路径由 `ResolveParams` 用 `UAVRGB_REPO_ROOT` 补全，再交给 `cf_sitl_init`。模板 `sim/worlds/uav_rgb_e1.sdf` 里写死 `sim/dynamics/e1_mini.json`。
- 修复前：`collect.py --cf-sitl-params` 只把 `CfSitlParams.from_json(副本)` 用在 Python 一侧（manifest 的 `dynamics_profile`、`params_sha256`、`dynamics_params`，以及库版本核对），
  世界里的 `<params>` 不变。给了副本时 manifest 写满电指纹，插件里的物理仍是 50% 电量，两边静默不一致。
- 修复（`b436c90`）：`scene_gen.py --cf-sitl-params <绝对路径>` 只改那一行 `<params>`（meta 多 `cf_sitl_params`，`world_sha256` 随世界更新；X3 模板、不存在的文件、
  含空白或 XML 特殊字符的路径拒绝）；`collect_parallel.scene_gen_extra` 与 `eval_closed_loop` 把同一个绝对路径同时透传给 `scene_gen` 与 `collect.py`，只能配 `--dynamics cf_sitl`；
  eval.json 在给了开关时多 `cf_sitl_params {path, sha256, values_sha256}` 与 `dynamics_profile`。
- 默认路径不变：不给 `--cf-sitl-params` 时世界、meta、命令行、eval.json 与旧树逐字相同。新旧树各跑一遍（11 个世界、3 种 eval 命令行、3 组 `scene_gen_extra` 参数），
  输出 json 逐字节相同（sha256 `57a879a0…ae402`，`diff_default.py`）；单测 17 项先红（旧树 7 失败 8 报错）后绿。
- 经验证据（遥测）：由探针 `probe_plugin_params.py` 在起跑时取得，见第 4 节条款 S1 与第 5 节。代码层面的结论（插件只读 `<params>`）与探针的遥测结论分开记，探针没跑完前，遥测一栏标「未核实」。

## 3. 预注册（抄自任务卡「11-11 更新」，逐字在 `run.sh` 头部，单测逐字核对）

> K=1 的每步前飞位移与转角（口径同 `summarize_r2.py`）与 50% 档相差不超过 5%，成功数配对无可检出的差别（精确 McNemar p > 0.05）；
> K=3 满电档里飞到电量掉高的集数为 0，第 1 块通过率与 50% 档相差不超过 0.08，三块全过的集数不少于 50% 档。证伪：K=1 的位移或转角相差超过 10%。
> 差超过 10% 则两档的数据与结论不能互用，报告里写明并停下。
> 第二轮没有 `DONE` 或 `DONE` 的 rc 不是 0 时先停下报告，不要自己起对照臂。

逐项落成（`summarize_parity.py` 的 `judge`，起跑后不改）：

| 条款 | 量与口径 | 通过 | 备注 |
|---|---|---|---|
| P1 | K=1 每步前飞位移，第二轮 `config.env` 的 `DISP_CLAUSE`（cruise：连续前进第 4 步起、步 3–30），三个训练种子 60 集的池化均值 | 满电对 50% 的相对差的绝对值 ≤ 5% | > 10% 证伪 |
| P2 | K=1 每步转角，YAW 步 \|dyaw_deg\| 的池化均值 | 相对差的绝对值 ≤ 5% | > 10% 证伪 |
| P3 | K=1 走廊内成功数（`success`，横向边界 3 m），同 seed 同训练种子逐集配对，三个种子合并 60 对 | 精确 McNemar p > 0.05 | |
| P4 | K=3 满电档 `z_tail_min < 1.5 m` 的集数（电池压降的症状，长课程汇总脚本的口径） | = 0 | |
| P5 | K=3 第 1 块通过率（通过数 / 60） | 满电与 50% 的差的绝对值 ≤ 0.08 | |
| P6 | K=3 三块全过的集数 | 满电 ≥ 50% 档 | |

判决：`PASS` = P1..P6 全过；`FAIL` = 有项没过且没触发证伪；`FALSIFIED` = P1 或 P2 相对差 > 10%（两档数据与结论不能互用）；`INVALID` = 指纹或配对协议键不一致；`INCOMPLETE` = 臂没跑完。
5% 与 10% 的边界各有单测（含浮点噪声：`1.05/1.0 − 1` 大于 0.05 的 4e-17 量级，判据加 1e-9 容差）。没设提前停止：判决量是 60 集的池化量，单个臂 20 集太噪。

## 4. 验收实验设计

- 协议：与第二轮学生臂同一条命令行（`run_r2.sh` 的 `acc_job`，单测逐词比较，只差臂名前缀与 `--cf-sitl-params $D/params/e1_mini_soc100.json`）：
  `--window-from observation --action-latency 0.20`（L 取 `$R2/L_STAR`），学生臂不带 `--rtf`，calswa 三个训练种子（`cal_swa_s{0,1,2}_k10.bin`）× K=1（柱阵 80 步）/ K=3（长课程 3 块 240 步），
  每臂 20 个冻结 seed，`--heading-guard 2`，走廊 3 m。共 6 个臂 120 集。对照 = 第二轮的 `acc-L0.20-k{1,3}-s{0,1,2}`（50% 电量），只读。
- 资源：2 条车道；阻塞式机器锁；起跑条件 ① GPU ② cgroup ≥ 12 核 ③ 机器锁 ④ 空闲（无 gz sim，30 s 窗口内容器 < 1.5 核，抄 `run_r2.sh` 的 R7）。
  实际起跑用 `IDLE_MAX_CORES=8`：01:00 前后同机负载实测 4.2–6.56 核（`.cursor-server` 的两个 node 进程约 1 核，别的卡的测试与分析 3–5 核），1.5 核的门长期不满足，持锁空等会挡住别的卡；第二轮对照臂自己也在 3.6–9.5 核的容器负载下跑（`run.log` 的 `usage_usec` 差）。`start.txt` 记实测核数与上限。
- 条款 S1（探针）：满电臂之前，用同一个守护进程起 default 与 copy 两种世界各 3 个 `gz sim -v 3`，读静止电压（DISARMED，不受负载影响）、READY 时刻读数与插件日志的 `params=` 行。
  判据 G0 copy 世界里 `<params>` 是副本路径，G1 每个都到 READY，G2 copy 的静止电压中位数比 default 高 ≥ 0.25 V（预期约 0.38 V，出处是 `sim/dynamics/e1_mini.json` 的开路电压曲线，SoC 1.0 为 4.20 V、SoC 0.5 为 3.82 V），G3 日志 `params=` 与世界一致（读不到记「未核实」），G4 库版本一致。不过 rc=21，不起满电臂。
- 条款 S2（对照核对）：拿到机器锁后，`$R2/DONE` 存在且 rc=0、`L_STAR`、对照六个臂评完；权重、推理二进制、插件的 sha256 与 `$R2/inputs.txt` 一致；
  `sim/tools`、`sim/dynamics`、`sim/worlds`、`sim/cf_sitl` 与第二轮冻结代码只许有允许清单里的差异（`scene_gen`、`collect_parallel`、`eval_closed_loop` 三个文件、测试文件、README）。
  第二轮没有 DONE 或 rc ≠ 0：rc=20，不起任何臂。
- 条款 S3（迟到步）：含迟到步的集自动重跑一次（`<臂>-retry1`），两份记录都留，汇总以重跑结果为准。
- 另报不进判决：位移与转角中位数、首步观测仿真秒（起飞到就绪的代理，逐 seed 配对）、K=3 的 S_1/S_2/S_3 与 sim_s、探针的 READY 用时与悬停油门。
- 评测口径：metric_version `sim09.v2.coast1s.corridor3m`，成功数的分母 = 请求集数（每臂 20）。

起跑前已知的事实（来源与可信度）：CPU 试探（`docs/reviews/2026-11-10-phase12/complexity.md` §5，未核实可复现）里 50% 电量解锁到 READY 约 7.3–8.1 s（SITL 时钟）、V_bus 约 3.43 V、悬停油门约 0.89，
100% 约 9.6–10.3 s、约 3.81 V、约 0.79；连续前飞时 50% 在 106–107.5 s 开始掉高、122.5–123 s 触地，100% 在 205.5 / 251 s 开始掉高、260.5 / 268 s 触地。
