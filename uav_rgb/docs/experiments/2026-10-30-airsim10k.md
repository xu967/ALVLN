# Kaggle AirSim 10k 公开数据集：清点、离散化、训练（链路验证，不作验收）

- 时间：2026-10-30 00:56–01:30
- 环境：RTX 2080 Ti（GPU 模式）、`.venv-tools`
- 数据集：`lukpellant/droneflight-obs-avoidanceairsimrgbdepth10k-320x320`（CC BY 4.0）
- 结论：**数据本身是自洽的，但不能单独用来训练我们的 4 类模型**——
  `SAFE_NEUTRAL` 一条都没有，模型一次也不会输出它。训练链路本身跑通了。

## 数据是什么

解压后 `data_collected_potential_final_v58_mod25_320x320_cmds/` 下三个目录，
各 10000 个文件，序号 `000000`–`009999` 连续、无缺口、无空文件：

| 目录 | 内容 | 形状/dtype | 实测范围 |
| --- | --- | --- | --- |
| `rgb/` | RGB 原图 | 320×320 PNG | — |
| `depth/` | 深度 | 320×320 float16 | 0.22–125.0 m，无 NaN |
| `commands/` | 连续指令 | (4,) float32 | 见下 |

### 数据集自己的描述有两处与文件不符

Kaggle API 拿到的作者描述 vs 实测：

| 描述声称 | 实测 | 影响 |
| --- | --- | --- |
| depth "normalized to [0, 1] with max_depth=25.0" | **单位就是米**，0.22–125.0；36.2% 的像素 >25 m，11.4% 卡在 125 m 远裁剪 | 按 [0,1]×25 还原会得到错误距离；本文的 `1/depth` 检验不受影响（单调变换） |
| commands "normalized based on statistics (means…, stds…)" | **是原始值**：四列均值/标准差恰好等于描述里那组数（真归一化后均值必须是 0） | 再按那组参数反归一化会把 `yaw_rate` 变成 ±1447 deg/s |

两处都是「照文档用就出错」。这也是为什么这份数据必须先过一遍实测再谈训练。

指令四列 = `(vx, vy, vz, yaw_rate)`：

```
vx        min=+1.0000 max=+3.4999 mean=+2.4262 std=0.8720   (m/s)
vy        min=+0.0000 max=+0.0000 mean=+0.0000 std=0.0000   (恒为 0，无侧移)
vz        min=-0.9287 max=+1.8799 mean=+0.0243 std=0.3191   (m/s)
yaw_rate  min=-70.3401 max=+70.4126 mean=-1.3046 std=20.7282 (deg/s)
```

**这三个 range 与 Kaggle 页面给的 mean/std 完全对得上**
（vx 2.43/0.87、vy 0/0、vz 0.025/0.32、yaw_rate -1.17/20.56），说明 `.npy`
里存的是**原始指令**，那组数是数据集统计量而不是归一化参数。
若当成归一化参数再反归一化，`yaw_rate` 会变成 ±1447 deg/s（物理上不可能）。
这一步差点搞错，记在这里。

## 两条硬结论

**1. `SAFE_NEUTRAL` = 0 条。** `vx` 最小 1.00 m/s，指令永远包含前进分量，
势场法从不输出「停」。任何从这份数据学出来的模型都不可能输出 `SAFE_NEUTRAL`。

**2. 标签和图像是自洽的。** 用深度图下半幅的左右接近度（`prox = 1/depth`，
`L−R`）分组检验转向标签。可复跑：

```bash
python3 tools/airsim_to_uavr.py --check-labels --src <解压目录>
# 判据：|标准化差| < 2 sigma 判 FAIL（EXIT=1），说明图像/标签可能错位
```

| 标签 | n | 中位数 L−R | 左更近占比 |
| --- | --- | --- | --- |
| `FORWARD_SLOW` | 6870 | +0.0000 | 50.3% |
| `YAW_LEFT` | 1408 | +0.0376 | **82.1%** |
| `YAW_RIGHT` | 1722 | −0.0430 | **16.8%** |

`YAW_LEFT` 与 `YAW_RIGHT` 的均值差 `+0.1243 m^-1`，合并标准误 `0.0048`，
**+25.8 sigma**。转向方向与深度图的左右几何强烈相关，不是噪声。
这条检验能过，说明至少「图像 / 深度 / 标签」三者是对齐的——正是我们自采数据
当年出的问题。

## 序号是不是连续飞行

相邻序号帧的灰度平均绝对差 vs 随机两帧：

| 对比 | min | p10 | median | p90 | max |
| --- | --- | --- | --- | --- | --- |
| 相邻序号 | 8.39 | 12.88 | **22.72** | 34.39 | 55.75 |
| 随机两帧 | 39.23 | 60.71 | **77.53** | 95.45 | 125.28 |

相邻对明显更像，说明序号是**连续飞行**，不能按帧随机分 split。
但相邻差仍有 22.7（真正的连续视频帧通常 < 5），说明采样间隔大/位移大。
按 `>50` 找边界得到 305 段、段长中位数 1，直方图也没有明显双峰——**分不出干净
的片段边界**，所以最终按序号**连续块**切分（train 0–6999 / val 7000–8499 /
test 8500–9999）。两个块边界上仍各有一对相邻帧（6999/7000、8499/8500）会
分属不同 split，泄漏量 2/10000，可忽略但不能说「不跨块相邻」。

## 离散化规则

`tools/airsim_to_uavr.py::action_of()`，确定性、可复算：

```
yaw_rate >= +10 deg/s        -> YAW_LEFT
yaw_rate <= -10 deg/s        -> YAW_RIGHT
vx > 0.05 m/s                -> FORWARD_SLOW
否则                          -> SAFE_NEUTRAL
```

离散化结果（10000 帧）：

| 类别 | 条数 | 占比 |
| --- | --- | --- |
| `SAFE_NEUTRAL` | 0 | 0.00% |
| `FORWARD_SLOW` | 6870 | 68.70% |
| `YAW_LEFT` | 1408 | 14.08% |
| `YAW_RIGHT` | 1722 | 17.22% |

图像处理：320×320 先中心裁成 320×240（去掉上下各 40 px），再双线性缩到
160×120，保持 4:3 不失真（`meta.resize.aspect = "preserve"`）。

## 训练

```bash
cmake --build src/build        # 先重建：旧二进制是 18:03 的，比源码老
src/build/uavrgb_train \
  --data /root/rivermind-data/uav_rgb/airsim10k-uavr/dataset.uavr \
  --epochs 10 --batch 128 --lr 1e-3 --seed 0 --class-weights auto \
  --out /root/rivermind-data/uav_rgb/airsim10k-run
```

模型 100,388 参数；70000 样本（1 万 × 10 轮）用时 1014.8 s。

逐轮（`class_weights auto`：`[0, 0.370, 1.733, 1.396]`，类别 0 因为没样本权重记 0）：

| epoch | train_ce | dev_ce | dev_acc | dev_macro_f1 |
| --- | --- | --- | --- | --- |
| 1 | 0.940 | 0.764 | 0.707 | **0.4873** ← best |
| 2 | 0.735 | 0.824 | 0.652 | 0.4621 |
| 3 | 0.648 | 1.170 | 0.488 | 0.3630 |
| 4 | 0.577 | 0.841 | 0.668 | 0.4655 |
| 5 | 0.484 | 1.011 | 0.607 | 0.4249 |
| 6 | 0.425 | 1.049 | 0.626 | 0.4378 |
| 7 | 0.343 | 1.017 | 0.655 | 0.4498 |
| 8 | 0.274 | 1.287 | 0.620 | 0.4263 |
| 9 | 0.227 | 1.324 | 0.652 | 0.4418 |
| 10 | 0.181 | 1.698 | 0.596 | 0.4212 |

**明显过拟合**：train_ce 从 0.94 一路降到 0.18，dev_ce 从 0.76 反升到 1.70。
best checkpoint 落在 **epoch 1**（macro_f1 0.4873）。

末轮权重在 test 上的指标（`EVAL_STANDARD.md` §1.1 口径）：

| 指标 | val | test |
| --- | --- | --- |
| `action_accuracy` | 0.5960 | 0.6387 |
| `macro_f1` | 0.4212 | **0.3855** |
| `balanced_accuracy` | 0.4681 | 0.4552 |

分类别（test，行=真值 列=预测）：

```
              SAFE  FORWARD  YAW_LEFT  YAW_RIGHT   真值合计
SAFE_NEUTRAL     0        0         0          0          0
FORWARD_SLOW     0      764       180        227       1171
YAW_LEFT         0       63        73         21        157
YAW_RIGHT        0       36        15        121        172
预测合计         0      863       268        369       1500

             SAFE  FORWARD  YAW_LEFT  YAW_RIGHT
recall      0.000    0.652     0.465      0.703
precision   0.000    0.885     0.272      0.328
f1          0.000    0.751     0.344      0.447
```

`SAFE_NEUTRAL` 的 recall / precision / F1 全为 0，且模型一次都没预测过它——
训练集里本来就没有这个类，这是必然结果，不是训练失败。

**这组数字不能当算法结论**：

1. test 用的是**末轮权重**，不是 `ckpt_best.bin`（epoch 1）。训练器没有
   eval-only 模式，best 模型在 test 上的数目前拿不到。
2. 只训了 10 轮、`lr=1e-3` 明显过大（dev_ce 第三轮就反弹）。
3. 只算了标准宏 F1（含 SAFE_NEUTRAL 的 0）。若只在**有样本的 3 类**上算，
   test 宏 F1 是 0.5140——这个数不符合 `EVAL_STANDARD` 口径，只能当参考，
   不能写进结论。

搜遍 Kaggle / GitHub / 论文库，没有找到配套的论文、仓库或排行榜。

同类工作里能查到的数据量（多数来自搜索摘要，未逐篇核对原文，标 ⚠）：

| --- | --- | --- | --- |

| 我们当前 | 3,726 样本（旧格式）/ 16 步（新格式验证） | 4 类分类 | test macro_f1 见上；旧格式未记 |
| IIT 硕士论文（AirSim 航点规划） ⚠ | ~29,000 帧 RGB | 视觉航点规划 | — |
| 北理工 2025（AirSim 门穿越 BC） ⚠ | 100 圈示范 | RGB → 控制 | 纯 BC **0% 成功率**，加 DAgger 式增强才可用 |

不能拿它当验收靶子。要「超过公开数字」，得先指定对标对象（见下）。

## 没做什么

- **没有验证势场法标签本身对不对**。做的是「标签与深度几何是否一致」，
  不是「势场法的决策是否最优」。没有场景几何和无人机位姿，后者做不到。
- **没有用 depth 训练**。我们的模型输入只有 RGB，depth 仅用于上面的标签检验。
- **没有做场景级 split**。数据里没有场景/位置元数据，无法保证 test 是新场景。
- **没有跑闭环**。这份数据的世界不是我们的柱阵，闭环要在 Gazebo 里跑，
  与这份数据的标签无关。
- **没有用 `ckpt_best.bin` 做 test 评估**。训练器没有 eval-only 模式，
  test 只在训练末尾用末轮权重跑一次。想要「交付模型」的 test 数，得先加这个模式。
- **没有调超参**。`lr=1e-3` 是默认档，没有为这份数据做过任何搜索，
  也没有加 early stopping。

## 待确认

- 10 deg/s 的转向阈值是拍的。它决定 69/14/17 这个分布；换成 20 deg/s 会变成
  66/34 左右的 3 类分布。要跟我们的动作幅度（YAW = 0.6 rad/s = 34.4 deg/s）
  对齐的话，阈值可能该取在两者之间。
- 这份数据到底值不值得当预训练。世界是郊区街道，我们是柱阵走廊；视觉域差得远。
  现在只知道「能训、训得出来」，不知道「训了有没有用」——要证明有用，得拿它
  预训练、再用 sim 数据微调，然后在 Gazebo 里跑闭环对比。
- 过拟合到 dev_ce 反弹，说明 7000 样本 + 10 轮已经吃满了。是加数据增强、
  降 lr，还是就认了（反正只是预训练），没有依据。
- **第一阶段「超过公开方案」的对标对象还没定。** 这份数据集没有公开数字，
  可选的三条路：（a）自建基线阶梯（盲前进 / 频率先验 / 我们的模型）在 sim 数据上
  比 macro-F1；（b）按 AvoidBench 口径跟 Ego-planner 等规划器比闭环 SR；
  （c）换一个有公开榜单的数据集。三条路的验收口径完全不同，需要先拍板。
