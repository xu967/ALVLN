# 3DGS 在线渲染 pilot（2026-11-05）

目标：在**独立 3DGS venv** 里用 gsplat 在线渲染 RGB/depth，配黑盒四动作动力学和
点云碰撞代理，跑通采集与学生 C++ 闭环；不改 Gazebo 管线、不改 `src/`、`teacher/`、
`sim/tools/collect.py`、`sim/tools/eval_closed_loop.py`。

结论先行：

- 真实 gsplat 后端在本机 **RTX 2080 Ti (sm_75) + torch 2.7.1+cu128 + gsplat 1.5.3**
  可用；`render_mode="RGB+ED"` 同时出 RGB 与期望深度。
- 公共场景 Callinstrasse Campus（MIT，512 MB PLY）**未下载成功**：服务器到本机
  约 12 KB/s（8 连接合计 ~36 KB/s），按 30 分钟预算中止；已保留 2.4 MB 断点和恢复命令。
- 改用两个场景：`luigi`（HuggingFace 988 KB 真实 3DGS，上传者未声明 license，仅验证
  渲染/深度/FPS）与 `synthetic`（自建合成走廊，几何/尺度/z 向上已知，用于闭环）。
- 学生 C++ 在线评测：用 `airsim10k-run/ckpt_best.bin` + `build/check/uavrgb_infer`
  跑通（输入 160×120，4 类，text_dim=0）；SR 数字没有意义（学生训练于 Gazebo 视觉，
  3DGS 场景是域外），只验证链路。

## 3. 代码与接口

新增包 `sim/3dgs/`：

| 文件 | 职责 |
|---|---|
| `scene.py` | INRIA 3DGS PLY 读写、合成场景、`scene.json`、nav 位姿→viewmat、K |
| `renderer.py` | `GsplatRenderer`（RGB+ED，任意 viewmat/K，320×240/160×120）、`MockRenderer`、CLI |
| `dynamics.py` | **薄包装**，直接 import `sim/tools/cf_blackbox.py`；参数唯一来源 `sim/dynamics/cf_blackbox_v1.json` |
| `collision.py` | 点云 2 m 高度切片 → 膨胀体素占据 + 地面；KD-tree 净空 |
| `collect_3dgs.py` | 在线采集：渲染→动作→cf_blackbox→碰撞→落盘 |
| `eval_3dgs.py` | 学生 C++ 在线评测，`eval.json` |
| `test_*.py` | 20 项单测（mock 全跑；真实 gsplat 用 `RUN_3DGS_REAL=1` 开启） |

**动力学单源**：`sim/3dgs/dynamics.py` 不再有第二套模型或 JSON；直接用
`CfBlackboxParams.from_json()` / `CfBlackbox`，manifest 写
`dynamics_profile=CfBlackboxParams.profile()`（带参数 sha8）和
`dynamics_params=CfBlackboxParams.manifest()`。z 固定 2.0 m。

**episode 格式**（与 `collect.py` 对齐，`preprocess.py` 可直接读）：

```
<out>/run.json
<out>/ep_00000/
  episode_manifest.json   schema=navlab.episode.v1，含 dynamics_profile/params、
                          teacher、hold_s、camera、renderer{backend,n_gaussians,...}、
                          collision_proxy、validity、performance
  actions.jsonl           step/timestamp_ns/action_expert/action_executed/collision/
                          src(voxel_proxy)/rgb_ok/frame/rgb_ts/pose_before/yaw_before/
                          displacement_m/dyaw_deg/sim_dt/infer_ms/render_ms/clearance_m
  oracle.jsonl            step/timestamp_ns(动作后)/pose_gt/action_start_ns/action_end_ns
  rgb_%05d.png            动作前 RGB（320×240，M1 语义：rgb_ts == 动作前时刻）
  depth/depth_%05d.npy    可选，float32 米，0=无回波
```

与现有管线的关系：

- `tools/preprocess.py` 只依赖 manifest 的 `geometry_gid/split/dynamics_profile` 和
  actions 的字段；3DGS episode 的 `geometry_gid=null`、`dynamics_profile` 是
  `cf_blackbox_v1:<sha8>`，可以正常打包，但**不能和 Gazebo v1 数据混训/混报**。
- `src/` 训练器与 `student.py` 完全未改；评测把渲染 RGB 包成 `gz.msgs.Image` dict，
  复用 `StudentPolicy.act()`（内部缩到 160×120）。
- `eval.json` 复用 `eval_closed_loop.summarize_episode/aggregate`，额外字段
  `metric_version=3dgs.pilot.v1`、`success_criterion=reach_waypoint_no_collision_v1`。

## 4. 运行

```bash
export UAV_RGB_ROOT=/root/claude-code-backup-20261028/code/uav_rgb
source "$UAV_RGB_ROOT/env.sh"
export TMPDIR=$DATA_ROOT/uav_rgb/tmp TORCH_HOME=$DATA_ROOT/uav_rgb/torch-cache \
       TORCH_EXTENSIONS_DIR=$DATA_ROOT/uav_rgb/torch-cache/extensions \
       TORCH_CUDA_ARCH_LIST=7.5 MAX_JOBS=4
PY=$DATA_ROOT/uav_rgb/3dgs-venv/bin/python
SCENES=$DATA_ROOT/uav_rgb/3dgs-scenes

# 合成场景（可重复生成；固定 seed）
$PY -m sim.3dgs.scene make-synthetic --out $SCENES/synthetic --seed 0

# 单帧 RGB+depth + 计时
$PY -m sim.3dgs.renderer --scene $SCENES/synthetic/scene.json \
  --pose 1,0,2,0 --width 320 --height 240 --fov 60 \
  --out /tmp/rgb.png --depth-out /tmp/depth.npy --bench 50

# 真实场景渲染验证（luigi）
$PY -m sim.3dgs.renderer --scene $SCENES/luigi/scene.json \
  --pose 0,-2,0.05,90 --out /tmp/luigi.png --depth-out /tmp/luigi.npy --bench 50

# 在线采集（1 集 8 步，teacher=深度反应式专家）
$PY -m sim.3dgs.collect_3dgs --scene $SCENES/synthetic/scene.json \
  --out $DATA_ROOT/uav_rgb/3dgs-pilot-20261105/collect-real \
  --steps 8 --policy teacher --save-depth

# 学生 C++ 在线评测（渲染 320x240，student.py 自己缩到 160x120）
$PY -m sim.3dgs.eval_3dgs --scene $SCENES/synthetic/scene.json \
  --out $DATA_ROOT/uav_rgb/3dgs-pilot-20261105/eval-student \
  --ckpt $DATA_ROOT/uav_rgb/airsim10k-run/ckpt_best.bin \
  --episodes 1 --steps 20 --save-depth

# 冒烟（不需要 GPU/权重）
$PY -m sim.3dgs.collect_3dgs --scene $SCENES/synthetic/scene.json \
  --out /tmp/3dgs-mock --steps 3 --policy forward --mock-renderer
$PY -m unittest discover -s sim/3dgs -p 'test_*.py'
```

`--mock-renderer` 是显式的：manifest 会写 `renderer.backend=mock`，不会静默伪装真实数据。
真实后端不可用时 `renderer.py` 直接报错，不回退 mock。

## 5. 实测（RTX 2080 Ti, 22 GB, sm_75）

以下数字来自本轮真实 gsplat 运行（协调 agent 复跑，代码含 00:59 的 viewmat +z 修正）：

| 项目 | 结果 |
|---|---|
| gsplat JIT（sm_75） | 首次 228–235 s；扩展缓存后不再编译 |
| 渲染 320×240，45,497 gaussians | 稳态 **~0.92 ms/帧**；eval 的 8 帧均值 2.2 ms/帧 |
| 采集 1 集 8 步（forward） | `3dgs-pilot-20261105/collect-claude/ep_00000/`，8 行 actions，无碰撞，`renderer.backend=gsplat` |
| 学生 C++ 在线评测 | `3dgs-pilot-20261105/eval-claude/eval.json`；t6 ckpt（`t6-full-1640/run/ckpt_best.bin`），8 步，碰撞 0，max_x=3.07 m（waypoint 30 m，8 步不可能到达，SR=0 属预期）；infer p50 9.4 ms / p95 12.5 ms |
| 单测 | 20 项（19 通过 + 1 个真实 gsplat 用例默认 skip；`RUN_3DGS_REAL=1` 可开） |

渲染器几何修正：gsplat/COLMAP 的 viewmat 是**相机 +z 朝前**，最初按 OpenGL -z 写导致
整帧被裁空；`scene.viewmat_from_pose` 已改为 `[right, down, forward]`。修正后采集帧
（step 5–7）有 1k–7k 种颜色，不再全空。

注意：合成走廊 spawn 处前 4–5 帧几乎全空——水平 60° 视场里地面要飞到 x≈5 m 才进入，
两侧墙要到 x≈7 m；这是**场景可见性**，不是渲染失败。正式训练前应在 spawn 附近加
近景几何或调 FOV，否则学生会看到大量无信息帧。

luigi（14,526 gaussians）只完成了下载与 PLY 解析；本轮时间用尽，未跑真实出图。

## 6. 碰撞代理限制（必须读）

**3DGS 不提供可靠碰撞几何。** 当前实现：

1. 取高斯 mean 在 `z_slice=[1.65, 2.35]`（飞行高度 2 m ± 0.35）的薄片；
2. 投影到 0.1 m 2D 栅格，按 `inflate_m=0.35` 膨胀；
3. 地面平面 `z=0` 单独判（`z-drone_radius <= ground_z` 即碰撞）；
4. `clearance_m` 用切片点云 KD-tree 的水平最近距离与离地高度取小。

因此：

- 薄树叶、玻璃、细杆、背面/视角外几何会漏检或误检；
- 高斯的 mean 不等于表面（半透明/悬浮高斯会把占据扩大）；
- 切片外的高度不检查（本 pilot z 固定 2 m，够用）；
- 数字只能用于**同代理下的相对比较**，不能当 Gazebo contact 或真实碰撞真值。

真实资产（COLMAP 稀疏点/网格）到位后，应把 `collision.py` 换成点云/网格/Isaac 的真值，
而不是继续用 splat 求交。

## 7. 未解决 / 风险

- **Callinstrasse 未落地**：只有断点；需要换网络或离线拷贝，然后手工对齐尺度/上轴。
- **luigi license 未声明**：只做本地验证，不随仓库分发；正式数据要换成有明确许可的场景。
- **gsplat JIT 编译**：首次运行需要 nvcc/编译缓存（本机 sm_75 实测 228–235 s）；
  换 CUDA/torch/显卡后缓存失效需重编。**不要并发跑两个 JIT 进程到同一个
  `TORCH_EXTENSIONS_DIR`**：会互相覆盖/ninja 竞态（本轮踩过，清理后单进程重编即可）。
- **首帧/近景空帧**：合成走廊 spawn 的前 4–5 帧几乎全空是场景可见性（地面/墙不在
  60° 视场内），不是渲染器问题；训练数据前应先修场景。
- **luigi license 未声明**：只做本地验证，不随仓库分发；正式数据要换成有明确许可的场景。
- **深度语义**：`RGB+ED` 是 expected depth（alpha 加权），不是 z-buffer；与 Gazebo
  depth 的噪声/边缘行为不同，教师阈值（`teacher.expert_action`）未针对它调参。
- **域差**：学生模型在 Gazebo 合成图上训练，3DGS 渲染图的 SR 不能代表导航能力；
  本 pilot 只证明链路跑通。
- **单源参数**：`sim/dynamics/cf_blackbox_v1.json` 的 notes 仍提到旧的
  `cf_blackbox_3dgs.json`（已删除），那是参数单源 agent 的文件，不在本任务所有权内，
  未改；`sim/3dgs/dynamics.py` 现在只读 `cf_blackbox_v1.json`。
- 场景/环境全部在数据盘；根分区未新增 >100 MB 文件。

## 8. 真实公开 3DGS 场景：Mip-NeRF 360 bicycle（2026-11-05）

- 来源：HuggingFace 公开镜像 `dylanebert/3dgs` 的
  `bicycle/bicycle-7k-mini.splat`（18 MB，567,714 Gaussians）。
  **上游数据集/HF 转换未声明 license；仅本地验证，不随仓库分发。**
- 下载：`https://hf-mirror.com/datasets/dylanebert/3dgs/resolve/main/bicycle/bicycle-7k-mini.splat`
  实测 ~891 KB/s。
- 转换：`python tools/splat_to_ply.py ... --flip-height --scale 2.0 --z-offset 0.516`
  -> `$DATA_ROOT/uav_rgb/3dgs-scenes/bicycle/bicycle_real.ply`（135 MB）。
  Mip-NeRF 360 的 COLMAP 世界是 y-up；这里转成 nav z-up，并翻转高度、缩放到
  ~2 m 飞行高度、把地面平移到 z=0。
- 场景：`$DATA_ROOT/uav_rgb/3dgs-scenes/bicycle/bicycle_real.json`
  spawn=(-6,0,2)，waypoint=(6,0,2)，camera pitch=-10°，collision slice z=[1.5,2.5]。
- 实测：
  - 单帧 320×240：2–13 ms（567k Gaussians；首帧 JIT ~1 s 编译缓存已热）。
  - 采集 1 集 12 步 teacher：第 9 步碰撞（自行车/植被代理）。
  - 预处理（`--drop-collision`）：train 9 / val 9。
  - 学生 2 epoch + 自动在线评测：10 步，第 9 步碰撞；infer ~9–29 ms。
  - 视频：`$DATA_ROOT/uav_rgb/3dgs-real-pilot-20261105/run/closed_loop_eval_*/videos/seed_0.mp4`
    （163 KB）。
- 结论：**真实 3DGS 场景的在线采集/训练/学生评测/视频链路已跑通**；SR/碰撞率
  仍只是链路验证，且碰撞代理是体素近似，不是真值。
- Callinstrasse Campus（MIT，512 MB）仍受服务器限速（~12 KB/s），未落地；
  需要换网络/离线拷贝后，才能做“真实校园 + 明确许可”的正式 pilot。
