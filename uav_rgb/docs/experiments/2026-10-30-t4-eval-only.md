# T4：训练器 eval-only 与 ckpt_best 复评

- 时间：2026-10-30
- 环境：GPU 模式（RTX 2080 Ti / sm_75），CUDA 12.8
- 数据：`/root/rivermind-data/uav_rgb/airsim10k-uavr/dataset.uavr`
  （10000 样本；train 7000 / val 1500 / test 1500）
- 结论：`--eval-only` 用同一权重、同一数据、同 `--batch 128` 能逐字节复现训练期
  validation 行；**`ckpt_best.bin` 的 test 宏 F1 是 0.5173，末轮 `ckpt.bin` 只有
  0.3855**。这直接证明「test 只评末轮」会低报模型能力。

## 命令

```bash
source env.sh
# 构建（CTest 20 项）
cmake -S src -B src/build -G Ninja -DCMAKE_BUILD_TYPE=Release && cmake --build src/build
ctest --test-dir src/build --output-on-failure

# best / 末轮各评一次，输出到新目录，避免污染原 run 的 metrics.jsonl
for ck in ckpt_best ckpt; do
  src/build/uavrgb_train \
    --data /root/rivermind-data/uav_rgb/airsim10k-uavr/dataset.uavr \
    --eval-only /root/rivermind-data/uav_rgb/airsim10k-run/$ck.bin \
    --out /root/rivermind-data/uav_rgb/airsim10k-eval-$ck \
    --batch 128 --split all
done
```

## 口径注意

- 逐字节对账要求 **同 batch**（浮点求和顺序）且 **同 `--drop-collision`**；
  本次两边都是 `batch=128, drop_collision=false`。换 batch 只保证数值近似。
- `--eval-only` 不写 `results.csv`、不更新权重；只向 `<out>/metrics.jsonl`
  追加 validation 事件。显式评估空 split 会写 `EVAL_SPLIT_EMPTY` 并返回非零。
- 旧 `ckpt_best.bin` 是 v3 checkpoint（含 `best_macro_f1`）；v2 checkpoint 没有该
  字段，`read_checkpoint` 会按 v2 默认值处理，不影响评估。
