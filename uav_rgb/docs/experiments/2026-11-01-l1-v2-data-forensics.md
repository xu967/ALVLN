# L1 v2 500 集数据取证（2026-11-01）

- 数据：`/root/rivermind-data/uav_rgb/l1-stop-500-173307`（498 集 / 10442 步，
  audit 18/18 PASS 的那一份）
- 目的：查清「为什么数据集总出问题」，不看标签格式，只看**这份数据能不能教会任务**
- 结论：数据内部自洽（18/18 PASS 是真的），但**任务信号只占约 22%，
  34% 的帧是纯色废帧，test 与 train 在视觉上不可分**。这三条 audit 一条都抓不到。

## 方法

纯离线统计，不重采、不改代码。脚本一次性跑完即删；涉及 dHash、32×32 灰度 RMSE、
位姿覆盖、teacher 重标注（`make_counterfactual.relabel` 同款逻辑）。

## 发现

### F1　18% 的集、34% 的帧是「贴着柱子拍」的纯色图

| 项 | 数 |
| --- | --- |
| 整集全帧恒定的集 | **90 / 498（18.1%）** |
| 这些集占的帧 | **3600 / 10442（34.5%）** |
| 它们的动作分布 | SAFE_NEUTRAL 3600/3600（100%） |
| 它们的 planner / spawn | `plan_action` / `spawn_mode=safe`，100% |
| 相机到柱面距离 | 0.100–0.125 m（正常集的中位数 1.60 m） |

根因：`scene_gen.make_spawn(mode="safe")` 把机体放在柱心 0.5 m 处，
相机在 SDF 里是 `<pose>0.2 0 0</pose>`（机体前方 0.2 m），于是相机离柱面只有
0.1 m，柱子填满 60° 视场 → 整帧一个颜色（灰 78,78,78 或绿 19,84,30）。
`_spawn_collides` 只查机身方框和桨盘，不查相机，也不要求最小观察距离。

后果：
- 训练集里 34% 的梯度在学「纯色图 → SAFE」，eval 里永远不会出现这种输入；
- SAFE 占比 49.7% 里 3600 步来自这里；**去掉后 SAFE 只有 23.3%**，
  和 pilot 的 21.5% 对上了（此前把 46% vs 21.5% 的差异记成"待查"）；
- 这 100 个 safe 集是「同一姿态 40 帧」，本身也不含任何新状态。

### F2　test 与 train 在像素上不可分

非空白帧、32×32 灰度 RMSE：

| 对照 | median |
| --- | --- |
| test 帧 → 最近的 train 帧 | **0.019** |
| train 帧 → 最近的**其它集** train 帧 | 0.021 |
| 同一集内相邻两帧 | 0.147 |

也就是说：**一张图离"别的集的同一步"比离"自己集的下一步"近 7 倍**。
跨 split 的"最近邻距离"与 train 内部完全相同 → test 没有引入任何新的视觉分布。
按几何组切 split 是对的，但场景族只有一个（同一条走廊），切了等于没切。

### F3　10442 步只走了世界的 40%

| 量 | 实测 |
| --- | --- |
| x 范围 | −0.50 … **2.89**（世界 x 到 5.0） |
| \|y\| | 中位 0.55，最大 1.70（世界 ±3.0） |
| \|yaw\| | 最大 62°；>30° 只占 21.6% |
| 出生点 | 只有 3 种（默认 / random / safe） |

彩色柱只在 `x ≤ 3.0` 的前排，目标 waypoint 也在那儿，所以**整份数据只有前 3.4 m**，
后面的 5–6 根柱子只改像素、不改行为。

把位姿按 0.2 m × 0.2 m × 10° 分箱：**10442 步只落在 238 个格子里**（平均每格 43.9 步）。
也就是说这份数据的"有效状态数"约 238，不是 10442。场景生成的随机化加在了不影响任务的轴上
（柱子 y 抖 ±0.2 m），没加在视角、目标距离、指令结构上。

### F4　只有 22% 的步需要看指令

| 组成 | 步数 | 占比 |
| --- | --- | --- |
| safe 出生集（F1，指令无关） | 4000 | 38.3% |
| astar 集里换目标色也不改标签的步 | 4168 | 39.9% |
| astar 集里**换目标色会改标签**的步 | **2274** | **21.8%** |

2274 步分布在 398 个集里，全部是 astar 集。按 split：

| split | astar 步 | 决定性步 | 占比 |
| --- | --- | --- | --- |
| train | 5045 | 1783 | 35.3% |
| val | 704 | 236 | 33.5% |
| test | 693 | 255 | 36.8% |

指令一共只有 4 句（2 bit）。注意 test 的决定性帧只有 **255 帧**，
语言门槛的置信区间大约 ±6 pp，够用但不宽裕。
这和「决定性帧模型 flip 49% 但 acc 只有 0.60」是一致的：
模型只要学会 78% 的无关部分就能拿到高准确率，语言分支没有梯度压力。

### F5　audit 18 项全是「内部自洽」，没有一项看图像内容

现有检查覆盖：时间对齐、动作窗口、标签复算、碰撞、类别占比、几何版本、出处一致。
缺的四类：图像非退化（F1）、位姿覆盖（F3）、语言信号占比（F4）、split 可分性（F2）。
F1–F4 全部在 18/18 PASS 的情况下存在。

### F6　测试集 20.6% 是白送分

49 个 test 集里有 5 个是 F1 的纯色集（200/973 帧），任何在纯色图上输出 SAFE 的
模型都自动答对。`test macro_f1 0.8595 / acc 0.9106` 包含这部分白送分。

## 该怎么修（都不需要重采）

1. **丢掉 90 个纯色集**：498 → 408 集 / 6842 步；SAFE 降到 23.3%。
   重新 preprocess 一次即可（`tools/preprocess.py` 传过滤后的目录列表）。
2. **`make_spawn(safe)` 加最小观察距离**（相机到柱面 ≥ 0.8 m），并把它写进
   fallback 网格的筛选条件；以后再生成不会复发。
3. **audit 增四项**（都能在现有 facts 上加）：
   - `frame_not_uniform`：整帧灰度 std < 1e-3 直接 FAIL；
   - `pose_coverage`：x/y/yaw 覆盖必须跨过设定阈值（例如 x 最大值 ≥ 3.5 m）；
   - `decisive_share`：用 `make_counterfactual.relabel` 复算，换色改标签的步必须 ≥ 20%；
   - `split_near_duplicate`：test→train 最近邻距离不得显著小于 train 内部最近邻。
4. **test 集单独检查**：剔除纯色集后再报离线指标。

## 没做什么

- 没有重训：`run-film-dec-ft` 仍在用含 90 个纯色集的 `ds-cf`，结果偏保守。
- 没有改 `scene_gen.py`/`audit_dataset.py`：本轮只取证，修复排期见 worklog。
- 没有验证「去掉纯色集后 test 指标掉多少」：需要重建数据集后重跑 eval-only。
- dHash 那一版的脚本有误（float32 GEMM 距离失真），结论以 32×32 RMSE 为准，
  已删脚本、不引用 dHash 数字。
