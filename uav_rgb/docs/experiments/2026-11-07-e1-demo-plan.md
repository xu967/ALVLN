## 1. 评测 seed：不能再用 HANDOFF 的 20 个

HANDOFF 里的 20 个「冻结 test seed」是 `uavrgb.geom.v3` 时代的 test。现在 `GEOMETRY_VERSION = uavrgb.geom.v5`，柱阵几何本身没变（20 个 seed 的 gid 逐个核对一致），只是 split 的 salt 变了：这 20 个在 v5 下 17 个 train、2 个 val、1 个 test。新 E1 学生用 v5 split 采数据，这些 seed 会进它的训练集。

**本轮用的 20 个 seed**（0–2999 中在 v3 和 v5 两个 salt 下都是 test 的共 53 个，取前 20；对旧 X3 学生和新 E1 学生都是未见过的几何）：

```
180, 206, 250, 485, 503, 555, 586, 708, 715, 721, 799, 855, 932, 992, 1113, 1116, 1123, 1145, 1246, 1282
```

复算命令：`sim/tools/split_manifest.py` 的 `split_for_gid(geometry_gid(sample_pillars(seed)[0]))` 与 `split_for_gid(..., salt="uavrgb.geom.v3")` 同为 `test`。写进 `tools/e1_pipeline.py` 的配置区，报告里注明。

## 4. 风险与应对

- Gazebo 1 kHz + 软件渲染慢于预期：先看 B 的每步墙钟；超过 8 s/步就把 D 砍到 150 集、训练轮数减半，并在报告里标 pilot。
- 执行器在柱阵里撞柱或悬停漂移大：先看 C 的 audit 和教师组 SR；教师 SR <0.8 说明执行器增益或滑行问题，先调 `e1_mini.json` 的 executor 再放量。
- SRC-ALGO 加速没按时到：E 用现有训练器跑 10 轮（约 1 h）而不是 30 轮。
- 后端断连频繁：每个 agent 的 PROGRESS.md 是断点，主会话每次先读它再 resume。
- GPU 与用户 YOLO 共享：吞吐数字注明条件。
