## 3. 数据合同

### 3.1 `results.csv`

期望表头：`epoch,train_ce,dev_ce,dev_accuracy`，一行一个 epoch。

- UTF-8（带 BOM 也可）、单元格允许为空/NaN/inf；坏值显示为 `—`，不崩溃。
- 空/非整数 `epoch` 的行保留在表格末尾，但不进入汇总和曲线。
- 行按 epoch 升序显示；重复 epoch 保持文件内相对顺序。
- 单个超长字段触发 `csv.Error` 时，保留已解析出的行（不会整文件清空）。

### 3.2 `metrics.jsonl`

一行一个 JSON object，追加写。已知事件：

```json
{"schema":"tinyvln.metrics.v1","event":"train_step","step":100,"total_steps":800,"loss":1.105,"action_accuracy":0.40,"lr":0.001,"eta_sec":87.5}
{"event":"validation","step":200,"loss":1.05,"action_accuracy":0.45,"split":"val"}
{"event":"status","message":"checkpoint saved"}
{"event":"error","severity":"FATAL","code":"TRAIN_NONFINITE_METRIC","step":300,"message":"loss is NaN"}
```

- 未知 `event` 也会显示；`error` 行红色显示。
- 非 UTF-8、坏 JSON、非 object 行跳过，不影响其他行。
- JSON 字符串里的孤立代理字符（如 `\ud800`）在显示前替换为 `?`，避免 Tk 报错。
- 末尾没有换行的半行会留到下一次追加完成后再解析。
- **默认日志只追加**。文件截断/替换（inode 变化、size 变小、或文件前 64 字节指纹变化）会清空事件日志并从头重读；同 inode 且前 64 字节相同的原地重写仍无法识别（代码中有 `shortcut:` 注释）。文件被删除时事件日志会清空，状态栏显示“等待 metrics.jsonl”。`load_events(limit<=0)` 返回空。
- 首次打开/重载时只读文件末尾 1 MiB，之后按字节偏移增量读；因此首次可能只显示最近的一部分事件（最多 200 条上限），不会把几小时的旧事件全部载入。
- 界面最多显示最近 200 条事件。

## 4. 界面与行为

- 顶部：缩写后的 run-dir（完整路径在窗口标题）、`DEMO 示例数据（非真实训练）` 标识、四个按钮。
- 左侧：汇总（epoch 数、当前/最佳 dev_ce、dev_acc）+ 指标表；表格刷新后按 epoch 恢复选中行。
- 右侧：loss 曲线（蓝=train，橙=dev）+ dev_accuracy 曲线；缺失点断开线段，单点画圆点；单 epoch/恒定值只画一个真实 x 刻度并对称留白；窗口缩放/首次 map 后重画。
- 底部：事件日志（红色 error）+ 状态栏（epoch 数、事件数、数据年龄、缺失文件、暂停状态）。
- 不可解码文件名：`_safe_text` 覆盖顶部路径、窗口标题、状态栏和日志；`_set_run_dir` 先复位状态再碰 Tk；`_is_demo` 对 `realpath` 失败容错。
- 启动：`launch_ui.sh` 在无 `DISPLAY` 时直接报错退出（Tk 8.6 需要 X11），避免桌面 `Terminal=false` 时静默失败。
- 刷新：默认 5 s；用 `(mtime_ns, size, inode)` 签名跳过无变化重绘；状态栏的「数据 Ns 前」持续增长可区分“训练死了”与“监控台卡死/暂停”。
- 健壮性：`_tick()` 用 `try/except/finally`，单次坏数据只影响当前刷新，**不会停掉后续自动刷新**；错误显示在状态栏并打印 traceback 到 stderr。
- 状态栏的 `数据 3.4h 前` 在 demo 上是正常的（示例文件很旧）；真实 run 中它反映最近一次文件写入。

## 7. 监控台未做/已知限制

- 没有真实 trainer，验证基于 `ui/demo` + 合成日志；没有小时级真实训练全程观察。
- 没有 stdout/stderr 面板、事件过滤/搜索、导出 CSV/PNG、多 run 历史/对比；每次只看一个 run-dir。
- 指标表每次刷新重建；epoch 数很大（>1 万）时可能卡顿，选中行会丢失。
- 事件日志只保留最近 200 条；旧事件不落盘。

- run-dir 不跨重启记忆；桌面快捷方式默认打开 `ui/demo`，真实 run 需在界面内选目录或用 `--run-dir`。
- DEMO 标识只对精确的 `ui/demo` 路径生效；复制 demo 到别处不会显示。
- 没有打包成 AppImage/单文件二进制；需要 Python 3 + Tk。当前以本地 Tk 程序 + 桌面快捷方式交付。
- 没有做 GPU/CPU/显存/进程监控；它只监控训练指标文件。
- `xdg-open` 存在但返回非零时没有状态栏反馈（缺失时会提示）；无文件管理器环境需自行用终端打开。

### 8.1 核心/仿真 P1

1. **动作指令不会主动停止**：`collect.py` 的 `collect_one()` 发速度指令后只 `sleep(hold)`，没有发送零速；指令会持续到下一次指令，且 contact listener 在动作结束前就被杀掉。wall-clock `hold` 与 sim-time 不一致，3 cm 的 `stuck` 阈值随 RTF 漂移；`cmd_twist()` 不检查发布返回码，`action_executed` 无条件写成请求动作。
   - 最小修法：hold 后立即发 `SAFE_NEUTRAL`/零速，按 `/clock` 等到真正停稳，listener 保持到停稳；检查发布结果。
2. **RGB 观测在动作之后抓取**：专家动作由动作前的深度算出，但唯一 RGB 在 hold/contact 之后读，`timestamp_ns` 是动作后的帧；YAW/FORWARD 标签与图像错位，且没有深度/RGB 时间戳一致性校验。
   - 最小修法：先抓 RGB+时间戳再发 twist；要求深度/RGB 时间戳在一帧内；动作后状态只进 oracle。
3. **失败步骤仍写成有效 episode / 文件非原子**：`read_rgb_png()` 失败仍 append 行（`timestamp_ns=0`、无图），`actions.jsonl` 不记 `rgb_ok`；pose 失败写 null；深度读失败 break 后仍写 `validity.episode_executed=true`；manifest 先写、JSONL 后写，崩溃会留下“看起来完整”的 manifest；复用 `--out` 会覆盖并残留旧 RGB。
   - 最小修法：缺 RGB/pose 的步骤丢弃或标无效；逐行写 validity；临时文件 + `os.replace()`，manifest 最后写；输出目录唯一；给 `gz` CLI 加超时和 JSON 校验。
4. **全无效深度被当成“前方空旷”**：`teacher._strip_min()` 全无效返回 `inf`，`center >= min_clear` → `FORWARD_SLOW`。深度传感器没出图/格式错/`h<=1`/`w<3` 都会让默认动作变成前进；`len(depth)!=w*h` 还会 IndexError。（23:30 版本新增了 `prev_action` 滞回，但这段 `inf` 处理未变。）
   - 最小修法：校验 w/h/长度；每带统计有限正样本；中心带无有效数据 → `SAFE_NEUTRAL`；侧带无数据视为“堵”。
5. **空 batch（N=0）**：CPU `softmax_ce_loss({0,C}, {})` 返回 NaN；CUDA `blocks=0` 启动零 grid，invalid configuration 后 `std::exit`。linear/conv/softmax grad 同样。
   - 最小修法：CPU/CUDA 一致地拒绝 `N<=0/C<=0` 或提前返回空/零；永远不要 `blocks=0` 启动。

### 8.2 核心/仿真 P2

- **CUDA 错误直接 `std::exit`**（linear/conv/softmax）：训练循环无法捕获 OOM/launch 错误、无法 checkpoint。改为抛 `std::runtime_error`，保留 `DeviceBuf` RAII。
- **32 位/size_t 溢出**：launch 元素数/block 数和 `Tensor::numel()` 未做 checked 64-bit；超大 conv 可能只算前缀。改 checked 64-bit，拒绝超过 `INT_MAX`/grid 上限。
- **碰撞漏报**：contact listener 无 readiness handshake；非零退出/超时/JSON 失败都当“无碰撞”；contact 只覆盖 `base_link_collision`，旋翼/偏航擦碰可能漏；`stuck` 只对 FORWARD 生效。
- **测试覆盖**：所有 CUDA kernel 只测一个 256-thread block；无 tail/multi-block、非方形 kernel、dx 有限差分、固定手算 oracle、零尺寸；`max_abs_err()` 不校验形状；`gradcheck_conv2d()` 不校验 x 形状；Python 工具未注册进 CTest。
- **深度/RGB payload 解析**：`read_depth()` 返回 `h*step/4` 个 float，但 teacher 按 `y*w+x` 索引；`step != 4*w` 会错位。`read_rgb_png()` 用 `nch=step//w` 但 `_png()` 按 `w*nch` 紧凑行构造，padding 会错位；无格式/长度校验。`save_frame.py` 声称支持 BGR/BGRA 但不换通道。
- **ActionAdapter NaN**：`yaw_rate=NaN`、`forward_speed>eps` 时返回 `FORWARD_SLOW`，而不是 `SAFE_NEUTRAL`。最小修法：输入非有限 → `SAFE_NEUTRAL`。
- **SDF/README 命名**：机体 `+Y` 是左（绿色地标在画面左侧），`pillar_right` 在 `y=+1.4` 实际是左侧；SDF 注释“右堵、左开→YAW_LEFT”与实际相反。README 话题表漏 `/uav/depth`、`/uav/contact`，把 `/model/x3/pose` 写成 `gz.msgs.Pose`（实际 `Pose_V`），采集器章节已过时。

## 12. 真实训练接入（2026-10-29 22:05，已完成）

### 12.1 用法

控制台「训练命令」填：

```bash
python3 ui/trainer_native.py --data /tmp/bench_ds.uavr
```

运行目录照常填新目录，点「开始训练」即可。`ui/trainer_native.py` 读控制台写下的
`<run_dir>.monitor/train_config.json`，拼出
`uavrgb_train --data ... --epochs ... --batch ... --lr ... --seed ... --out <run_dir>`，
然后 `os.execv` 替换自身（pid 不变，停止信号链路不变）。命令框里多写的参数
（`--resume`、`--class-weights`、`--max-grad-norm`、`--drop-collision`）原样追加给 trainer，
同名参数以命令框里的为准。数据集也可以只写在命令框里（推荐），配置里的 `data` 字段可选。

### 12.2 落盘布局

- `<run_dir>/`：只归 trainer —— `results.csv`、`metrics.jsonl`、`config.json`、`ckpt.bin`。
- `<run_dir>.monitor/`：控制台的 `train_config.json`、`train_command.txt`、`train.log`。
- 原因：`RunOwner`（`src/run_owner.cpp:28`）拒绝除 `.run.lock` 外的任何条目；控制台文件放外面后，
  重新构建的 trainer 也能正常启动。
- `train.log` 现在对真实 trainer 也有内容（stdout/stderr 重定向到那里），「训练输出」页可用。
- 兼容：监控旧 run（日志还在 run 目录里）时，`_refresh_train_log` 回退读 `<run_dir>/train.log`。
