# 自采 3DGS 场景数据集：采集规范、处理流水线、验收（2026-11-07 开线）

- 用途：用户团队实地拍摄真实场地（试飞场地 / 校园 / 室内走廊），重建成 3DGS，接进 `sim/3dgs/` 当训练与评测场景。这是论文里的「自采场景组」，和公开场景组（Callinstrasse、Mip-NeRF 360 等）分开报。
- 状态：只定规范和流程，**不写新代码**（用户 11-07 要求）。处理步骤全部用仓库已有工具或已装软件（COLMAP、gsplat venv、`tools/splat_to_ply.py`、`sim/3dgs/*`）。
- 原则：采集时就按「2 m 高度、沿飞行路线、看向飞行方向」的视角拍，3DGS 只在采集视角附近清晰；离采集路径 1–2 m 以上就发糊（Callinstrasse 的教训，见 `experiments/2026-11-07-dataset-compare-plan.md` §5）。

## 1. 场地选择

| 要求 | 为什么 |
| --- | --- |
| 可飞走廊长 8–30 m，宽 ≥2 m，有 3 个以上明显障碍（柱、树、桶、门框） | 对应现在路线的航程与四动作任务；太空旷学生全程 FORWARD，太窄 E1（外径 0.2 m）过不去 |
| 静态：无行人、无晃动的树叶/旗帜/水面 | 动态物在 3DGS 里变成雾团 |
| 纹理丰富：避免大面积白墙、玻璃、镜面、强反光地面 | COLMAP 配不上特征，重建出洞 |
| 光照稳定：阴天或室内恒定灯光，避开太阳直射和窗户逆光 | 曝光变化让高斯颜色不一致 |
| 和真机试飞是**同一块场地** | 阶段 2 的 sim-to-real 要在这里飞 |

每个场地一个目录：`$DATA_ROOT/uav_rgb/3dgs-scenes/<site>/`，`<site>` 用小写英文加日期，如 `lab_corridor_20261120`。

## 2. 采集规范（手机或运动相机都行，参数定了写进 `capture.json`）

| 项 | 设定 | 原因 |
| --- | --- | --- |
| 模式 | 视频 4K 30 fps 或连拍照片；锁定曝光、白平衡、对焦（手机用 pro 模式） | 自动曝光会让同一面墙在不同帧亮度不同 |
| 高度 | 主要在 1.5–2.5 m（举过头顶或用 2 m 独脚架），再补一圈 1.0 m 和 3.0 m | 无人机飞 2 m；上下各补一层让俯仰 ±10° 内也清晰 |
| 路线 | 沿每条候选飞行路线**正向走一遍、反向走一遍**，再在走廊两侧各走一遍（相距 0.5–1 m） | 覆盖机载相机会看到的视角；单向走只有一侧清晰 |
| 朝向 | 相机朝行进方向，偶尔左右各偏 30° | 和机载相机一致；纯侧向拍的画面无人机看不到 |
| 步速 / 重叠 | 慢走（0.5 m/s），相邻帧重叠 ≥70%；转弯处停一下多拍 | COLMAP 需要重叠；转弯是最容易断轨的地方 |
| 闭环 | 起点和终点回到同一处，再绕场地外圈走一圈 | 回环约束让尺度和漂移收敛 |
| 尺度参考 | 地上放 2 个以上 ArUco 码（边长 ≥0.3 m，打印后量实际边长写进 `capture.json`）或 5 m 卷尺拉直 | COLMAP 没有真实尺度；没有参考就只能靠相机高度估，误差 10–20% |
| 重力参考 | 至少一段视频相机水平（手机陀螺仪记录或靠墙角垂直线） | `nav_to_world` 要把 z 对齐重力，否则地面是斜的 |
| 数量 | 每个场地 600–1500 帧（视频按 2 fps 抽） | Callinstrasse 684 张可用；少于 400 张转弯处会缺 |
| 禁忌 | 不拍人脸、车牌；不在采集中途换设备或改参数 | 隐私；内参不一致 |

采集完当场检查：视频有没有抖糊（随机抽 10 帧放大看）、起点终点是否闭环、ArUco 是否出现在 ≥20 帧里。不合格当场补拍，比回来重建失败再去一次便宜。

## 3. 处理流水线（全部已有工具；每步落盘，失败就停）

| 步 | 命令 / 工具 | 产物 | 过线 |
| --- | --- | --- | --- |
| 1 抽帧 | 视频 → 2 fps 抽帧（cv2，`$DATA_ROOT/uav_rgb/3dgs-scenes/<site>/images/`），丢弃模糊帧（Laplacian 方差 < 同批中位数的 30%） | `images/*.jpg`、`frames.json` | 剩余帧 ≥400 |
| 2 COLMAP | 特征 SIFT、顺序匹配 + 回环检测、稀疏重建、`undistort`（COLMAP 已在 `code/colmap.zip`，解压到数据盘） | `sparse/0/`、`cameras.txt` | 注册帧 ≥90%，重投影误差 <1 px |
| 3 尺度与重力 | 用 ArUco 角点求相似变换（尺度 + 旋转 + 平移），把 `sparse/0` 变到「z 朝上、米制、地面 z=0」 | `align.json`（4×4 矩阵 + 残差） | ArUco 边长误差 <2%；地面点 z 的 p50 在 ±5 cm |
| 4 3DGS 训练 | gsplat（`3dgs-venv`）默认 30k 步，SH 3；4080 上约 30–60 min | `point_cloud.ply` | 留出 10% 帧 PSNR ≥ 24，转弯处帧 ≥ 22 |
| 5 转换 | `tools/splat_to_ply.py`（已处理旋转/镜像/四元数） | `scene.ply` | `tools/test_splat_to_ply.py` 口径 |
| 6 场景文件 | 写 `scene.json`（`nav_to_world`、`ground_z`、`camera` 60°/320×240、`collision` e1_mini 包络、`routes[]`） | `scene.json` | `python -m sim.3dgs.planner --scene … --json` 全部 feasible 且 clear_ok |
| 7 清晰度探测 | 沿每条路线按机载位姿渲染，算每帧 Laplacian 方差（`tmp/agent-3dgs-routes/probe_visual.py` 的做法，转正后进仓库） | `routes_quality.json` | 每条路线低质帧 <10% |
| 8 冒烟 | `collect_3dgs --policy astar --route r` 每路线 2 集 + `sim.3dgs.video` | 三视角视频 | 到达 ≥1/2、0 碰撞 |
| 9 pilot → 放量 | 同 Callinstrasse（`tools/demo_3dgs_routes.py` 换 `DEMO_SCENE`） | 数据集 | 健康检查通过 |

步 3 的 ArUco 对齐脚本和步 7 的探测脚本是**要新写的两个小工具**（各 ≤150 行，配置区风格），等用户定了设备和场地再写。

## 4. 验收与记录

- 每个场地一份 `experiments/3dgs-site-<site>.md`：采集参数、帧数、COLMAP 统计、PSNR、路线表、冒烟结果、低质帧比例、已知雾区。
- `scene.json` 的 `license` 写明「自采，<团队>，仅学术使用」；`source` 写采集日期与设备。
- 进论文的场景必须满足：≥4 条路线、每路线 ≥20 集可采、低质帧 <10%、教师冒烟 0 碰撞。

## 5. 与公开场景的分工

| 组 | 场景 | 作用 |
| --- | --- | --- |
| 公开组 | Callinstrasse + 调研清单选出的 2–3 个 | 可复现、审稿人能下载；跨场景泛化主表 |
| 自采组 | 用户场地 1–2 个 | 和真机试飞同一场地；sim-to-real 章节 |
| 合成组 | Gazebo 柱阵、forest_e1 三档 | 几何可控的消融；接触碰撞真值 |

## 6. 风险

- 手持采集的 3DGS 在 2 m 高度以外都糊：严格按 §2 的高度带拍，别只在 1.6 m 眼高拍。
- 室内走廊白墙多：提前贴海报/放杂物增加纹理，或选纹理多的场地。
- 尺度错 10% 会让 E1 的 0.2 m 外径对应的净空判断全错：ArUco 必须放，边长要量。
