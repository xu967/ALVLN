# 00｜最终技术决策记录（V8，待实机验证）

## A. 保留/冻结/撤销

**保留的核心研究任务**：自然语言指令条件下的空中导航；学生在线只接收前视单目 RGB（或短时序）、完整文本指令、历史动作和自身递归状态。学生不接收 GPS/深度/真实姿态/隐藏地图、GT 子目标、未来帧。飞控内部 IMU 用于姿态稳定是另一层系统，不属于学生的视觉输入。

**冻结**：CF-Drone 原始固件，本轮不改 `.ino`、`mavlink.ino`、PID 参数和飞行安全模式；当前不进行有桨实机测试。大型 VLM 蒸馏、复杂多重 ROI、自研通用自动微分引擎均不在首个验证闭环里。

**单一主界面**：`frontend/` = NavLab Studio UI v3；V7.1 的 dashboard 只放 `legacy/` 以利审核；UI 的 DEMO 模式不会变成实际训练成绩。`POST /api/v1/simulation-jobs` 是管理层接口，不意味着已有 AirSim/Unity 自动控制器。

**主线优先级**：

1. 服务器能启动 UI/API 且所有未满足前置条件都正确 BLOCKED；
2. 在服务器上完成 *两条限时探针*：AerialVLN 官方仿真可用性；PX4/Gazebo 真电机—机体—RGB 闭环可用性；
3. 获得至少一条具有真实图像与控制执行结果的 episode，不是假图像、不仅是 SDF；
4. 让同一视觉语言策略在真正闭环中形成第一批 baseline；
5. 才实现/验证 ECPT、蒸馏及板端迁移；
6. CF-Drone 的 PID/SIL 独立推进，不能阻断学生研究。

## B. 两种任务协议严格隔离

| 项 | AerialVLN-S（离散标准基准） | Gazebo Phys-VLN（自建物理基准） |
|---|---|---|
| 动作 | 8 类离散协议，单位遵循官方数据 | 有界机体系/世界系速度、航向变化或短时局部目标，需要控制器合同 |
| 环境 | 官方 AirSim/UE 场景、协议、对象布局 | Gazebo Harmonic + 经测试的真实四旋翼动力学 |
| 输入 | 单目 RGB+指令+记忆（按论文设定复现） | 同一学生合法输入集合 |
| 成功 | 按官方停止半径/评测器，不修改指标 | 自建终止/碰撞/安全/时间指标，明确数值阈值 |
| 可比性 | 仅官方观测/评测协议下可比较 | 自建成绩不能冒充 AerialVLN-S 排行榜 |
| 实机映射 | **禁止把 5m/15° 的 benchmark 动作直接写入 UART** | 经动力学约束验证的 NavIntent；真实飞控不一定支持 |

## C. 科学假设，不等于已发表创新

- RQ0：在低于约 1M 参数的学生容量限制下，完整自然语言在闭环 VLN 中仍提供非平凡增益吗？检验：图像置零、文本置零、文本打乱、同图换指令。
- RQ1：在**相同参数/数据/训练种子**下，将证据置信状态与语言阶段状态通过一套明确瓶颈关联，是否改善失配、阶段切换和 STOP？检验：GRU 基线、Self-Monitoring 式进度、独立 STOP、ECPT 候选。
- RQ2：是否值得给非均匀采样/特权教师蒸馏增加复杂度？只在真实基线、渲染原图、端侧预算已测量后回答；ROI 与 KD 不作为必须成功的强制创新。
- RQ3：实际板端是否能满足 P95（图像采集到动作建议，不包含物理完成时间）、RSS、掉帧与量化误差限制？只用 SG2002 真实 measurements 回答。

2026 年相关竞争包括 Self-Monitoring (2019), L2Stop, AerialVLN (ICCV 2023), LookasideVLN (CVPR 2026), LightVLN (2026), AirAnchor (2026), QAD (2026)，必须避免将“进度+STOP+紧凑记忆”当作无人研究过的新颖机制。参考详见 `13_PROVENANCE_LICENSE.md`。
